# 第 3 篇：信息收集——先找到能下嘴的地方

新手最常见的错误，是拿到一个域名就开始 `sqlmap -u`。真实项目里，主站往往被 WAF 护得严严实实，真正能出洞的是没人管的测试环境、旧系统、边缘业务、第三方接口。

信息收集的目的不是"收集越多越好"，而是回答三个问题：

1. **目标到底有哪些资产？**（域名、IP、端口、App、小程序、API）
2. **哪些资产在授权范围内？**（范围外的一律不碰）
3. **哪些地方最可能有漏洞？**（登录、上传、支付、后台、旧版本组件、调试接口）

---

## 一、先分清被动和主动

| 类型 | 做什么 | 是否接触目标 | 风险 |
| --- | --- | --- | --- |
| 被动收集 | 证书透明度、搜索引擎、GitHub、历史快照、第三方测绘 | 不直接发包 | 低 |
| 主动收集 | 子域爆破、端口扫描、目录扫描、指纹识别 | 直接发包 | 中，受规则限制 |

**顺序：先被动，再主动。** 被动阶段能拿到大量资产，还能避免一上来就打草惊蛇。主动阶段控制速率，先看项目规则允不允许扫描。

---

## 二、域名与子域：从证书透明度开始

### 查 whois 和备案

```bash
whois example.com
```

重点看注册人、邮箱、NS、创建时间。国内目标再查 ICP 备案，备案信息能反查同一主体的其他域名（很多 SRC 只收主域名，但资产梳理时需要知道边界）。

### 证书透明度日志（crt.sh）

HTTPS 证书会记录域名，crt.sh 能查历史证书里的所有子域：

```bash
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | jq -r '.[].name_value' \
  | sed 's/\*\.//g' \
  | sort -u
```

`%25` 是 `%` 的编码，`%` 是 SQL LIKE 的通配符。输出里会有 `*.example.com`，去掉通配符后就是子域列表。

### subfinder：被动子域收集

```bash
subfinder -d example.com -all -silent -o subs.txt
wc -l subs.txt
```

`-all` 会调用所有可用源，速度慢一些但覆盖全。常用源包括 crt.sh、Virustotal、SecurityTrails、Shodan 等，部分需要 API Key，配置在 `~/.config/subfinder/provider-config.yaml`。

### amass：更重的资产测绘

```bash
amass enum -passive -d example.com -o amass.txt
```

被动模式不发包，适合刚开始。主动模式 `-active` 会做 DNS 解析和爆破，注意规则。

### 子域爆破：ffuf + 字典

```bash
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
  -u http://FUZZ.example.com \
  -mc 200,204,301,302,307,401,403 \
  -t 20 \
  -o subdomains.json
```

几个细节：

- **先测泛解析**：随便填一个不存在的子域，如果也返回 200，说明有泛解析，要按响应大小/内容过滤（`-fs`）。
- **HTTP 和 HTTPS 分开跑**：有些子域只开 443。
- **不要用太大字典**：5000 条起步，跑完再换大字典。上来就 100 万条，容易被封。

### 存活探测：httpx

```bash
httpx -l subs.txt -silent -mc 200,301,302,401,403 \
  -title -tech-detect -web-server -o live.txt
```

输出每行包含 URL、状态码、标题、技术栈、Server。`live.txt` 就是你的"可访问资产表"。

## 三、端口与服务：别只盯 80/443

```bash
nmap -Pn -sS -sV -T3 --top-ports 1000 -oN nmap.txt 192.0.2.10
```

- `-sS`：SYN 扫描，需要 root；
- `-sV`：版本识别；
- `-T3`：速率适中，别用 `-T5` 打生产；
- `--top-ports 1000`：先扫常见端口，确认目标承受能力后再考虑全端口。

看到非标准端口，先用 `httpx` 探一下是不是 Web：

```bash
httpx -u http://192.0.2.10:8080 -title -tech-detect -status-code
```

### 常见"高价值"端口

| 端口 | 服务 | 优先看什么 |
| --- | --- | --- |
| 7001 | WebLogic | 反序列化、弱口令 |
| 8080/8081 | Tomcat/Nexus | 管理后台、默认口令、CVE |
| 9000 | PHP-FPM | FastCGI 未授权 |
| 9200 | Elasticsearch | 未授权、数据泄露 |
| 6379 | Redis | 未授权、写计划任务/SSH |
| 27017 | MongoDB | 未授权 |
| 2375 | Docker API | 未授权，可直接起容器 |
| 5000/5001 | 各类管理面板 | 默认口令、调试接口 |

**注意：** 端口开放不等于有漏洞。SRC 报告只写"端口开放"通常不收，要证明实际影响。

## 四、指纹：知道对方用什么，才知道该试什么

### whatweb / Wappalyzer

```bash
whatweb -a 3 https://example.com
```

输出会列出 CMS、框架、JS 库、服务器、CDN、统计代码。浏览器端可以用 Wappalyzer 插件，看同一份信息。

### 响应头和技术栈

```bash
curl -sI https://example.com | grep -Ei 'server|x-powered-by|set-cookie|via|cf-ray'
```

- `X-Powered-By: PHP/7.4`：PHP 版本，老旧版本可能有已知 CVE；
- `Server: nginx/1.18.0`：Nginx 版本；
- `Set-Cookie` 里的 `PHPSESSID`、`JSESSIONID`、`ASP.NET_SessionId` 能判断后端语言；
- `cf-ray`、`aliyun`、`x-cache` 能判断 CDN/WAF。

### favicon 哈希：找同源资产

很多测绘平台支持用 favicon 的 mmh3 哈希搜索，同一套系统 favicon 相同：

```python
import codecs
import mmh3
import requests

url = "https://example.com/favicon.ico"
r = requests.get(url, timeout=10, verify=False)
favicon = codecs.encode(r.content, "base64")
print(mmh3.hash(favicon))
```

拿到哈希后，在 FOFA 里查 `icon_hash="-123456789"`，能找到同一套 CMS 的其他站点。

### 网络空间测绘平台

| 平台 | 常用语法 | 适合找什么 |
| --- | --- | --- |
| FOFA | `domain="example.com"`、`cert="example.com"`、`icon_hash="-123"`、`body="管理后台"` | 子域、同证书资产、同 favicon |
| Hunter | `domain.suffix="example.com"`、`ip="1.2.3.4"`、`web.title="登录"` | 国内资产、备案信息 |
| Quake | `domain:"example.com"`、`ip:"1.2.3.4"` | 端口、协议指纹 |
| Shodan | `org:"Example Inc"`、`ssl:"example.com"`、`http.title:"admin"` | 海外资产、暴露服务 |

搜索语法不是背出来的，用平台侧边栏的筛选器点几次，看它生成的语句就会了。**查到资产先确认归属和授权范围**，别把测绘平台的结果当成"可以随便打"的清单。

## 五、搜索引擎：Google Hacking 还有用

| 语法 | 作用 | 示例 |
| --- | --- | --- |
| `site:` | 限定站点 | `site:example.com 后台` |
| `inurl:` | URL 含关键词 | `site:example.com inurl:admin` |
| `intitle:` | 标题含关键词 | `site:example.com intitle:登录` |
| `intext:` | 正文含关键词 | `site:example.com intext:默认密码` |
| `filetype:` | 文件类型 | `site:example.com filetype:xls` |
| `-` | 排除 | `site:example.com -www` |
| `""` | 精确匹配 | `"index of /backup"` |

常用组合：

```text
site:example.com inurl:upload
site:example.com intitle:"index of"
site:example.com ext:sql
site:example.com inurl:api swagger
```

Google 对国内站点收录不一定全，Bing、百度也可以试。搜到的敏感文件**只确认是否存在，不要批量下载**。

## 六、JS、历史 URL、API 文档：漏洞最集中的地方

现代 Web 的前端 JS 里常硬编码接口路径、AppKey、测试环境地址。历史 URL 里常藏着已经删掉但服务器还在的接口。

### 历史 URL

```bash
# 安装
go install github.com/tomnomnom/waybackurls@latest
go install github.com/lc/gau/v2/cmd/gau@latest

# 收集
echo example.com | waybackurls | tee wayback.txt
gau example.com --threads 5 | tee gau.txt
sort -u wayback.txt gau.txt > urls.txt
```

从 URL 里筛高价值参数：

```bash
grep -Ei '(\?|&)(url|redirect|next|callback|file|path|id|uid|token)=' urls.txt | sort -u
```

这些参数名对应 SSRF、开放重定向、文件包含、越权，是手工测试的入口。

### 爬虫：katana

```bash
katana -u https://example.com -d 3 -jc -silent -o crawl.txt
```

- `-d 3`：爬三层；
- `-jc`：解析 JS 里的路径；
- 输出包含表单、带参数 URL、JS 文件。

### JS 里找接口

```bash
# 下载页面引用的 JS
katana -u https://example.com -jc -silent | grep -E '\.js($|\?)' | sort -u > js.txt

# 从 JS 里提取路径和完整 URL
while read -r js; do
  curl -s "$js" | grep -Eo '(https?://[^"'"'"' ]+|/[a-zA-Z0-9_./?=&-]{3,})'
done < js.txt | sort -u > endpoints.txt
```

重点看：

- `/api/v1/...`、`/internal/...`、`/actuator/...`；
- `app.js.map`、`vendor.js.map`（source map 可能还原源码）；
- `secret`、`appkey`、`accessKey`、`password` 等字符串；
- 测试环境域名 `test-`、`dev-`、`uat-`。

工具可以用 LinkFinder：

```bash
git clone https://github.com/GerbenJavado/LinkFinder.git
cd LinkFinder && pip3 install -r requirements.txt
python3 linkfinder.py -i https://example.com -o cli
```

### API 文档和调试端点

优先访问这些路径：

```text
/swagger-ui.html
/swagger-ui/index.html
/v2/api-docs
/v3/api-docs
/openapi.json
/actuator
/actuator/env
/actuator/heapdump
/druid/index.html
/phpinfo.php
/.git/config
/.svn/entries
/.env
/backup.zip
/www.zip
```

`/actuator/env`、`/actuator/heapdump` 泄露配置和内存，常常能直接拿到数据库密码或 AK/SK，是高价值发现。但**看到就停，不要下载 heapdump 里的用户数据**。

## 七、GitHub 和代码泄露

搜索语法：

```text
org:example "password"
org:example "secret"
"example.com" "accessKey"
"example.com" filename:.env
"example.com" filename:config.php
```

工具：

```bash
# gitleaks 扫本地仓库
gitleaks detect --source ./repo --verbose

# trufflehog 扫 GitHub 组织
trufflehog github --org=example --only-verified
```

发现密钥后，**不要拿它登录生产系统**。正确做法是确认密钥是否有效（用只读、无副作用的方式），然后立即报告，让厂商轮换。很多 SRC 对"只证明密钥有效"和"实际访问了数据"的定级完全不同。

## 八、目录扫描：找没挂链接的页面

```bash
ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
  -u https://example.com/FUZZ \
  -mc 200,204,301,302,307,401,403 \
  -fs 0 -t 20 \
  -o dirs.json
```

dirsearch 更适合按后缀扫：

```bash
python3 dirsearch.py -u https://example.com \
  -e php,asp,aspx,jsp,zip,bak,txt,old \
  --exclude-status=404 \
  -t 20
```

### 403 绕过先别急着放弃

看到 403 不代表没东西。可以试：

```text
/admin        → /admin/
/admin        → //admin
/admin        → /./admin
/admin        → /%2e/admin
/admin        → /admin;/
/admin        → /admin/..
```

请求头绕过：

```http
X-Forwarded-For: 127.0.0.1
X-Real-IP: 127.0.0.1
X-Original-URL: /admin
X-Rewrite-URL: /admin
```

这些只在特定中间件/框架配置下有效，不要当万能钥匙。测到一个能绕过，先确认返回的是真实管理页面，再继续。

### 备份文件和源码泄露

```text
/index.php.bak
/index.php~
/index.php.swp
/www.zip
/web.zip
/backup.sql
/db.sql
/.git/config
```

`.git` 泄露可以用 gitHack 或 `git-dumper` 还原源码：

```bash
pip3 install git-dumper
git-dumper https://example.com/.git ./repo
```

拿到源码后，重点看路由、鉴权中间件、SQL 拼接、文件上传处理、配置文件。**源码只用于本地审计，不要公开传播。**

## 九、把上面的步骤串成一条流水线

下面这段脚本只做"收集 + 存活 + 截图/标题"，不做漏洞扫描。跑之前把 `target.com` 换成授权目标，把输出目录建好：

```bash
#!/usr/bin/env bash
set -euo pipefail

target="target.com"
out="recon-$target-$(date +%Y%m%d)"
mkdir -p "$out"

echo "[1/5] 被动子域"
subfinder -d "$target" -all -silent -o "$out/subs.txt"

echo "[2/5] 证书透明度补充"
curl -s "https://crt.sh/?q=%25.$target&output=json" \
  | jq -r '.[].name_value' 2>/dev/null \
  | sed 's/\*\.//g' | sort -u >> "$out/subs.txt" || true

sort -u "$out/subs.txt" -o "$out/subs.txt"

echo "[3/5] 存活探测"
httpx -l "$out/subs.txt" -silent \
  -mc 200,301,302,401,403 \
  -title -tech-detect -web-server \
  -o "$out/live.txt"

echo "[4/5] 历史 URL"
gau "$target" --threads 5 2>/dev/null | sort -u > "$out/urls.txt" || true

echo "[5/5] 高价值参数"
grep -Ei '(\?|&)(url|redirect|next|callback|file|path|id|uid|token|cmd)=' \
  "$out/urls.txt" | sort -u > "$out/params.txt" || true

echo "完成，结果在 $out/"
wc -l "$out"/*.txt
```

**注意：** 脚本里没有目录爆破和漏洞扫描，因为这两步最容易触发 WAF/告警。要跑也先看项目规则，并把线程数压到 `-t 5` 以下。

## 十、资产怎么排序：先打哪里

拿到几十上百个存活资产后，不要平均用力。按下面的优先级排：

| 优先级 | 特征 | 为什么 |
| --- | --- | --- |
| P0 | 登录/注册/找回密码/支付/上传/后台 | 逻辑漏洞和越权高发，手工测试价值最高 |
| P1 | `test-`、`dev-`、`uat-`、`staging` 环境 | 防护弱、调试信息多、可能连生产库 |
| P2 | 旧版 CMS、旧框架、暴露版本号 | 已知 CVE 多，验证成本低 |
| P3 | API、Swagger、GraphQL | 参数多、鉴权容易漏、越权好测 |
| P4 | 静态站、纯展示页 | 优先级最低，除非有信息泄露 |

### 一张资产表

| 资产 | 状态 | 指纹 | 账号 | 可疑点 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `www.example.com` | 200 | Nginx + Vue | 已注册 | `/api/user/{id}` | 待测越权 |
| `test.example.com` | 200 | Tomcat 8.5 | 无 | `/manager/html` | 待测默认口令（需规则允许） |
| `api.example.com` | 401 | Spring Boot | Token | `/actuator` | 待测未授权 |

**规则：** 一个资产测完，先在表里写结论再换下一个。否则一天下来只剩下浏览器历史记录，报告写不出来。

## 十一、信息收集的边界

- 只收集**授权范围内**的域名/IP/App。测绘平台搜到的同主体资产，先确认项目是否覆盖。
- 不爆破第三方邮箱、不扫公共 DNS、不对 CDN 节点做端口扫描。
- 控制速率。目录扫描 `-t 20` 已经不算低，生产环境建议 `-t 5`。
- 发现源码、备份、密钥，**下载最小证明即可**，不要整站拖走。
- 不公开任何未修复漏洞的细节和资产列表。
