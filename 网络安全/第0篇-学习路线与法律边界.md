# 第 0 篇：从零到 SRC，先搞清楚路怎么走、线在哪里

这不是一份"看完就会挖洞"的目录。从这一篇开始，每一篇都要你动手：装环境、抓包、在靶场里把漏洞打出来、写复现步骤。只看不练，看到第 12 篇也只会背几个名词。

这一篇干三件事：把学习路线画清楚，把法律红线划出来，然后立刻做第一个实验——用 `curl` 完整看一遍 HTTP 响应。别急着装 Burp，先把"浏览器背后发生了什么"弄明白。

---

## 一、先划红线：哪些事做了要负刑事责任

技术可以学，手不能乱伸。下面这些不是吓唬人，是真实判例里最常见的几条：

| 法条 | 管什么 | 典型触发场景 |
| --- | --- | --- |
| 《刑法》第 285 条 | 非法侵入计算机信息系统、非法获取计算机信息系统数据、非法控制计算机信息系统 | 扫到别人站点有 SQL 注入，跑 sqlmap 拖了库；用默认口令登录了没授权的后台 |
| 《刑法》第 286 条 | 破坏计算机信息系统 | 上传 webshell 后删文件、改配置；跑压力测试把业务打挂 |
| 《刑法》第 253 条之一 | 侵犯公民个人信息 | 把漏洞里拿到的手机号、身份证、住址存下来或转手 |
| 《网络安全法》第 27 条 | 不得非法侵入他人网络、干扰正常功能、窃取网络数据 | 未授权的扫描、爆破、漏洞利用 |
| 《数据安全法》《个人信息保护法》 | 数据收集、存储、使用的合规要求 | 把测试数据带出、公开披露未脱敏数据 |

**关键点：** "我只是看看，没删东西"不等于没事。非法获取数据本身就是 285 条规制的内容；"没造成损失"最多影响量刑，不影响定性。

### 授权必须同时满足三个条件

1. **主体对**：授权方得是资产的所有者，或者有明确转授权。甲方说"这个站是我们的"不代表真的能测，最好有盖章授权书或平台项目页。
2. **范围对**：写清楚域名、IP 段、App 包名、测试账号、时间窗口。`*.example.com` 和 `example.com` 是两回事；"相关系统"这种模糊表述不要接。
3. **行为对**：授权书没写的测试项不要做。常见禁止项：拒绝服务、社会工程、物理入侵、钓鱼、碰第三方供应链、下载超过证明所需的数据。

### SRC 项目里尤其要看的几行规则

每个项目页面都有"测试范围"和"禁止行为"，提交前逐条对照。高频坑：

- **只收主站，不收子域名**：你测了 `test.example.com`，可能直接判 out of scope。
- **不收第三方系统**：用了某云厂商的客服系统，漏洞在厂商那边，不属于目标。
- **不收过期组件**：只报"使用了 jQuery 1.x"没有实际影响，通常不收。
- **不收自 XSS**：只有自己能触发的 XSS 没有受害者，一般忽略。
- **禁止爆破和 DoS**：登录口跑字典、发压测流量，轻则封号，重则移交。
- **禁止碰真实数据**：证明到"能读到数据库名"就停，不要 `--dump` 用户表。

**出问题时的正确动作**：立刻停止、保留操作记录、通过项目渠道报告、不要自行删除痕迹或隐瞒。越早说清楚，性质越轻。

## 二、能力地图：SRC 挖洞到底要会什么

很多人卡在"工具会用，但不知道下一步点哪"。原因是只学了工具，没建立下面这五层结构：

```text
第 5 层  报告与沟通      ← 决定漏洞能不能被确认、拿不拿得到钱
第 4 层  漏洞原理与利用  ← SQLi / XSS / SSRF / 上传 / 越权 / 反序列化
第 3 层  信息收集        ← 子域、端口、指纹、JS、历史 URL、泄露
第 2 层  Web 与协议      ← HTTP、Cookie、同源策略、DNS、TLS
第 1 层  系统与编程      ← Linux 命令、Python、PHP/Java 基础、SQL
```

对应到这份资料：

| 层 | 篇目 |
| --- | --- |
| 第 1 层 | 第 1 篇补网络与 Web；第 2 篇装环境；Python 基础可看仓库里的《Python 速成》 |
| 第 2 层 | 第 1 篇 |
| 第 3 层 | 第 3 篇 |
| 第 4 层 | 第 4 ～ 10 篇 |
| 第 5 层 | 第 11 ～ 12 篇 + 附录 |

**不要跳层。** 直接学 "SQL 注入 payload 大全" 的人，遇到 JSON 接口、WAF、盲注就废了；把第 1 篇的 HTTP 吃透，后面每个漏洞你都能自己推 payload。

## 五、第一个实验：不装任何工具，先看 HTTP

打开终端，跑：

```bash
curl -I https://example.com
```

你会看到类似：

```text
HTTP/2 200
content-type: text/html; charset=UTF-8
date: Fri, 14 Nov 2026 08:00:00 GMT
expires: Sat, 15 Nov 2026 08:00:00 GMT
cache-control: max-age=86400
server: cloudflare
```

逐行读：

- `HTTP/2 200`：协议版本 + 状态码。200 是成功，301/302 是跳转，403 是无权，404 是不存在，500 是服务端报错。
- `content-type`：响应体是什么。`text/html` 是网页，`application/json` 是接口，`image/png` 是图片。后面判断上传漏洞时，这个字段很关键。
- `server`：服务端软件。有些站点会暴露 `nginx/1.18.0`，版本信息就是指纹。
- `cache-control`、`expires`：缓存策略。测试时浏览器缓存会骗你，记得勾 "Disable cache"。

再看完整请求：

```bash
curl -v https://example.com
```

`-v` 会把 DNS 解析、TCP 连接、TLS 握手、请求头、响应头全打出来。你需要能指出：

1. 请求行：`GET / HTTP/2`；
2. `Host` 头：`example.com`；
3. `User-Agent`：curl 的版本；
4. `Accept`：客户端能接受什么格式；
5. 响应码和响应头。

### 在本地观察一个"自己发出去"的请求

开两个终端。第一个：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

第二个：

```bash
curl -v http://127.0.0.1:8000/hello
```

第一个终端会打印：

```text
127.0.0.1 - - [14/Nov/2026 08:01:02] code 404, message File not found
127.0.0.1 - - [14/Nov/2026 08:01:02] "GET /hello HTTP/1.1" 404 -
```

这就是服务端看到的"访问日志"。后面讲日志包含、盲 SSRF、XSS 打管理后台，都靠这种日志确认请求有没有到。

### 用 nc 手写一个 HTTP 请求

```bash
printf 'GET / HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\n\r\n' | nc 127.0.0.1 8000
```

`\r\n` 是 HTTP 的换行，不是 `\n`。请求头最后必须空一行，表示头结束了。这个细节在打 SSRF 的 gopher 协议、Redis 未授权、CRLF 注入时会反复用到。

## 六、笔记模板：从第一篇就开始用

好记性不如一份能复现的记录。每个练习点建一个 Markdown 文件，固定写这几块：

```markdown
# 目标 / 漏洞名

- 时间：2026-11-14 20:00
- 范围：127.0.0.1:8080（本地 DVWA）
- 账号：admin / password
- 工具：Burp 2025.x、Firefox 128

## 现象
访问 /vulnerabilities/sqli/?id=1'，页面返回 SQL 语法错误。

## 请求
POST /login.php HTTP/1.1
Host: 127.0.0.1:8080
...

## 复现步骤
1. 登录后进入 SQL Injection 页面；
2. id 填 `1'`，观察报错；
3. id 填 `1' AND 1=1-- -`，页面正常；
4. id 填 `1' AND 1=2-- -`，页面为空。

## 影响
可读取当前数据库数据；已验证可读到 database() 名称，未继续拖库。

## 修复建议
预处理语句、数据库最小权限、关闭详细报错。

## 参考
- OWASP SQL Injection
- sqli-labs Less-1
```

**为什么现在就要写：** 第 12 篇写报告时，你需要原始请求、响应、时间线。事后补的截图通常缺关键信息，审核一问就露馅。

## 七、四条学习硬规矩

1. **先复现，再背 payload。** 每个 payload 都要知道它落在哪个上下文、为什么能闭合、服务端怎么解析。背 100 条不如手推 10 条。
2. **一洞一笔记，一周一复盘。** 周末把这周所有"没打进去"的点翻一遍，通常比新学一个漏洞更有用。
3. **只在授权范围里动手。** 看到陌生站点手痒，就去开靶场。这个习惯值钱，也能保命。
4. **不碰数据、不破坏、不社工。** 证明漏洞存在即可。真实项目里，拿到管理员权限后第一件事是停手并报告，不是继续翻。
