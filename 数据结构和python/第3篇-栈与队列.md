# 第 3 篇：栈与队列——括号匹配、表达式求值，一次讲透

这篇讲两种"受限的线性表"：栈和队列。它们本身简单得只有几个操作，但一用到括号匹配、表达式求值上就变得很有意思，而这两道题几乎是期末必考。需要先会：第 1 篇的列表、循环、类，第 2 篇的复杂度（尤其是"数循环次数"和"头部操作是 O(n)"）。

上一篇文章我们数了半天"挪元素"的成本，最后留了个伏笔：如果**只在末尾加、只在末尾删**，所有操作都是 O(1)。这一篇就从这里出发——把"只在一头操作"这件事，变成两个真正有用的结构。

---

## 一、栈：像叠盘子一样"后进先出"

### 先看生活里的栈

你去食堂，阿姨把洗好的盘子一个个往上摞。你要拿盘子，会拿**最上面**那个，也就是最后放上去的那个。你绝对不会从最底下抽——一抽整摞都塌了。

这就是栈：**最后进去的，最先出来**，英文叫 LIFO（Last In First Out）。

生活里到处都是栈，你可以留意一下：

- **Ctrl + Z 撤销**：你刚才做的最后一步，最先被撤销。撤完再按一次，撤的是倒数第二步。
- **浏览器后退**：你最后访问的页面，最先退回去。
- **函数调用**：`a()` 调用 `b()`，`b()` 调用 `c()`，`c()` 执行完先回到 `b()`，再回到 `a()`。这个"调用栈"就是栈，而且**递归的本质就是栈**——第 5 篇讲树的时候，递归遍历靠的就是它。
- **弹夹**：最后压进去的子弹最先打出来。

### 栈的术语和"只许在一头动"的规矩

```text
        ┌─────┐
        │  3  │  ← 栈顶 top（只能在这里进、这里出）
        ├─────┤
        │  2  │
        ├─────┤
        │  1  │  ← 栈底 bottom（动不了）
        └─────┘
```

- **入栈 / 压栈（push）**：往栈顶放一个元素。
- **出栈 / 弹栈（pop）**：把栈顶元素拿走。
- **栈顶（top）**：唯一能操作的位置。
- **栈底（bottom）**：最先进去的元素，但它要等到最后才能出来。

**注意这里**：栈不是"不能访问中间元素"，而是"按规矩不该访问"。你当然可以偷看中间那个，但那就不是栈的操作了。考试问"栈的特点"，标准答案就是四个字：**后进先出**。

### 用 Python 列表实现一个栈

Python 列表的 `append`（末尾加）和 `pop()`（末尾删）都是 O(1)——第 2 篇刚数过。而"末尾"正好可以当栈顶。所以一个栈用列表两行就能实现。

不过考试通常要求你写一个**类**，所以我们也写一个完整的：

```python
class Stack:
    def __init__(self):
        self.items = []              # 用列表存数据，列表末尾就是栈顶

    def push(self, x):
        self.items.append(x)         # 入栈：加到末尾，O(1)

    def pop(self):
        if self.is_empty():
            return None              # 空栈不能弹，先防一手
        return self.items.pop()      # 出栈：删掉末尾并返回，O(1)

    def peek(self):
        if self.is_empty():
            return None
        return self.items[-1]        # 只看一眼栈顶，不删除

    def is_empty(self):
        return len(self.items) == 0

    def size(self):
        return len(self.items)

    def __str__(self):
        body = " ".join(str(x) for x in self.items)
        return "栈底 " + body + " 栈顶"


s = Stack()
s.push(1)
s.push(2)
s.push(3)
print(s)                 # 栈底 1 2 3 栈顶
print("栈顶是", s.peek())  # 栈顶是 3
print("弹出", s.pop())     # 弹出 3
print("弹出", s.pop())     # 弹出 2
print("现在栈里还有", s.size(), "个")   # 现在栈里还有 1 个
print("空了吗？", s.is_empty())         # 空了吗？ False
print(s.pop())           # 1
print("空了吗？", s.is_empty())         # 空了吗？ True
```

逐块解释：

- `self.items` 是真正存东西的地方。列表的**末尾**被我们当作栈顶。
- `push` 就是 `append`，`pop` 就是 `pop()`，一个字母都不用改。**这就是"尾部操作 O(1)"的价值**。
- `peek` 用 `items[-1]` 取最后一个，不删。考试里叫"取栈顶元素"，注意它和 `pop` 的区别：**一个只读，一个读并删**。
- `is_empty` 先判断再弹，是为了避免空栈时 `pop()` 抛 `IndexError`。这个防御性写法在考试里能加分。
- `__str__` 是为了让 `print(s)` 输出好看，不然你会看到一串地址。

### 栈的复杂度

| 操作 | 复杂度 | 原因 |
| --- | --- | --- |
| `push` | O(1) | 末尾追加 |
| `pop` | O(1) | 末尾删除 |
| `peek` | O(1) | 按下标取 |
| `is_empty` / `size` | O(1) | 看长度 |

**这是栈最迷人的地方：所有操作都是 O(1)。** 它什么都没多干，只是**限制了你能操作的位置**——而正是这个限制，换来了稳定和快速。这个思想在数据结构里会反复出现，你可以先记下来。

## 二、栈的第一个应用：括号匹配

### 题目长什么样

给你一串只包含 `(`、`)`、`[`、`]`、`{`、`}` 的字符串，判断括号是否**正确配对**。

正确的例子：`()[]{}`、`([{}])`、`(())`、空串。
错误的例子：`(]`（类型不配）、`([)]`（交叉）、`((`（少了右括号）、`)`（多了右括号）。

### 为什么这题非栈不可

你可以这样想：括号像**成对的舞伴**，左括号是"伸出手等人牵"，右括号是"来牵手的人"。

关键规律是：**最后出现的左括号，必须最先被闭合**。

看 `([{}])`：`(` 先出现，然后是 `[`，然后是 `{`。闭合的时候，顺序必须反过来——先 `}`，再 `]`，最后 `)`。这正好是"后进先出"。所以每读到一个左括号，就把它压进栈；每读到一个右括号，就看看**栈顶**是不是它的另一半。

如果用一个计数器数"左括号几个、右括号几个"，`([)]` 会被误判为正确（数量是平衡的），但它的类型和顺序都是错的。**这就是为什么必须用栈，而不是数数。**

### 手工演示

以 `([{}])` 为例，从左往右扫：

| 读到 | 动作 | 栈（底 → 顶） | 结果 |
| --- | --- | --- | --- |
| `(` | 入栈 | `(` | 继续 |
| `[` | 入栈 | `( [` | 继续 |
| `{` | 入栈 | `( [ {` | 继续 |
| `}` | 栈顶是 `{`，配对，弹出 | `( [` | 继续 |
| `]` | 栈顶是 `[`，配对，弹出 | `(` | 继续 |
| `)` | 栈顶是 `(`，配对，弹出 | 空 | 继续 |
| 结束 | 栈为空 | — | **正确** |

再看 `([)]`：

| 读到 | 动作 | 栈（底 → 顶） | 结果 |
| --- | --- | --- | --- |
| `(` | 入栈 | `(` | 继续 |
| `[` | 入栈 | `( [` | 继续 |
| `)` | 栈顶是 `[`，不是 `(` | `( [` | **错误** |

栈顶是 `[`，来的却是 `)`，对不上，直接判错。**交叉的括号，栈一眼就看穿了。**

### 代码

```python
def is_matched(s):
    pairs = {")": "(", "]": "[", "}": "{"}   # 右括号 → 对应的左括号
    stack = []

    for ch in s:
        if ch in "([{":
            stack.append(ch)                 # 左括号：入栈，等着被配对
        elif ch in ")]}":
            # 栈空了说明右括号比左括号多；栈顶不匹配说明类型或顺序错了
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()                      # 配对成功，把左括号弹掉
        # 其他字符直接忽略（题目保证只有括号时，这句不生效）

    return len(stack) == 0                   # 全部配完，栈必须空


tests = ["()[]{}", "([{}])", "(]", "([)]", "((", ")", "", "{[()()]}"]
for t in tests:
    print(f"{t!r:12} → {is_matched(t)}")
```

输出：

```text
'()[]{}'     → True
'([{}])'     → True
'(]'         → False
'([)]'       → False
'(('         → False
')'          → False
''           → True
'{[()()]}'   → True
```

逐块解释：

- `pairs` 用字典做"右括号查左括号"的对照表，比写一堆 `if ch == ")" ... elif ch == "]" ...` 干净得多。**这是第 1 篇字典的典型用法。**
- `if ch in "([{"`：判断字符是不是三种左括号之一。字符串也能用 `in`，意思是"是不是这个字符串的子串"。
- `not stack`：栈空。空栈遇到右括号，说明右括号多了，立刻判错。
- `stack[-1] != pairs[ch]`：`stack[-1]` 是栈顶（列表最后一个）。配对不上就错。
- `return len(stack) == 0`：**这一行最容易漏**。如果字符串是 `((`，循环里一个右括号都没遇到，不会返回 False，最后栈里还剩两个左括号。必须用"栈是否为空"来收尾。写成 `return True` 就错了。

### 复杂度和边界

每个字符进栈、出栈各一次，**时间 O(n)**，最坏情况（比如 `((((`）栈里有 n 个元素，**空间 O(n)**。

考试里常给你这几组边界，你写代码时脑子里过一遍就能防住：

- 空串 `""` → 应该返回 `True`（没有括号，当然配平）。很多同学写成了 `False`。
- 只有右括号 `")"` → `False`，靠的是 `not stack` 这一句。
- 只有左括号 `"(("` → `False`，靠的是最后 `len(stack) == 0`。
- 长度是奇数 → 一定不对（但不用特判，算法自然会处理，别为此多写一行）。

**踩坑提醒**：有同学用 `s.count("(") == s.count(")")` 来判断，`([)]` 会直接判成正确。**数量平衡 ≠ 配对正确**，这是这道题的核心考点。

## 三、栈的第二个应用：表达式求值

### 先搞清楚：为什么计算机算不了 `3+4*2`

你看到 `3+4*2`，脑子里自动先算 `4*2=8`，再算 `3+8=11`。因为你知道"乘法优先于加法"。

但计算机从左到右读，如果它读到 `3+4` 就立刻加，会得出 `7*2=14`，错了。

麻烦有两层：

1. **优先级**：`*` `/` 比 `+` `-` 高。
2. **括号**：括号里的内容要先算。

数学家给出的解法很聪明：把 `3+4*2` 改写成一种**不需要括号、不需要记优先级、从左往右扫一遍就能算**的形式，叫**后缀表达式**（也叫逆波兰表达式）。

### 三种表达式长什么样

以 `3 + 4 * 2` 为例：

| 形式 | 写法 | 特点 |
| --- | --- | --- |
| 中缀 | `3 + 4 * 2` | 人看的，运算符在中间，有优先级问题 |
| 前缀（波兰式） | `+ 3 * 4 2` | 运算符在前，从右往左算 |
| **后缀（逆波兰式）** | `3 4 2 * +` | **运算符在后，从左往右算，不用括号** |

注意后缀式的读法：`3 4 2 * +` 的意思是"3、4、2，先算 4*2 得 8，再算 3+8 得 11"。**运算符出现在它的两个操作数后面**。

括号也消失了：`(1+2)*(3+4)` 的后缀式是 `1 2 + 3 4 + *`，`(3+4)*2` 是 `3 4 + 2 *`。括号的作用被"运算顺序"本身表达了。

### 第一步：中缀 → 后缀（调度场算法）

规则就五条，用两个容器：一个**输出**（存最终结果），一个**运算符栈**。

1. 遇到**数字**：直接输出。
2. 遇到**左括号 `(`**：压入运算符栈。
3. 遇到**右括号 `)`**：不断弹出栈顶并输出，直到遇到 `(` 为止，然后把 `(` 弹掉（不输出）。
4. 遇到**运算符**：只要栈顶还是运算符、且栈顶优先级 **≥** 当前运算符，就弹出栈顶输出；重复这一步，然后把当前运算符压栈。
5. 扫完后，把栈里剩下的运算符全部弹出输出。

**为什么规则 4 里是"≥"而不是">"**？因为同级运算符要**从左往右**算。`8-2-3` 必须先算 `8-2`，如果栈里的 `-` 不弹出来，就会变成 `8-(2-3)=9`，错了。这个细节考试很爱考。

下面是代码（为简单起见，只支持**一位数字**和 `+ - * / ( )`，这也是考试最常见的设定）：

```python
def infix_to_postfix(expr):
    priority = {"+": 1, "-": 1, "*": 2, "/": 2}   # 乘除优先级高
    output = []                                    # 存放后缀结果
    stack = []                                     # 运算符栈

    for ch in expr:
        if ch == " ":
            continue
        if ch.isdigit():                           # 规则 1：数字直接输出
            output.append(ch)
        elif ch == "(":                            # 规则 2：左括号入栈
            stack.append(ch)
        elif ch == ")":                            # 规则 3：弹到左括号为止
            while stack and stack[-1] != "(":
                output.append(stack.pop())
            stack.pop()                            # 把 "(" 也弹掉，但不输出
        else:                                      # 规则 4：运算符
            while (stack and stack[-1] != "("
                   and priority[stack[-1]] >= priority[ch]):
                output.append(stack.pop())
            stack.append(ch)

    while stack:                                   # 规则 5：清空栈
        output.append(stack.pop())

    return "".join(output)


for e in ["3+4*2", "(1+2)*(3+4)", "8-2-3", "8/2-3", "1+2*3-(4+5)"]:
    print(f"{e:15} → {infix_to_postfix(e)}")
```

输出：

```text
3+4*2           → 342*+
(1+2)*(3+4)     → 12+34+*
8-2-3           → 82-3-
8/2-3           → 82/3-
1+2*3-(4+5)     → 123*+45+-
```

**拿 `8-2-3` 验证一下"≥"的必要性**：

- 读到 `8` → 输出 `8`
- 读到 `-` → 栈空，压栈。栈：`-`
- 读到 `2` → 输出 `82`
- 读到 `-` → 栈顶是 `-`，优先级相等（1 ≥ 1），**弹出**旧的 `-` 输出，再压入新的 `-`。输出 `82-`，栈：`-`
- 读到 `3` → 输出 `82-3`
- 扫完，弹出栈里的 `-` → `82-3-`

结果 `82-3-`，求值是 `(8-2)-3 = 3`，正确。如果把规则写成 `>`（只有严格大于才弹），这一步就会把两个 `-` 都留在栈里，得到 `823--`，算出来 `8-(2-3)=9`，**错了**。

**注意这里**：这个版本只认一位数字。如果表达式里有 `12` 这种多位数，`ch.isdigit()` 会把 `1` 和 `2` 当成两个数。考试基本不考多位数，但如果考了，正确做法是先"分词"（把字符串切成 `["12", "+", "3"]` 这样的列表），再按同样的规则处理。思路完全一样，只是多了一步切分。

### 第二步：后缀表达式求值

后缀求值比中缀转后缀还简单，一句话：

> **遇到数字就压栈；遇到运算符就弹出两个数，算完把结果压回去；最后栈里剩下的那个数就是答案。**

```python
def eval_postfix(expr):
    stack = []
    for ch in expr:
        if ch.isdigit():
            stack.append(int(ch))          # 数字入栈
        else:
            b = stack.pop()                # 先弹出的是"右操作数"
            a = stack.pop()                # 后弹出的是"左操作数"
            if ch == "+":
                stack.append(a + b)
            elif ch == "-":
                stack.append(a - b)        # 注意是 a - b，不是 b - a
            elif ch == "*":
                stack.append(a * b)
            elif ch == "/":
                stack.append(a // b)       # 用整除，保持整数结果
    return stack.pop()


print(eval_postfix("342*+"))     # 11   → 3 + 4*2
print(eval_postfix("12+34+*"))   # 21   → (1+2)*(3+4)
print(eval_postfix("82-3-"))     # 3    → (8-2)-3
print(eval_postfix("82/3-"))     # 1    → 8/2-3
print(eval_postfix("123*+45+-")) # -2   → 1+2*3-(4+5)
```

输出：

```text
11
21
3
1
-2
```

**`b` 和 `a` 的顺序是这道题最大的坑**。栈是后进先出，所以**先弹出来的是表达式里靠右的那个数**。以 `8 2 -` 为例：先压 8，再压 2，弹出时先拿到 2（右操作数），再拿到 8（左操作数），所以必须是 `a - b = 8 - 2 = 6`。你要是写成 `b - a`，得到 `-6`。

减法和除法都对顺序敏感，加法和乘法无所谓——但**统一按 `a 运算符 b` 写**，别偷懒。

### 把两步接起来：一个能直接算的 `calc`

真实考试有时会直接让你"求值"，这时候先转后缀、再算，两步串联最稳。下面的代码**接在上面 `infix_to_postfix` 和 `eval_postfix` 两个函数后面运行**，不用重复写：

```python
def calc(expr):
    return eval_postfix(infix_to_postfix(expr))


for e in ["3+4*2", "(1+2)*(3+4)", "1+2*3-(4+5)", "(8-2)*3", "9-2*3+1"]:
    print(f"{e:15} = {calc(e)}")
```

输出：

```text
3+4*2           = 11
(1+2)*(3+4)     = 21
1+2*3-(4+5)     = -2
(8-2)*3         = 18
9-2*3+1         = 4
```

（最后两个可以拿来检验规则：`(8-2)*3` 有括号，先减后乘；`9-2*3+1` 里 `-` 和 `+` 同级，必须从左往右，得到 `9-6+1=4`。如果算成 2，说明你把同级运算符的顺序搞反了。）

### 手工演示：`3 4 2 * +` 的求值过程

| 读到 | 动作 | 栈（底 → 顶） |
| --- | --- | --- |
| `3` | 压栈 | `3` |
| `4` | 压栈 | `3 4` |
| `2` | 压栈 | `3 4 2` |
| `*` | 弹 2、弹 4，算 4*2=8，压回 | `3 8` |
| `+` | 弹 8、弹 3，算 3+8=11，压回 | `11` |
| 结束 | 栈里只剩一个数 | 答案 **11** |

考试里这类"给出求值过程中栈的变化"的题非常常见，**照着上面这张表画，一行一行写，别在脑子里跳步**。

### 复杂度与三个易错点

无论是转换还是求值，每个字符最多进栈一次、出栈一次：**时间 O(n)**，空间 O(n)。

三个最容易错的地方，考试前默念一遍：

1. **先弹出的是右操作数**。`a - b` 里的 `b` 先出来，别写反。
2. **同级运算符要弹出**（`>=` 而不是 `>`），否则 `8-2-3` 会算成 `8-(2-3)`。
3. **右括号要把左括号也弹掉**，只是不输出。忘了这一步，`(` 会跑到后缀式里，求值时直接报错。

## 四、队列：像排队买奶茶一样"先进先出"

### 概念

队列和栈正好相反：**先进去的先出来**，叫 FIFO（First In First Out）。

生活里最典型的就是排队：先来的先买到奶茶，后来的排在后面。**插队是不允许的**，你只能在队尾加人、在队首走人。

计算机里也到处是队列：

- **打印机**：三个文档一起打印，先点的先打。
- **客服系统**：先接入的客户先被服务。
- **消息队列**：发出去的消息按顺序被处理。
- **广度优先搜索（BFS）**：第 6 篇讲图的时候，BFS 就是靠队列一层一层往外扩的。

### 术语

```text
   出队 ←┌───┬───┬───┬───┐← 入队
         │ 1 │ 2 │ 3 │ 4 │
         └───┴───┴───┴───┘
        队首              队尾
       front             rear
```

- **入队（enqueue）**：从队尾加。
- **出队（dequeue）**：从队首删。
- **队首（front）**：最早进来的，下一个要走的就是它。
- **队尾（rear）**：最后进来的。

### 用列表实现：`append` 配 `pop(0)`，能用但很慢

最直观的想法是：入队用 `append`（O(1)，完美），出队用 `pop(0)`（删第一个）。

```python
class SlowQueue:
    def __init__(self):
        self.items = []

    def enqueue(self, x):
        self.items.append(x)         # 入队：末尾加，O(1)

    def dequeue(self):
        if not self.items:
            return None
        return self.items.pop(0)     # 出队：删头部，O(n)！


q = SlowQueue()
for i in [1, 2, 3]:
    q.enqueue(i)
print(q.dequeue(), q.dequeue(), q.dequeue())   # 1 2 3
```

功能上完全正确，输出 `1 2 3`。**但第 2 篇我们已经算过账了**：`pop(0)` 要把后面所有元素往前挪一格，是 O(n)。如果出队 n 次，总共就是 O(n²)。

实际有多惨？我们数一下：

```python
n = 10000
a = list(range(n))
moves = 0
for _ in range(n):
    a.pop(0)
    moves += len(a)
print("出队", n, "次，一共挪了", moves, "次")
```

输出：

```text
出队 10000 次，一共挪了 49995000 次
```

一万次出队，挪了五千万次——**这就是 O(n²) 的手感**。

**很多同学会在这里踩坑**：写完 `append` + `pop(0)` 觉得"队列不就是这么简单吗"，然后在数据量大的测试用例上超时。**面试和考试里，这一步是必扣分点。**

### 正确写法 1：加一个"队首下标"

既然删头部才贵，那我们**不删**，只把"队首在哪"记下来：

```python
class Queue:
    def __init__(self):
        self.items = []
        self.head = 0            # 队首下标：从这里开始才是"有效数据"

    def enqueue(self, x):
        self.items.append(x)     # 入队：末尾加，O(1)

    def dequeue(self):
        if self.is_empty():
            return None
        x = self.items[self.head]   # 取出队首
        self.head += 1              # 队首往后挪一格，而不是删元素
        return x

    def is_empty(self):
        return self.head >= len(self.items)

    def size(self):
        return len(self.items) - self.head


q = Queue()
for i in [1, 2, 3]:
    q.enqueue(i)
print("出队", q.dequeue())     # 出队 1
print("出队", q.dequeue())     # 出队 2
print("还剩", q.size(), "个")  # 还剩 1 个
q.enqueue(4)
print("出队", q.dequeue())     # 出队 3
print("出队", q.dequeue())     # 出队 4
print("空了吗", q.is_empty())  # 空了吗 True
```

逐块解释：

- `head` 是一个"指针"，记录**有效数据的起点**。出队时只让 `head += 1`，一步搞定，O(1)。
- `is_empty` 判断的是 `head >= len(items)`：当 `head` 追上列表末尾，说明所有元素都被取走了。
- `size` 是 `len - head`，因为前面 `head` 个元素已经"逻辑上删掉"了，但物理上还在列表里。

**代价**：列表只增不减，前面那些"已经出队但没删"的格子一直占着内存。工程里不会这么写，但这个思路（**用下标代替搬运**）是理解循环队列的钥匙。

### 正确写法 2：直接上 `collections.deque`

工程上（以及你自己写作业时），Python 标准库已经给了答案：

```python
from collections import deque

q = deque()
q.append(1)          # 入队
q.append(2)
q.append(3)
print(q.popleft())   # 1，出队，O(1)
print(q.popleft())   # 2
print("还剩", len(q), "个")   # 还剩 1 个
print(q[0])          # 3，看一眼队首
```

`deque` 是"双端队列"，两头增删都是 O(1)。**考试写代码题允许用 `deque` 就用它**，比自己写省事，而且不会错。但如果题目要求"用列表实现队列"，那就得用上面的 `head` 下标法或循环队列。

### 循环队列：考试最爱考的队列实现

上面"用下标代替搬运"的办法有个毛病：数组会一直往后长。真实实现里（C 语言数组、考试卷子上的画图题），用的是**循环队列**——把数组的尾部接回头部，像一条环形跑道。

你可以这样想：**一个圆形转盘，有 n 个座位**，`front` 指向队首，`rear` 指向下一个空位。走到末尾就绕回 0，用取模 `% n` 实现。

关键在"怎么区分空和满"。因为如果 `front == rear` 既表示空、又可能表示满，就分不清了。标准解法是：**牺牲一个格子**，让数组最多只放 n-1 个元素。于是：

| 判断 | 公式 |
| --- | --- |
| 队空 | `front == rear` |
| 队满 | `(rear + 1) % n == front` |
| 元素个数 | `(rear - front + n) % n` |

**这三个公式请务必背下来**，选择题和填空题直接考。

```python
class CircularQueue:
    def __init__(self, n):
        self.n = n                    # 数组长度 n，最多能放 n-1 个元素
        self.data = [None] * n
        self.front = 0                # 队首下标
        self.rear = 0                 # 下一个入队位置

    def is_empty(self):
        return self.front == self.rear

    def is_full(self):
        return (self.rear + 1) % self.n == self.front

    def size(self):
        return (self.rear - self.front + self.n) % self.n

    def enqueue(self, x):
        if self.is_full():
            return False              # 满了，入队失败
        self.data[self.rear] = x
        self.rear = (self.rear + 1) % self.n   # 绕圈
        return True

    def dequeue(self):
        if self.is_empty():
            return None
        x = self.data[self.front]
        self.front = (self.front + 1) % self.n
        return x


cq = CircularQueue(4)                 # 数组长度 4，最多存 3 个
print(cq.enqueue(1), cq.enqueue(2), cq.enqueue(3))   # True True True
print("满了？", cq.is_full())                        # 满了？ True
print("再入队 4：", cq.enqueue(4))                   # 再入队 4： False
print("出队", cq.dequeue())                          # 出队 1
print("再入队 4：", cq.enqueue(4))                   # 再入队 4： True
print("当前元素个数", cq.size())                     # 当前元素个数 3
print("依次出队：", cq.dequeue(), cq.dequeue(), cq.dequeue())   # 2 3 4
print("空了？", cq.is_empty())                       # 空了？ True
```

输出：

```text
True True True
满了？ True
再入队 4： False
出队 1
再入队 4： True
当前元素个数 3
依次出队： 2 3 4
空了？ True
```

逐块解释：

- `(self.rear + 1) % self.n` 是"往前走一格，走到头就回 0"。取模就是转圈。
- **队满判定用的不是 `rear == front`，而是"rear 再走一格就追上 front"**，这正是"牺牲一个格子"的体现。
- `size` 里为什么要 `+ self.n`？因为 `rear - front` 可能是负数（比如 rear=0、front=3），加上 n 再取模就绕回来了。**这个 `+n` 是很爱考的细节**。

**踩坑提醒**：如果你不牺牲那一格，非要存满 n 个，那 `front == rear` 就同时表示"空"和"满"，必须再额外加一个计数器 `count` 才能区分。**考试里默认按"牺牲一个格子"来答**，除非题目明说"另设计数器"。

### 栈和队列，放一起对比

| 对比项 | 栈 | 队列 |
| --- | --- | --- |
| 进出规则 | 后进先出（LIFO） | 先进先出（FIFO） |
| 操作位置 | 只在**一端**（栈顶） | 两端：队尾进、队首出 |
| 核心操作 | `push` / `pop` | `enqueue` / `dequeue` |
| 用列表实现的代价 | 全部 O(1)，完美 | 出队若用 `pop(0)` 是 O(n)，要用 `head` 下标或循环队列 |
| 典型应用 | 括号匹配、表达式求值、撤销、递归、DFS | 层序遍历、BFS、任务调度、缓冲区 |
| 考试出现形式 | 出栈序列、括号匹配、中缀转后缀 | 循环队列判空判满、BFS 手写 |

**一句话记住区别**：**栈是一摞盘子，队列是一条队伍。** 盘子只能从上面拿，队伍只能从前面走。

## 五、选择题高频：这个出栈序列可能吗？

### 题目形式

> 元素 1、2、3、4、5 依次入栈，入栈过程中可以随时出栈，问下面哪个出栈序列是**不可能**的？

这是栈这一章最经典的送分题（也可能是送命题）。判断方法只有一个：**拿笔模拟**。

规则是：**元素必须按 1,2,3,4,5 的顺序入栈**，但每次入栈之后你都可以选择"立刻弹出栈顶"，也可以选择"先憋着，继续入栈"。问题是：能不能凑出题目给的出栈顺序。

### 手工推演一个例子

问：`4 5 3 2 1` 可能吗？

| 步骤 | 动作 | 栈（底 → 顶） | 已输出 |
| --- | --- | --- | --- |
| 1 | 入 1 | `1` | |
| 2 | 入 2 | `1 2` | |
| 3 | 入 3 | `1 2 3` | |
| 4 | 入 4 | `1 2 3 4` | |
| 5 | 弹 4 | `1 2 3` | 4 |
| 6 | 入 5 | `1 2 3 5` | 4 |
| 7 | 弹 5 | `1 2 3` | 4 5 |
| 8 | 弹 3 | `1 2` | 4 5 3 |
| 9 | 弹 2 | `1` | 4 5 3 2 |
| 10 | 弹 1 | 空 | 4 5 3 2 1 |

**可能**。

再问：`4 3 5 1 2` 可能吗？

前面 4、3、5 都能凑出来（入 1,2,3,4 → 弹 4 → 弹 3 → 入 5 → 弹 5），此时栈里从底到顶是 `1 2`。题目下一个要的是 `1`，但栈顶是 `2`——**1 被 2 压着，出不来**。所以**不可能**。

### 用代码模拟这个判断

思路和手工一模一样：按 1..n 依次入栈，每次入栈后，只要栈顶等于"下一个该输出的数"，就弹出来，直到对不上为止。

```python
def is_valid_pop_order(push_seq, pop_seq):
    stack = []
    j = 0                                   # j 指向 pop_seq 中下一个该输出的位置
    for x in push_seq:
        stack.append(x)                     # 按顺序入栈
        while stack and j < len(pop_seq) and stack[-1] == pop_seq[j]:
            stack.pop()                     # 栈顶正好是想要的，弹出去
            j += 1
    return j == len(pop_seq)                # 全都输出完了才算合法


push = [1, 2, 3, 4, 5]
for pop in [[4, 5, 3, 2, 1], [4, 3, 5, 1, 2], [1, 2, 3, 4, 5], [5, 4, 3, 2, 1]]:
    print(pop, "→", is_valid_pop_order(push, pop))
```

输出：

```text
[4, 5, 3, 2, 1] → True
[4, 3, 5, 1, 2] → False
[1, 2, 3, 4, 5] → True
[5, 4, 3, 2, 1] → True
```

逐块解释：

- `j` 是"出栈序列的进度条"。如果 `pop_seq` 是 `[4,5,3,2,1]`，一开始要的是 `4`，所以要等到 4 入栈才能弹。
- `while` 里三个条件缺一不可：栈非空、`j` 没越界、栈顶正好是想要的。**漏掉 `j < len(pop_seq)` 就会 IndexError**。
- 最后 `j == len(pop_seq)` 说明整个出栈序列都被满足了。如果 `j` 卡在中间，说明栈里还压着东西出不来，不合法。

### 顺便记一个数：卡特兰数

"n 个元素依次入栈，一共有多少种合法的出栈序列？"答案是**卡特兰数**：

```text
C(2n, n) / (n + 1)
```

| n | 合法序列数 |
| --- | --- |
| 1 | 1 |
| 2 | 2 |
| 3 | 5 |
| 4 | 14 |
| 5 | 42 |

n = 3 的 5 种，你可以自己枚举一遍验证：`123、132、213、231、321`。注意 `312` 是不合法的（要 3 先出，说明 1、2 都在栈里，那 1 就被 2 压住了）。

选择题里如果问"不可能的出栈序列"，用模拟法最稳；如果问"共有多少种"，直接套卡特兰数。

## 六、这一章最容易踩的 7 个坑

**1. 空栈还 `pop()`**

```python
stack = []
# x = stack.pop()   # IndexError: pop from empty list
```

**每次 `pop` 之前都要问一句"会不会是空的"**。手写代码时加一个 `if not stack: return ...`，老师看到会觉得你考虑周全。

**2. 用 `pop(0)` 实现队列**

功能对，复杂度错（O(n²)）。这是本章最贵的错误，一道 10 分的题可能因为这一行扣掉一半。

**3. 后缀求值把 `a - b` 写成 `b - a`**

`82-` 应该得 6，写成 `b - a` 得 -6。**先弹出的永远是右边的数**，这个必须形成肌肉记忆。

**4. 括号匹配只数个数**

`s.count("(") == s.count(")")` 对 `([)]` 无效。而且这只考虑了圆括号，方括号花括号全漏了。

**5. 忘了检查"最后栈必须为空"**

只写 `return True`（在循环结束后），`((` 会被判成正确。**栈里剩下的东西就是没配对的左括号**，这一条是本题的"收尾判据"。

**6. 中缀转后缀时用 `>` 而不是 `>=`**

`8-2-3` 会算成 `8-(2-3)=9`。同级运算符**必须**弹出，因为要从左往右算。

**7. 把列表的头部当栈顶**

```python
stack = [1, 2, 3]
stack.insert(0, 4)   # 想"入栈"却插到了头部，O(n)
stack.pop(0)         # 想出栈却删头部，O(n)
```

栈顶应该固定在**列表末尾**，用 `append` / `pop()`。方向搞反，功能也许还能凑对，但复杂度从 O(1) 变成 O(n)，而且可读性极差。

## 七、典型考题

### 考题 1（手写代码）

> 用栈判断一个只含 `(`、`)`、`[`、`]`、`{`、`}` 的字符串是否括号匹配。要求：匹配返回 `True`，否则返回 `False`；空串返回 `True`。并分析复杂度。

**参考答案：**

```python
def is_matched(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in ")]}":
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()
    return len(stack) == 0


print(is_matched("{[()()]}"))   # True
print(is_matched("([)]"))       # False
print(is_matched("((("))        # False
print(is_matched(""))           # True
```

**解析与评分点：**

1. **`pairs` 字典**（或等价的 if-elif 分支）必须有，这是"类型匹配"的关键。只判断"是不是右括号"而不判断"是哪种右括号"，`(]` 会漏判。
2. **`not stack`** 处理右括号多余的情况。没有这一句，空栈时会 `IndexError`。
3. **`return len(stack) == 0`** 处理左括号多余的情况。这是最容易被扣分的一行。
4. **复杂度**：时间 O(n)，空间 O(n)（最坏全左括号）。

**小技巧**：如果你怕字典写错，可以反过来存——`pairs = {"(": ")", "[": "]", "{": "}"}`，遇到右括号时就判断 `pairs[stack[-1]] != ch`。两种都行，选一种写熟。

### 考题 2（手工 + 代码）

> 已知中缀表达式 `1+2*(3-4)`：
> （1）写出它的后缀表达式；
> （2）写出求值过程中栈的变化，并给出结果。

**参考答案：**

（1）后缀表达式是 **`1234-*+`**。

（2）求值过程：

| 读到 | 动作 | 栈（底 → 顶） |
| --- | --- | --- |
| `1` | 压栈 | `1` |
| `2` | 压栈 | `1 2` |
| `3` | 压栈 | `1 2 3` |
| `4` | 压栈 | `1 2 3 4` |
| `-` | 弹 4、弹 3，算 3-4 = -1，压回 | `1 2 -1` |
| `*` | 弹 -1、弹 2，算 2*(-1) = -2，压回 | `1 -2` |
| `+` | 弹 -2、弹 1，算 1+(-2) = -1，压回 | `-1` |

**结果：-1**。

**转换过程的推演（建议在卷子上也写，能拿过程分）：**

| 读到 | 动作 | 运算符栈 | 输出 |
| --- | --- | --- | --- |
| `1` | 输出 | — | `1` |
| `+` | 入栈 | `+` | `1` |
| `2` | 输出 | `+` | `12` |
| `*` | 栈顶 `+` 优先级低，不弹；`*` 入栈 | `+ *` | `12` |
| `(` | 入栈 | `+ * (` | `12` |
| `3` | 输出 | `+ * (` | `123` |
| `-` | 栈顶是 `(`，不弹；`-` 入栈 | `+ * ( -` | `123` |
| `4` | 输出 | `+ * ( -` | `1234` |
| `)` | 弹到 `(` 为止：弹出 `-` 输出，再弹掉 `(` | `+ *` | `1234-` |
| 结束 | 清空栈：弹 `*`、弹 `+` | — | `1234-*+` |

**这道题的两个坑**：

1. 负数的计算。`3-4 = -1` 时，**弹出顺序仍是"先右后左"**：先弹 4（b），再弹 3（a），算 `a-b`。写代码时如果用的是 `int()` 只处理数字字符，负数结果照样能存进栈里，不影响后续（栈里存的是整数，不是字符）。
2. `2*(-1)` 要用乘法，别抄成减法。手工推的时候**每写一步就核对一次栈**，比事后检查有效得多。

## 八、考试怎么考

**选择题**：

- "栈的特点是什么"（后进先出）、"队列的特点"（先进先出）。
- 给定入栈序列，问哪个出栈序列不可能（用本篇第五节的模拟法）。
- 循环队列：`front == rear` 表示什么、`(rear+1)%n == front` 表示什么、当前元素个数怎么算。
- 中缀 `A+B*C-D` 的后缀式是什么（`ABC*+D-`）。
- 后缀式 `AB+C*` 对应的中缀式是什么（`(A+B)*C`）。
- 栈和队列的常见应用配对（撤销→栈，打印任务→队列，BFS→队列，括号匹配→栈）。

**填空题**：

- "栈的插入和删除操作都在 \_\_\_\_ 进行"（填"栈顶"）。
- "队列的插入在 \_\_\_\_，删除在 \_\_\_\_"（队尾 / 队首）。
- "循环队列中判断队满的条件是 \_\_\_\_"。
- 给一个后缀表达式，填求值结果。

**读代码写输出**：给你一段用列表模拟栈/队列的代码，问最后输出什么。注意 `append` / `pop` / `pop(0)` 的方向，**在纸上画一个栈，一步步跟着代码走**。

**手写代码**：三个高频——括号匹配、用两个栈/队列的简单操作、用列表实现栈或队列类。**括号匹配是重中之重**，几乎每年都有。

**复杂度分析**：括号匹配、中缀转后缀、后缀求值，**全是 O(n)**。如果出队用了 `pop(0)`，就会被问"为什么是 O(n²)"——这时候你要能说出"每次出队都要移动后面所有元素"。

---

## 九、小结

这一篇的两句话：

1. **栈 = 只在一头操作**，后进先出。因为只动末尾，所有操作都是 O(1)。它解决的是"**最近的东西最先需要**"这一类问题——括号、表达式、撤销、递归。
2. **队列 = 一头进、另一头出**，先进先出。难点全在"出队"上：用 `pop(0)` 是 O(n)，要用 `head` 下标、`deque` 或循环队列，才能做到 O(1)。

如果只记一个画面，就记这个：

> **栈是一摞盘子，队列是一条队伍。** 盘子上下一拿就完事，队伍前面走一个人，后面所有人都得跟着动——这就是为什么队列的实现要比栈费心。

还有一句方法论，值得你带走：**"受限"不是缺点，是设计**。栈和队列都放弃了"随便访问中间元素"的自由，换来了简单、稳定、O(1)。后面学树、图、堆，你会发现这个思路一直在重复。

## 下一篇讲什么

栈和队列都用连续的空间存数据。可你有没有想过一个问题：**顺序表插在中间要挪一堆元素，能不能不挪？**

能。办法是**不要求连续**——每个元素记住"下一个在哪"，用一根"链子"串起来。这就是**链表**。

下一篇《链表》会从"节点类"讲起，手把手教你用 `ListNode` 串出一条链，然后写遍历、插入、删除、反转。你会看到它的插入删除真的是 O(1)（只要已经站到那个位置），也会看到它为此付出的代价——不能按下标直接跳，找第 k 个必须从头走。**链表还是后面树和图的地基**，`node.next` 这个写法会一直跟着你到最后一篇。
