## 一、先弄明白"排序"在考什么

### 一句话定义

**排序**：把一组数据按关键字重新排列，使它们**递增（或递减）有序**。

数据结构教材里的排序默认**递增**，本文也一样。

### 排序的代价只看三件事

| 看什么 | 具体是 | 为什么重要 |
| --- | --- | --- |
| **时间** | 比较了多少次、移动了多少次 | 决定 n 变大以后还跑不跑得动 |
| **空间** | 除了原数组，还要额外借多少内存 | 能不能**原地**排（O(1) 还是 O(n)） |
| **稳定性** | 关键字相等的两个元素，排完谁在前 | 决定多关键字排序"能不能分两趟做" |

前两个是大 O 的老朋友（第 2 篇讲过），第三个是排序独有的概念，也是考试最爱挖的坑。

### 稳定性：相等元素的相对次序不能变

定义：**如果排序前 `a` 在 `b` 前面，且 `a`、`b` 的关键字相等，排完序 `a` 仍然在 `b` 前面**，这个算法就叫**稳定**的。反之叫不稳定。

注意这里说的"相等"是**关键字相等**，不是整个元素一模一样。

**为什么考试这么在意稳定性？** 因为多关键字排序要靠它：

> 学生表要按「分数降序，分数相同按学号升序」排。
>
> 做法：**先用稳定排序按学号排一遍**（次要关键字打底），**再用稳定排序按分数排一遍**（主要关键字）。
>
> - 第二趟排序是稳定的 ⇒ 分数相同的那些人，**保留第一趟排好的学号顺序**；
> - 如果第二趟用的是**不稳定**排序 ⇒ 分数相同的人的相对次序被随机打乱，前面的学号白排了。

**一句话**：稳定性就是"多关键字排序能不能拆成几趟做"的许可证。

### 内部排序 vs 外部排序

| | 内部排序 | 外部排序 |
| --- | --- | --- |
| 数据在哪 | 全部在**内存**里 | 数据太大，要放**外存**（磁盘文件） |
| 代表算法 | 本篇讲的八大排序 | **多路归并排序**（先分段排好写回磁盘，再逐段归并） |
| 考试要求 | 会算复杂度、会写一趟结果 | 一般只考一句"外部排序用归并" |

本篇讲的全部是**内部排序**。

### 统一用一组数据

后面所有算法都拿这一组数当靶子，方便你横向对照：

```python
data = [5, 2, 9, 1, 7, 6, 3]
print("原始数据:", data)
print("排好之后:", sorted(data))
```

输出：

```text
原始数据: [5, 2, 9, 1, 7, 6, 3]
排好之后: [1, 2, 3, 5, 6, 7, 9]
```

**八个排序算法跑出来的结果都是最后这一行**，区别只在"过程怎么走、代价多大"。

### n² 和 n log n 到底差多少

排序分两大阵营：**O(n²)** 和 **O(n log n)**。别小看这个差别，n = 1000 时是几十倍的差距：

```python
import math

n = 1000
print("O(n²) 级别的操作数  ≈", n * n // 2)
print("O(n log n) 级别的操作数 ≈", int(n * math.log2(n)))
```

输出：

```text
O(n²) 级别的操作数  ≈ 500000
O(n log n) 级别的操作数 ≈ 9965
```

**50 倍。** n 再大一点就是 500 倍、5000 倍——这就是为什么八大排序要分成两个阵营来背。

### 八大排序家族总览

| 阵营 | 算法 | 平均时间 | 记忆点 |
| --- | --- | --- | --- |
| O(n²) 三兄弟 | 冒泡、选择、插入 | O(n²) | 双层循环，写起来最简单 |
| O(n log n) 三巨头 | 快速、归并、堆 | O(n log n) | 都靠"分"或"树的高度" |
| 非比较 | 计数、基数（还有桶） | O(n+k)、O(d(n+r)) | 不比较大小，靠"分配" |

先记住这三行，后面八个算法一个个拆。

## 二、O(n²) 三兄弟：能排，但慢

三个算法都是**双层循环**，代码短、思路直白，考试却特别爱问"它稳定吗""最好情况是什么"。最后再附赠一个插入排序的加强版——**希尔排序**，它也经常出现在选择题里。

### 2.1 冒泡排序：相邻比较，大的往后冒

**思想**：从左到右，相邻两个比一比，前面的比后面大就换过来。走完一趟，**当前最大的那个一定被"冒"到了末尾**；再走一趟，第二大到位……总共走 n-1 趟。

```python
def bubble_sort(a):
    a = a[:]                      # 不破坏原数据
    n = len(a)
    for i in range(n - 1):        # 一共 n-1 趟
        swapped = False
        for j in range(n - 1 - i):        # 末尾 i 个已经排好，不用再比
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:           # 这一趟一次都没换 ⇒ 已经有序
            break
    return a


print(bubble_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
[1, 2, 3, 5, 6, 7, 9]
```

**每趟做了什么**，看一眼就懂：

```python
data = [5, 2, 9, 1, 7, 6, 3]
b = data[:]
n = len(b)
for i in range(n - 1):
    swapped = False
    for j in range(n - 1 - i):
        if b[j] > b[j + 1]:
            b[j], b[j + 1] = b[j + 1], b[j]
            swapped = True
    print(f"第 {i + 1} 轮: {b}")
    if not swapped:
        print("  本轮没有交换，提前结束")
        break
```

输出：

```text
第 1 轮: [2, 5, 1, 7, 6, 3, 9]
第 2 轮: [2, 1, 5, 6, 3, 7, 9]
第 3 轮: [1, 2, 5, 3, 6, 7, 9]
第 4 轮: [1, 2, 3, 5, 6, 7, 9]
第 5 轮: [1, 2, 3, 5, 6, 7, 9]
  本轮没有交换，提前结束
```

**读这三行**：

- 第 1 轮结束，9 到位（最后一格）
- 第 2 轮结束，7 到位
- 第 3 轮结束，6 到位……每轮固定"钉住"一个最大值
- 第 4 轮数组其实已经有序了，但程序不知道，第 5 轮又比了 2 次，发现一次都没交换才敢退出

**没有 `swapped` 优化的版本，哪怕数组一开始就有序，也要老老实实比完 n(n-1)/2 次。**

#### 复杂度与稳定性

| 项 | 值 | 为什么 |
| --- | --- | --- |
| 最好情况 | **O(n)** | 已经有序，第 1 趟比 n-1 次、0 次交换，直接退出 |
| 最坏情况 | O(n²) | 完全逆序，每趟都要换 |
| 平均 | O(n²) | 比较次数 θ(n²) |
| 空间 | **O(1)** | 只用了 `i`、`j`、`swapped` |
| 稳定性 | **稳定** ✓ | 代码写的是 `a[j] > a[j + 1]`，**相等时不交换** |

**稳定性的关键就是那个 `>`**：如果手滑写成 `>=`，相等元素就会被换位置，冒泡立刻变成不稳定排序。

**交换次数有个说法**：冒泡排序的交换次数**正好等于这组数据的"逆序对"个数**（前大后小的数对有几对）。这一组数据冒泡比较了 20 次、交换了 11 次。

### 2.2 选择排序：每轮挑最小的，放到前面

**思想**：把数组分两段——**前面已排好**，**后面还没排**。每一轮在"没排"的部分里找到最小值，**和"没排"部分的第一个元素交换**。

```python
def selection_sort(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):          # i 是"已排好"和"没排"的分界线
        m = i                       # 先假定没排部分的第一个最小
        for j in range(i + 1, n):
            if a[j] < a[m]:
                m = j               # 记住最小值的下标，不急着换
        if m != i:                  # 每轮最多换一次
            a[i], a[m] = a[m], a[i]
    return a


print(selection_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
[1, 2, 3, 5, 6, 7, 9]
```

**和冒泡的最大区别**：冒泡是"边比边换"，选择是"**比完一整轮才换一次**"。所以同样这组数据：

| | 比较次数 | 交换次数 |
| --- | --- | --- |
| 冒泡排序 | 20 | 11 |
| 选择排序 | **21** | **3** |

比较次数是固定的 6+5+4+3+2+1 = 21 = n(n-1)/2，**和数据长什么样完全无关**；但交换只有 3 次。

#### 复杂度与稳定性

| 项 | 值 | 为什么 |
| --- | --- | --- |
| 最好情况 | O(n²) | **注意！**不管数据多有序，都要比完 n(n-1)/2 次 |
| 最坏情况 | O(n²) | 同上 |
| 平均 | O(n²) | 同上 |
| 空间 | **O(1)** | 原地 |
| 稳定性 | **不稳定** ✗ | 远距离交换会打乱相等元素的顺序 |

**这是选择题的常客**：**选择排序的最好、最坏、平均全都是 O(n²)**，没有"最好 O(n)"这种好事——因为它不检查"是不是已经有序了"。

**为什么不稳定？** 交换的两个位置隔得很远，中间那些相等元素就被跨过去了：

```python
# 用 (值, 标记) 表示元素，标记用来追踪"谁原来在前面"
items = [(5, "a"), (5, "b"), (2, "c")]

def selection_sort_tagged(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if a[j][0] < a[m][0]:       # 只比第 0 位（关键字）
                m = j
        if m != i:
            a[i], a[m] = a[m], a[i]
    return a

print("排序前:", items)
print("排序后:", selection_sort_tagged(items))
```

输出：

```text
排序前: [(5, 'a'), (5, 'b'), (2, 'c')]
排序后: [(2, 'c'), (5, 'b'), (5, 'a')]
```

`5a` 本来在 `5b` 前面，排完变成 `5b` 在前了 ⇒ **不稳定**。原因是第 1 轮把最小的 `2c` 从下标 2 直接换到下标 0，`5a` 被扔到下标 2，**越过了 `5b`**。

**选择排序的唯一优势**：交换次数最少（最多 n-1 次）。元素很大、交换很贵时（比如结构体数组），它反而划算。

### 2.3 插入排序：像整理扑克牌

**思想**：左手是已经排好的牌，右手每次摸一张，**插到左手合适的位置**。数组上就是：把 `a[i]` 往前挪，直到前面那个数比它小。

```python
def insertion_sort(a):
    a = a[:]
    for i in range(1, len(a)):       # a[0] 自己就算有序，从 i=1 开始
        cur = a[i]                   # 把要插入的牌"抽"出来
        j = i - 1
        while j >= 0 and a[j] > cur:     # 比 cur 大的都往后挪一格
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = cur               # 空出来的位置放 cur
    return a


print(insertion_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
[1, 2, 3, 5, 6, 7, 9]
```

**`while` 里两个条件缺一不可**：`j >= 0` 防止越界，`a[j] > cur` 决定要不要挪。**写得好的插入排序，在处理"几乎有序"的数据时近乎是 O(n)。**

#### 复杂度与稳定性

| 项 | 值 | 为什么 |
| --- | --- | --- |
| 最好情况 | **O(n)** | 已经有序，每个元素只和左邻居比 1 次就停 |
| 最坏情况 | O(n²) | 完全逆序，第 i 个元素要挪 i 次 |
| 平均 | O(n²) | 大约挪 n²/4 次 |
| 空间 | **O(1)** | 原地 |
| 稳定性 | **稳定** ✓ | `a[j] > cur` 才挪，**遇到相等就停下**，相等的元素不会互相越过 |

**"基本有序"到底能快多少？** 数一数移动次数最直观：

```python
def insertion_moves(a):
    a = a[:]
    moves = 0
    for i in range(1, len(a)):
        cur = a[i]
        j = i - 1
        while j >= 0 and a[j] > cur:
            a[j + 1] = a[j]
            j -= 1
            moves += 1
        a[j + 1] = cur
    return moves

ordered = list(range(1, 11))          # 完全有序
almost = list(range(1, 11))
almost[3], almost[4] = almost[4], almost[3]   # 只把 4 和 5 换了位置
reversed_ = list(range(10, 0, -1))    # 完全逆序

print("完全有序 10 个，移动", insertion_moves(ordered), "次")
print("几乎有序 10 个，移动", insertion_moves(almost), "次")
print("完全逆序 10 个，移动", insertion_moves(reversed_), "次")
```

输出：

```text
完全有序 10 个，移动 0 次
几乎有序 10 个，移动 1 次
完全逆序 10 个，移动 45 次
```

45 = 10×9/2 = n(n-1)/2。**同样 10 个数，从 0 次移动跳到 45 次**——数据的有序程度对插入排序的影响是数量级的。所以工程里常这么干：**大数据先用快排切到很小，小区间（< 10 个）改用插入排序收尾**。

**插入排序稳定性的精髓也在这儿**：`a[j] > cur` 而不是 `>=`，相等时 `while` 立刻停，`cur` 插到相等元素的**后面**，原来的先后关系保住了。

### 2.4 附赠：希尔排序——插入排序的加强版

**动机**：插入排序有个短板——**每次只能把元素往前挪一格**。如果一个很小的数在末尾，它得慢慢挪 n-1 次才能到前面。

**希尔排序的思路**：先按一个较大的**间隔 gap** 把数组"分组"，组内做插入排序，让元素能**大步长地跳到前面**；然后 gap 不断缩小（比如每次减半），最后 gap = 1 时做一次普通插入排序——这时候数组已经"基本有序"，插入排序几乎不费劲。

```python
def shell_sort(a):
    a = a[:]
    n = len(a)
    gap = n // 2                     # 初始间隔取一半
    while gap > 0:
        for i in range(gap, n):      # 对每个"间隔 gap 的子序列"做插入排序
            cur = a[i]
            j = i - gap
            while j >= 0 and a[j] > cur:
                a[j + gap] = a[j]    # 一次挪 gap 格，不是 1 格
                j -= gap
            a[j + gap] = cur
        print(f"gap = {gap} 之后:", a)
        gap //= 2                    # 间隔减半
    return a


print(shell_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
gap = 3 之后: [1, 2, 6, 3, 7, 9, 5]
gap = 1 之后: [1, 2, 3, 5, 6, 7, 9]
[1, 2, 3, 5, 6, 7, 9]
```

**看第一行**：gap = 3 时，数组被切成 3 组——`(5, 1, 3)`、`(2, 7)`、`(9, 6)`，每组各自插入排序后拼回去，就得到 `[1, 2, 6, 3, 7, 9, 5]`。此时**小的数已经大步跳到了前面**（1 从下标 3 跳到下标 0），最后一趟 gap = 1 只做微调。

#### 复杂度与稳定性

| 项 | 值 | 说明 |
| --- | --- | --- |
| 平均 | 约 **O(n^1.3)** | 具体与增量序列有关，考试写这个数就行 |
| 最坏 | O(n²) | 某些增量序列下会退化 |
| 空间 | **O(1)** | 原地 |
| 稳定性 | **不稳定** ✗ | 分组是跨着来的，相等元素可能被换到不同组 |

**两个考试要点**：

1. **增量序列最后必须是 1**，否则数组一定没排完
2. **希尔排序不稳定**，因为它做的是**跨间隔的移动**，相等元素没法保证不被越过

### O(n²) 家族横向对比

| | 冒泡 | 选择 | 插入 | 希尔 |
| --- | --- | --- | --- | --- |
| 最好情况 | O(n) | O(n²) | **O(n)** | — |
| 平均 / 最坏 | O(n²) | O(n²) | O(n²) | O(n^1.3) / O(n²) |
| 比较次数 | 与数据有关 | **恒为 n(n-1)/2** | 与数据有关 | 与数据和 gap 有关 |
| 交换/移动次数 | 多（= 逆序对） | **最少（≤ n-1）** | 中等 | 比插入少 |
| 稳定性 | 稳定 ✓ | **不稳定** ✗ | 稳定 ✓ | **不稳定** ✗ |
| 一句话 | 最慢但最稳 | 交换最省 | 基本有序时最快 | 插入排序的加强版 |

## 三、O(n log n) 三巨头：n 大了就靠它们

三个算法都用到同一个想法：**把问题拆小**。快排和归并用的是"分治"，堆排序用的是"完全二叉树的高度是 log n"（第 5 篇的堆）。

### 3.1 快速排序：选个基准，分两边

**思想**（三步）：

1. **选一个基准（pivot）**，比如最后一个元素
2. **划分（partition）**：把区间里的数分成两拨——比 pivot 小的全挪到左边，比 pivot 大的留在右边，pivot 自己坐到中间
3. **对左右两半递归重复**（长度为 0 或 1 就不用排了）

**关键就是 partition**。它做完之后，**pivot 已经在最终位置上了**，而且左半都 ≤ pivot ≤ 右半——这叫"**一趟划分确定一个元素的最终位置**"，也是考题"写出一趟快排结果"的由来。

#### 先把 partition 拆开

用「`i` 指向小于区的下一个空位，`j` 从头扫到尾」的写法（教材叫 **Lomuto 划分**）：

```python
def partition(a, low, high):
    pivot = a[high]              # 基准取区间最后一个
    i = low                      # i 左边（不含 i）都是小于 pivot 的
    for j in range(low, high):   # j 负责扫描
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1               # 小于区扩大一格
    a[i], a[high] = a[high], a[i]    # 最后把 pivot 换到分界处
    return i                     # 返回 pivot 的最终下标
```

**这段只有 8 行，但每一行都有人在考场上写错**。跑一遍看它到底在干什么：

```python
def partition_verbose(a, low, high):
    pivot = a[high]
    i = low
    print(f"pivot = {pivot}（最后一个元素），i 指向 {i}")
    print(f"初始: {a}")
    for j in range(low, high):
        val = a[j]
        if val < pivot:
            a[i], a[j] = a[j], a[i]
            print(f"j={j}: {val} < {pivot} → 交换 a[{i}],a[{j}] → {a}，i 右移到 {i + 1}")
            i += 1
        else:
            print(f"j={j}: {val} >= {pivot} → 不动 → {a}")
    a[i], a[high] = a[high], a[i]
    print(f"最后把 pivot 换到位置 {i}: {a}")
    return i


b = [5, 2, 9, 1, 7, 6, 3]
p = partition_verbose(b, 0, len(b) - 1)
print("左半:", b[:p], "| pivot:", b[p], "| 右半:", b[p + 1:])
```

输出：

```text
pivot = 3（最后一个元素），i 指向 0
初始: [5, 2, 9, 1, 7, 6, 3]
j=0: 5 >= 3 → 不动 → [5, 2, 9, 1, 7, 6, 3]
j=1: 2 < 3 → 交换 a[0],a[1] → [2, 5, 9, 1, 7, 6, 3]，i 右移到 1
j=2: 9 >= 3 → 不动 → [2, 5, 9, 1, 7, 6, 3]
j=3: 1 < 3 → 交换 a[1],a[3] → [2, 1, 9, 5, 7, 6, 3]，i 右移到 2
j=4: 7 >= 3 → 不动 → [2, 1, 9, 5, 7, 6, 3]
j=5: 6 >= 3 → 不动 → [2, 1, 9, 5, 7, 6, 3]
最后把 pivot 换到位置 2: [2, 1, 3, 5, 7, 6, 9]
左半: [2, 1] | pivot: 3 | 右半: [5, 7, 6, 9]
```

**盯着 `pivot = 3`、`i` 这个变量看**：

| 时刻 | `i` 的位置 | `i` 左边的数 |
| --- | --- | --- |
| 开始 | 0 | 无 |
| j=1 之后 | 1 | `[2]`——都比 3 小 |
| j=3 之后 | 2 | `[2, 1]`——都比 3 小 |
| 结束 | 2 | `[2, 1]`，pivot 换到下标 2 |

`i` 永远指向"小于区"的**下一个空位**，所以每遇到一个小数，就把它扔到 `i` 那里、再让 `i` 往右挪。**9、5、7、6 这些大数被 `i` 路过后原地不动，自然就留在了右边。**

#### 完整快排

```python
def partition(a, low, high):
    pivot = a[high]
    i = low
    for j in range(low, high):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[high] = a[high], a[i]
    return i


def quick_sort(a):
    a = a[:]

    def _quick(low, high):
        if low >= high:              # 只剩 0 个或 1 个元素，天然有序
            return
        p = partition(a, low, high)  # p 位置的元素已到位
        _quick(low, p - 1)           # 排左边
        _quick(p + 1, high)          # 排右边

    _quick(0, len(a) - 1)
    return a


print(quick_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
[1, 2, 3, 5, 6, 7, 9]
```

**递归终止条件 `low >= high` 千万别写成 `low == high`**：划分后可能出现 `p - 1 < low`（比如空区间），`low > high` 是常态，只判等会无限递归。

#### 复杂度：平均很美，最坏很丑

| 项 | 值 |
| --- | --- |
| 最好 / 平均 | **O(n log n)** |
| 最坏 | **O(n²)** |
| 空间 | 平均 O(log n)、最坏 O(n)（递归栈） |
| 稳定性 | **不稳定** ✗ |

**为什么平均是 O(n log n)**：每层 partition 加起来要扫 O(n) 个元素；如果每次划分都比较均匀，n 个元素大概 log₂n 层就分完了 ⇒ O(n log n)。

**为什么最坏是 O(n²)**：如果每次都挑到当前区间的最大/最小值，划分就变成"一边 0 个、一边 n-1 个"，退化成**冒泡式的 n 层递归**，每层还是 O(n) ⇒ O(n²)。

**最典型的踩雷场景：数据本来就有序，pivot 还取最后一个。** 实测一下递归深度：

```python
def quick_depth(a):
    a = a[:]
    depth = [0]

    def _q(low, high, d):
        if low >= high:
            return
        depth[0] = max(depth[0], d)
        pivot = a[high]
        i = low
        for j in range(low, high):
            if a[j] < pivot:
                a[i], a[j] = a[j], a[i]
                i += 1
        a[i], a[high] = a[high], a[i]
        _q(low, i - 1, d + 1)
        _q(i + 1, high, d + 1)

    _q(0, len(a) - 1, 1)
    return depth[0]


print("已有序的 8 个数，递归深度:", quick_depth(list(range(1, 9))))
print("乱序的 8 个数，递归深度:", quick_depth([5, 2, 9, 1, 7, 6, 3, 8]))
```

输出：

```text
已有序的 8 个数，递归深度: 7
乱序的 8 个数，递归深度: 4
```

有序数据递归 7 层（= n-1），乱序只有 4 层（≈ log₂8 = 3，再加常数）。**8 个元素差 3 层，8000 个元素就是 8000 层 vs 13 层的差别**——最坏情况下递归栈直接爆掉。

#### 四条优化（面试/大题加分项）

| 优化 | 解决什么 | 怎么做 |
| --- | --- | --- |
| **随机选 pivot** | 已有序/已逆序时退化 | 先随机挑一个和末尾交换，再走原流程 |
| **三数取中** | 同上，且不用随机数 | 取 `a[low]`、`a[mid]`、`a[high]` 的中位数当 pivot |
| **小区间切插入排序** | 递归到很小（< 10 个）时快排反而慢 | `if high - low < 10: 用插入排序; return` |
| **三路划分** | 大量重复元素时退化 | 分成 `< pivot`、`== pivot`、`> pivot` 三段，相等的直接不再递归 |

#### 为什么快排不稳定？

partition 里那次 `a[i], a[j] = a[j], a[i]` 是**远距离交换**，和选择排序一个毛病：相等元素被隔着换过去，次序就乱了。用 5 个元素实测：

```python
items = [(3, "a"), (1, "b"), (3, "c"), (2, "d"), (1, "e")]

def quick_tagged(a):
    a = a[:]

    def q(low, high):
        if low >= high:
            return
        pivot = a[high]
        i = low
        for j in range(low, high):
            if a[j][0] < pivot[0]:
                a[i], a[j] = a[j], a[i]
                i += 1
        a[i], a[high] = a[high], a[i]
        q(low, i - 1)
        q(i + 1, high)

    q(0, len(a) - 1)
    return a


print("原始:", items)
print("快排:", quick_tagged(items))
```

输出：

```text
原始: [(3, 'a'), (1, 'b'), (3, 'c'), (2, 'd'), (1, 'e')]
快排: [(1, 'e'), (1, 'b'), (2, 'd'), (3, 'a'), (3, 'c')]
```

`1b` 本来在 `1e` 前面，排完 `1e` 跑到前面去了 ⇒ **不稳定**（3a、3c 这次恰好没乱，但只要有相等的数就有风险）。

### 3.2 归并排序：先拆到不能再拆，再两两合并

**思想**（分治三步）：

1. **分**：把数组从中间劈成两半，递归劈下去，直到每段只剩 1 个元素（1 个元素天然有序）
2. **治**：把两个**已经有序**的半段合并成一个有序段
3. **合**：一路合上去，合到只剩一段

**全部功夫都在"合并"这一步**。合并两个有序数组很简单：两个指针各指一个头，谁小先取谁。

```python
def merge(left, right):
    res = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:      # 关键：用 <=，相等先取左边
            res.append(left[i])
            i += 1
        else:
            res.append(right[j])
            j += 1
    res.extend(left[i:])             # 谁还有剩，直接整段接上
    res.extend(right[j:])
    return res


print(merge([2, 5], [1, 3]))
```

输出：

```text
[1, 2, 3, 5]
```

**`<=` 这个等号是稳定性的命门**：`left[i] == right[j]` 时先取**左边**的，左边本来就在前面 ⇒ 相等元素的相对次序保住了。写成 `<` 就变成先取右边 ⇒ 归并排序立刻不稳定。

#### 递归怎么拆的

```text
              [5, 2, 9, 1, 7, 6, 3]
             /                    \
        [5, 2, 9]              [1, 7, 6, 3]
        /       \               /        \
      [5]     [2, 9]         [1, 7]     [6, 3]
              /    \          /   \      /   \
            [2]   [9]       [1]   [7]  [6]   [3]

合并回来：
  [2] + [9]        → [2, 9]
  [5] + [2, 9]     → [2, 5, 9]
  [6] + [3]        → [3, 6]
  [1, 7] + [3, 6]  → [1, 3, 6, 7]
  [2, 5, 9] + [1, 3, 6, 7] → [1, 2, 3, 5, 6, 7, 9]
```

**树的深度是 ⌈log₂n⌉，每层的合并加起来都是 O(n)** ⇒ 总复杂度 O(n log n)。而且**不管数据长什么样，都是这个数**——归并没有"最坏情况变差"的毛病。

#### 完整代码

```python
def merge(left, right):
    res = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            res.append(left[i])
            i += 1
        else:
            res.append(right[j])
            j += 1
    res.extend(left[i:])
    res.extend(right[j:])
    return res


def merge_sort(a):
    if len(a) <= 1:                  # 只剩 0/1 个元素，天然有序
        return a[:]
    mid = len(a) // 2
    left = merge_sort(a[:mid])       # 排好左半
    right = merge_sort(a[mid:])      # 排好右半
    return merge(left, right)        # 合并两个有序段


print(merge_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
[1, 2, 3, 5, 6, 7, 9]
```

#### 复杂度与稳定性

| 项 | 值 | 说明 |
| --- | --- | --- |
| 最好 / 平均 / 最坏 | **都是 O(n log n)** | 与数据初始状态无关 |
| 空间 | **O(n)** | 合并时要额外开结果数组（递归还占 O(log n) 栈） |
| 稳定性 | **稳定** ✓ | `left[i] <= right[j]` |

**归并的两个标签**：

- **"最稳的 O(n log n)"**：三个 n log n 的算法里，只有归并和堆排最坏也是 n log n（快排会掉到 n²）
- **外部排序的地基**：数据大到内存放不下时，先分段排好写回磁盘，再"多路归并"合并成一个大文件——考试问"外部排序用什么方法"，答案就是**归并**

**它的缺点也很明确**：要 O(n) 额外空间，**不是原地排序**。所以内存紧张时宁可用堆排。

### 3.3 堆排序：把数组当成完全二叉树

这个算法第 5 篇已经见过一次（当时叫"堆"），这里只补排序那一步。**整棵逻辑结构是数组，不用建任何节点。**

**两个前提**（第 5 篇背过的）：

- 下标 `i` 的**左孩子是 `2i+1`**、**右孩子是 `2i+2`**，**父节点是 `(i-1)//2`**
- **大顶堆**：父节点 ≥ 两个孩子 ⇒ **堆顶 `a[0]` 永远是最大值**

**排序分两步**：

1. **建堆**：从**最后一个非叶子结点**（下标 `n//2 - 1`）倒着往前，每个都"下沉"一次 ⇒ 整个数组变成大顶堆
2. **反复取堆顶**：堆顶（最大值）和**当前堆的最后一个元素**交换 ⇒ 最大值就位；堆的范围缩小 1，新的堆顶再下沉恢复堆性质 ⇒ 重复 n-1 次

```python
def sift_down(a, i, size):
    """让 a[i] 下沉到合适位置，维持大顶堆（size 是当前堆的大小）"""
    while True:
        left, right = 2 * i + 1, 2 * i + 2
        largest = i
        if left < size and a[left] > a[largest]:
            largest = left
        if right < size and a[right] > a[largest]:
            largest = right
        if largest == i:             # 父节点已经是最大的，停
            return
        a[i], a[largest] = a[largest], a[i]
        i = largest                  # 继续往下检查


def heap_sort(a):
    a = a[:]
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):    # 建堆：从最后一个非叶子倒着来
        sift_down(a, i, n)
    print("建堆完成:", a)
    for end in range(n - 1, 0, -1):        # 每次把堆顶换到末尾
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)               # 堆大小变成 end
    return a


print("排序结果:", heap_sort([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
建堆完成: [9, 7, 6, 1, 2, 5, 3]
排序结果: [1, 2, 3, 5, 6, 7, 9]
```

**建堆完成后的 `[9, 7, 6, 1, 2, 5, 3]` 画出树是这样**（正好是第 5 篇的"大顶堆"）：

```text
            9
          /   \
         7     6
        / \   / \
       1   2 5   3
```

每个父节点都不小于自己的孩子 ⇒ 堆顶 9 是最大值。把 9 和末尾的 3 交换，9 就永久落到了最后一格；剩下 6 个元素重新下沉恢复堆 ⇒ 再取 7……**n-1 轮之后数组就有序了。**

#### 复杂度与稳定性

| 项 | 值 | 说明 |
| --- | --- | --- |
| 建堆 | **O(n)** | 不是 O(n log n)！这是高频考点 |
| 排序阶段 | O(n log n) | n-1 次"换堆顶 + 下沉"，每次 O(log n) |
| 总计 最好/最坏/平均 | **都是 O(n log n)** | 与数据无关 |
| 空间 | **O(1)** | 原地，不借数组 |
| 稳定性 | **不稳定** ✗ | 堆顶和末尾是远距离交换 |

**"建堆为什么是 O(n)"**：越靠下的结点下沉得越少，把所有结点的下沉代价加起来是 n/4·1 + n/8·2 + … < n，是个收敛的等比级数 ⇒ O(n)。**结论记住就行，考试只考结论**。

**堆排的定位**：**唯一"最坏 O(n log n) + 空间 O(1)"的算法**。要稳定性选归并，要省内存 + 保最坏选堆排。缺点是常数大、缓存不友好，实际跑不过快排。

### 三巨头横向对比

| | 快速排序 | 归并排序 | 堆排序 |
| --- | --- | --- | --- |
| 平均 | O(n log n) | O(n log n) | O(n log n) |
| **最坏** | **O(n²)** | O(n log n) | O(n log n) |
| 空间 | O(log n)（栈） | **O(n)** | **O(1)** |
| 稳定性 | 不稳定 | **稳定** ✓ | 不稳定 |
| 实际速度 | **通常最快** | 中等 | 偏慢（常数大） |
| 适用场景 | 内存里的通用排序 | 要求稳定 / 外部排序 / 链表 | 内存紧张 / 要求最坏可控 |

## 四、非比较排序：不比大小，靠"分配"

到这里为止，所有算法干的都是同一件事——**比较两个元素谁大**。而比较排序有个**理论天花板：O(n log n)**（第 7 篇的判定树：n 个元素有 n! 种排列，判定树要有 n! 个叶子，高度至少 log₂(n!) ≈ n log n）。

想突破它，就得**不比大小**，改用数据本身的**取值信息**直接"算"出位置——这就是非比较排序。

### 4.1 计数排序：数一数每个值出现了几次

**思想**：给值域里每个整数配一个"计数器"，扫一遍把次数数出来，再按值从小到大倒出来。

```python
def counting_sort(a):
    lo, hi = min(a), max(a)
    count = [0] * (hi - lo + 1)      # 值 x 的计数器放在下标 x - lo
    for x in a:
        count[x - lo] += 1
    res = []
    for i, c in enumerate(count):
        res.extend([i + lo] * c)     # 出现 c 次就放 c 个
    return count, res


data = [4, 2, 2, 8, 3, 3, 1]
count, res = counting_sort(data)
print("原始:", data, "| 最小值", min(data), "最大值", max(data))
print("count 桶:", count)
print("结果:", res)
```

输出：

```text
原始: [4, 2, 2, 8, 3, 3, 1] | 最小值 1 最大值 8
count 桶: [1, 2, 2, 1, 0, 0, 0, 1]
结果: [1, 2, 2, 3, 3, 4, 8]
```

**对着 `count` 桶读一遍**：

| 下标（= 值减 1） | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 对应值 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| 出现次数 | 1 | **2** | **2** | 1 | 0 | 0 | 0 | 1 |

2 出现 2 次、3 出现 2 次、5/6/7 一次都没出现（计数器是 0）⇒ 按顺序倒出来就是 `[1, 2, 2, 3, 3, 4, 8]`。**全程没有比较过任何两个元素的大小。**

| 项 | 值 | 说明 |
| --- | --- | --- |
| 时间 | **O(n + k)** | k 是值域大小（`hi - lo + 1`） |
| 空间 | **O(k)** | 桶数组 |
| 稳定性 | **稳定** ✓ | 标准做法是"求前缀和 + 从后往前填"，能保持原次序 |

**限制（考试爱问"为什么不用计数排序"）**：

- **只能排整数**（或能一一映射成下标的离散值）
- **值域不能太大**：n = 100 但值域 0 ~ 10⁹，要开 10 亿个桶，内存直接爆
- k ≫ n 时，O(n+k) 反而比 O(n log n) 慢

### 4.2 基数排序：按个位、十位、百位依次分桶

**思想**：从**最低位**开始，按这一位把数分进 10 个桶，再**按桶 0 → 9 的顺序收集回来**；然后上升一位（十位、百位…）重复，直到最高位。**全程不比较大小，只做"分配 + 收集"。**

```python
nums = [170, 45, 75, 90, 802, 24, 2, 66]
out = nums[:]
exp = 1                  # exp = 1 表示个位，10 表示十位，100 表示百位
round_ = 1
while max(out) // exp > 0:                  # 最高位处理完就停
    buckets = [[] for _ in range(10)]       # 10 个桶
    for x in out:
        buckets[(x // exp) % 10].append(x)  # 按当前位分桶
    out = [x for b in buckets for x in b]   # 按桶 0..9 收集
    print(f"第 {round_} 轮（按 {exp} 位）:", out)
    exp *= 10
    round_ += 1
print("排好:", out)
```

输出：

```text
第 1 轮（按 1 位）: [170, 90, 802, 2, 24, 45, 75, 66]
第 2 轮（按 10 位）: [802, 2, 24, 45, 66, 170, 75, 90]
第 3 轮（按 100 位）: [2, 24, 45, 66, 75, 90, 170, 802]
排好: [2, 24, 45, 66, 75, 90, 170, 802]
```

**逐轮看**：

| 轮次 | 看哪一位 | 结果的关键性质 |
| --- | --- | --- |
| 第 1 轮 | 个位 | 按个位有序 |
| 第 2 轮 | 十位 | **十位有序；十位相同的一组内部，仍按个位有序** |
| 第 3 轮 | 百位 | **百位有序；百位相同的一组内部，仍按十位、个位有序 ⇒ 全有序** |

**为什么第 2 轮结束时"十位有序、内部个位也有序"？** 因为第 1 轮已经按个位排好了，第 2 轮分桶时**每个桶内部的相对顺序没变**（收集是稳定的）。这就是基数排序必须**稳定**的原因——**每一轮都依赖上一轮的顺序**。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 时间 | **O(d × (n + r))** | d = 最大位数，r = 基数（十进制 r = 10） |
| 空间 | O(n + r) | 桶要存 n 个元素 |
| 稳定性 | **稳定** ✓ | 每轮"分配 + 收集"必须稳定，否则前一轮白排 |
| 限制 | 整数 / 定长字符串 | 位数太多时 d 变大，优势消失 |

### 4.3 桶排序（知道思想就行）

把值域平均切成若干个**区间（桶）**，元素按大小扔进对应桶，**每个桶内部单独排序**，最后按桶的顺序拼起来。

- 数据**均匀分布**时，每个桶里只有常数个元素 ⇒ **平均 O(n)**
- 数据**全挤在一个桶**里 ⇒ 退化成对 n 个元素做一次普通排序 ⇒ **最坏 O(n²)**
- 教材常考的一句话：**计数排序是桶排序的特例**（每个桶只装一个值）

## 五、八大排序总表：考场上默写这张

**这一节是整篇里最值钱的部分**，选择题、填空题、大题第 1 问基本都在考它。

> **读表说明**：前 8 行（名字加粗）就是教材口径的**八大排序**；最后两行（计数、桶）是非比较排序，属于"知道更好"的补充。基数排序是非比较排序，但因为它太常和八大排序一起考，也加粗了。

| 排序方法 | 平均 | 最好 | 最坏 | 空间 | 稳定性 | 一句话 |
| --- | --- | --- | --- | --- | --- | --- |
| **直接插入** | O(n²) | **O(n)** | O(n²) | O(1) | **稳定** ✓ | 基本有序时最快 |
| **希尔** | O(n^1.3) | — | O(n²) | O(1) | 不稳定 ✗ | 增量最后要收尾到 1 |
| **冒泡** | O(n²) | **O(n)** | O(n²) | O(1) | **稳定** ✓ | 能提前退出 |
| **快速** | O(n log n) | O(n log n) | **O(n²)** | O(log n) | 不稳定 ✗ | 实际最快，已有序会退化成 n² |
| **简单选择** | O(n²) | **O(n²)** | O(n²) | O(1) | 不稳定 ✗ | 交换次数最少（≤ n-1） |
| **堆** | O(n log n) | O(n log n) | **O(n log n)** | **O(1)** | 不稳定 ✗ | 唯一"最坏 n log n + 空间 O(1)" |
| **归并** | O(n log n) | O(n log n) | **O(n log n)** | **O(n)** | **稳定** ✓ | 外部排序靠它 |
| **基数** | O(d(n+r)) | 同左 | 同左 | O(n+r) | **稳定** ✓ | 不比较，按位分桶；必须稳定 |
| 计数 | O(n+k) | O(n+k) | O(n+k) | O(k) | 稳定 ✓ | 值域小才行 |
| 桶 | O(n) | O(n) | O(n²) | O(n+k) | 稳定 ✓ | 数据得均匀 |

### 五条分组记忆（比死背表格快）

| 问题 | 答案 | 口诀 |
| --- | --- | --- |
| 哪些**稳定**？ | 冒泡、插入、归并、计数、基数、桶 | **「冒插归，计基桶」** |
| 哪些**不稳定**？ | 选择、希尔、快速、堆 | **「选希快堆」** |
| 最坏也是 **O(n log n)** 的？ | **只有归并和堆** | 「归堆最稳」 |
| 空间 **O(1)** 的？ | 冒泡、选择、插入、希尔、堆 | 数组里自己换 |
| 复杂度与初始状态**无关**的？ | 选择、归并、堆、计数、基数 | 「选归堆，计基无关」 |

### 六个最容易记错的点

| 说法 | 对不对 | 正确版本 |
| --- | --- | --- |
| 选择排序最好情况是 O(n) | ❌ | **最好、最坏、平均全是 O(n²)** |
| 快速排序最坏是 O(n log n) | ❌ | **最坏 O(n²)**，而且递归深度 O(n) |
| 归并排序是原地排序 | ❌ | 需要 **O(n)** 辅助数组 |
| 堆排序的建堆是 O(n log n) | ❌ | **建堆 O(n)**，排序阶段才是 O(n log n) |
| 希尔排序是稳定的 | ❌ | **不稳定**（跨间隔移动） |
| 基数排序不用管稳定性 | ❌ | **必须稳定**，否则前一轮白排 |

## 六、怎么选：题目给场景，你报算法

考试最后常常来一句"**针对下列场景，选择最合适的排序算法并说明理由**"。思路就一条：**先看约束，再看数据特征**。

| 场景 | 选谁 | 理由（答题直接抄） |
| --- | --- | --- |
| 数据量很小（n < 50） | **直接插入** | 常数因子小，代码简单，实际比快排还快 |
| 数据**基本有序** | **插入 / 冒泡** | 接近 O(n)，冒泡可提前退出 |
| 要求**稳定** | **归并 / 插入** | 快排、堆排、选择都不稳定 |
| **内存紧张**，不能开 O(n) 辅助空间 | **堆排序** | 最坏 O(n log n)，空间 O(1) |
| 通用场景、追求实际速度 | **快速排序** | 平均常数最小（工程上常用"内省排序"） |
| 数据存在**链表**里 | **归并排序** | 链表归并不需要额外数组，快排不好随机访问 |
| 数据在**磁盘**上、内存放不下 | **多路归并** | 外部排序的标准做法 |
| **整数且值域很小** | **计数排序** | O(n+k)，线性时间 |
| 大量**重复元素** | **三路快排** | 相等的元素一趟就全部就位，不再递归 |

**答题模板**（一句话公式）：

> 选 **X 排序**。因为题目的约束是【稳定 / 省空间 / 数据基本有序 / 数据量大】，而 X 的【复杂度 / 空间 / 稳定性】正好满足，且比 Y 更合适（Y 的短板是……）。

### Python 里到底用什么

Python 的 `list.sort()` 和 `sorted()` 用的是 **Timsort**（归并 + 插入的混合体），它的三个特点：

- **稳定**（归并带来的）
- **最坏 O(n log n)**（不会像快排掉到 n²）
- 数据**基本有序**时接近 **O(n)**（识别出已有的有序段，直接拼）

```python
rows = [(90, "张"), (85, "李"), (90, "王")]

print(sorted(rows, key=lambda r: r[1]))            # 按名字
print(sorted(rows, key=lambda r: -r[0]))           # 分数降序
print(sorted(rows, key=lambda r: (-r[0], r[1])))   # 分数降序，同分按名字
print(sorted(rows, key=lambda r: r[0]))            # 分数升序（稳定：同分保持原次序）

nums = [5, 2, 9, 1]
print(sorted(nums, reverse=True))
print(nums.sort())                                 # 原地排序，返回 None
```

输出：

```text
[(90, '张'), (85, '李'), (90, '王')]
[(90, '张'), (90, '王'), (85, '李')]
[(90, '张'), (90, '王'), (85, '李')]
[(85, '李'), (90, '张'), (90, '王')]
[9, 5, 2, 1]
None
```

**读最后两行**：

- 第 4 行 `sorted(..., key=lambda r: r[0])`：85 分的最前，两个 90 分**保持原来的「张、王」次序**——这就是 Timsort 稳定的直接体现
- 最后一行 `nums.sort()` 打印 `None`：**`list.sort()` 是原地排序、没有返回值**，写 `nums = nums.sort()` 会把列表变成 `None`（第 2 篇踩过这个坑）

**多关键字排序的正确写法是 `key=lambda r: (-r[0], r[1])`**：把主要关键字、次要关键字按优先级放进一个元组，Python 会按元组逐位比较。**不要**写成两次 `sorted` 还指望结果对——虽然稳定排序确实支持两趟，但一步到位更不容易错。

## 七、常见错误

这一节的每个 ❌ 都是真实跑出来的现象，不是"应该会错"。

### 错误 1：冒泡内层范围写成 `range(n)` —— 越界

```python
# ❌ 错：内层应该只到 n-1-i
data = [5, 2, 9]
for j in range(len(data)):          # j 会走到最后一个下标
    if data[j] > data[j + 1]:       # data[j+1] 越界
        data[j], data[j + 1] = data[j + 1], data[j]
```

运行结果：

```text
IndexError: list index out of range
```

**记法**：`a[j]` 要和 `a[j+1]` 比，那 `j` 最大只能到 `n-2`，所以 `range` 的终点写 `n-1`（Python 的 `range` 右端不含）。

### 错误 2：选择排序在内层就交换 —— 结果对，但白忙

```python
# ❌ 错：选择排序应该"记下标、最后换一次"
def selection_inner_swap(a):
    a = a[:]
    n = len(a)
    swaps = 0
    for i in range(n - 1):
        for j in range(i + 1, n):
            if a[j] < a[i]:                 # 一发现更小就换
                a[i], a[j] = a[j], a[i]
                swaps += 1
    return a, swaps


res, sw = selection_inner_swap([5, 2, 9, 1, 7, 6, 3])
print("结果:", res, "交换次数:", sw)
```

得到的结果和交换次数：

```text
结果: [1, 2, 3, 5, 6, 7, 9] 交换次数: 11
```

**排序结果没错，但交换次数从 3 次变成了 11 次**——"选择排序交换最少（≤ n-1）"这个唯一的优点直接没了。正确写法是先扫完记住最小值下标 `m`，一轮只换一次。

### 错误 3：插入排序漏了 `j >= 0` —— 不会报错，但数组被改烂

这是 Python 特有的坑：**负下标不报错，而是从末尾倒着数**。

```python
a = [5, 2, 9]
print("a[-1] =", a[-1], "| a[-2] =", a[-2])
```

输出：

```text
a[-1] = 9 | a[-2] = 2
```

于是这段错误代码不会崩，而是**一直拿数组末尾的元素在比较**，把数组改得面目全非：

```python
# ❌ 错：while 少了 j >= 0
def broken_insertion(a, guard=12):
    a = a[:]
    steps = 0
    for i in range(1, len(a)):
        cur = a[i]
        j = i - 1
        while a[j] > cur:          # j 变成 -1、-2… 时依然"合法"
            a[j + 1] = a[j]
            j -= 1
            steps += 1
            if steps > guard:      # 人为截断，否则真的停不下来
                return f"转了 {steps} 次还没停，数组已成 {a}"
        a[j + 1] = cur
    return a


print(broken_insertion([5, 2, 9, 1, 7, 6, 3]))
```

输出：

```text
转了 13 次还没停，数组已成 [6, 3, 3, 5, 9, 2, 7]
```

**原数组 `[5, 2, 9, 1, 7, 6, 3]` 被改成了 `[6, 3, 3, 5, 9, 2, 7]`，而且根本停不下来。** 对比 C 语言：C 里 `a[-1]` 是野指针，多半直接段错误；Python 帮你想"友好"了，反而更难查。**`while` 的两个条件，宁可多写一个也不能少。**

### 错误 4：快排递归写成 `q(low, p)` —— 栈溢出

```python
# ❌ 错：右边界应该传 p - 1
def broken_quick(a):
    a = a[:]

    def q(low, high):
        if low >= high:
            return
        pivot, i = a[high], low
        for j in range(low, high):
            if a[j] < pivot:
                a[i], a[j] = a[j], a[i]
                i += 1
        a[i], a[high] = a[high], a[i]
        q(low, i)          # 区间没缩小：i 可能等于 high
        q(i + 1, high)

    q(0, len(a) - 1)
    return a


try:
    broken_quick([5, 2, 9, 1])
except RecursionError:
    print("RecursionError: maximum recursion depth exceeded")
```

运行结果：

```text
RecursionError: maximum recursion depth exceeded
```

**划分函数返回的 `p` 位置的元素已经在最终位置上了**，所以左右两段是 `[low, p-1]` 和 `[p+1, high]`。写成 `q(low, p)` 时区间可能没变小（`p == high`），递归永远停不下来。

### 错误 5：归并 `merge` 用 `<` —— 稳定性当场丢失

```python
# ❌ 错：相等时先取了右边
def merge_lt(left, right):
    res, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i][0] < right[j][0]:
            res.append(left[i]); i += 1
        else:
            res.append(right[j]); j += 1
    res.extend(left[i:])
    res.extend(right[j:])
    return res

print("用 < :", merge_lt([(5, "a"), (9, "b")], [(5, "c"), (7, "d")]))
```

输出：

```text
用 < : [(5, 'c'), (5, 'a'), (7, 'd'), (9, 'b')]
```

`5a` 在左半边、`5c` 在右半边，**它们相等时如果先取右边，`5c` 就跑到 `5a` 前面去了**。改成 `<=`（相等先取左边）立刻恢复稳定：

```text
改成 <= : [(5, 'a'), (5, 'c'), (7, 'd'), (9, 'b')]
```

**一句话**：归并的稳定性全押在这一个等号上。

### 错误 6：堆排序"从上往下"建堆 —— 建出来的不是堆

建堆必须**从最后一个非叶子结点（`n//2 - 1`）往 0 倒着走**，因为下沉需要"孩子的孩子已经满足堆"。从上往下（`range(0, n//2)`）会让已经调整好的下面重新被打乱：

```python
# ❌ 错：从 0 往 n//2 走
def build_top_down(a):
    a = a[:]
    n = len(a)
    for i in range(0, n // 2):      # 方向反了
        sift_down(a, i, n)
    return a

w = build_top_down([1, 2, 3, 4, 5, 6, 7])
print("建堆后:", w)
print("根的值:", w[0], "| 两个孩子:", w[1], w[2])
```

输出：

```text
建堆后: [3, 5, 7, 4, 2, 6, 1]
根的值: 3 | 两个孩子: 5 7
```

**根 3 比它的孩子 5、7 都小，这根本不是大顶堆。** 之后拿它去排序，结果就是错的。正确方向跑出来是 `[7, 5, 6, 4, 2, 1, 3]`（根 7 最大）。

### 错误 7：`nums = nums.sort()` —— 列表变 None

```python
# ❌ 错：list.sort() 原地排序，返回 None
nums = [3, 1, 2]
nums = nums.sort()
print(nums)
```

输出：

```text
None
```

`list.sort()` 是**原地排序，返回值是 `None`**。要返回值用 `sorted(nums)`，要原地排序就单独一行写 `nums.sort()`，**别接返回值**。

### 错误 8：函数里忘拷贝，把调用者的列表改掉了

```python
# ❌ 错：以为 a = a 是拷贝
def sort_wrong(a):
    a.sort()               # 直接排了传进来的那个列表
    return a


d = [5, 2, 9]
print("返回值:", sort_wrong(d))
print("调用者的 d 变成:", d)
```

输出：

```text
返回值: [2, 5, 9]
调用者的 d 变成: [2, 5, 9]
```

**列表是可变对象，函数参数传的是引用。** 本文所有排序函数第一行都写 `a = a[:]`（或 `a[:]` 的等价写法），就是为了不污染调用者的数据。如果想让函数原地排序，那就干脆不返回列表，**两件事别混着做**。

### 错误 9：`key=` 后面忘了写 `lambda`

```python
# ❌ 错：key 要一个函数，不是元素
rows = [(90, "张"), (85, "李")]
try:
    print(sorted(rows, key=rows[0]))
except TypeError as e:
    print("TypeError:", e)
```

输出：

```text
TypeError: 'tuple' object is not callable
```

`key` 要的是**"给一个元素、返回排序依据"的函数**，`rows[0]` 是 `(90, '张')` 这个元组，不可调用。正确写法 `key=lambda r: r[0]`（或 `key=lambda r: (-r[0], r[1])` 做多关键字）。

### 错误 10：计数排序忘了减 `lo` —— 负数下标悄悄绕到末尾

```python
# ❌ 错：count 下标应该是 x - lo
a = [-2, 3, 1]
count = [0] * 6
for x in a:
    count[x] += 1          # -2 → count[-2]，绕到了倒数第二格
print("错误 count:", count)
```

输出：

```text
错误 count: [0, 1, 0, 1, 1, 0]
```

`-2` 被记到了**下标 4**（6 + (-2)），正确应该是下标 0：

```text
正确 count: [1, 0, 0, 1, 0, 1]
```

**计数排序有负数时，桶下标必须是 `x - min(a)`**；数组下标没法表示负数，Python 又不报错，这类 bug 极难查。

## 八、考题演练

### 考题 1：写出**第一趟**排序结果（超高频，必考）

> 数据 `[49, 38, 65, 97, 76, 13, 27, 49]`，写出**第一趟冒泡排序**和**第一趟快速排序**（以第一个元素为枢轴）之后的结果。

#### 第一趟冒泡

```python
a = [49, 38, 65, 97, 76, 13, 27, 49]
b = a[:]
for j in range(len(b) - 1):          # 只跑一趟：从 0 扫到 n-2
    if b[j] > b[j + 1]:
        b[j], b[j + 1] = b[j + 1], b[j]
print("第一趟冒泡后:", b)
```

输出：

```text
第一趟冒泡后: [38, 49, 65, 76, 13, 27, 49, 97]
```

**手写过程就在卷子上这么写**：

```text
初始：49  38  65  97  76  13  27  49
(49,38) 换 → 38  49  65  97  76  13  27  49
(49,65) 不换
(65,97) 不换
(97,76) 换 → 38  49  65  76  97  13  27  49
(97,13) 换 → 38  49  65  76  13  97  27  49
(97,27) 换 → 38  49  65  76  13  27  97  49
(97,49) 换 → 38  49  65  76  13  27  49  97
第一趟结果：38  49  65  76  13  27  49  [97]   ← 97 到位
```

**评分点**：① 共比较 n-1 = 7 次；② 最终 97 落到最后一格；③ 前面的相对次序不变。

#### 第一趟快速排序

教材里"第一趟快排"通常指**以第一个元素为枢轴、用挖坑法（双指针）划分一趟**：

```python
def partition_first(a, low, high):
    pivot = a[low]                     # 教材习惯：拿第一个元素当枢轴
    while low < high:
        while low < high and a[high] >= pivot:   # 从右往左找比 pivot 小的
            high -= 1
        a[low] = a[high]               # 填到左边的坑里
        while low < high and a[low] <= pivot:    # 从左往右找比 pivot 大的
            low += 1
        a[high] = a[low]               # 填到右边的坑里
    a[low] = pivot                     # 枢轴归位
    return low


c = [49, 38, 65, 97, 76, 13, 27, 49]
p = partition_first(c, 0, len(c) - 1)
print("一趟划分后:", c)
print("枢轴 49 落在下标", p)
```

输出：

```text
一趟划分后: [27, 38, 13, 49, 76, 97, 65, 49]
枢轴 49 落在下标 3
```

**关键结论（写答案时必须点出来）**：

```text
[27, 38, 13]  49  [76, 97, 65, 49]
 └─左半全部 ≤ 49─┘    └─右半全部 ≥ 49─┘
```

- 枢轴 49 已经落在**最终位置**（下标 3），后面再也不会动它
- 左半 `[27, 38, 13]`、右半 `[76, 97, 65, 49]` 内部**都还没排好**，只保证"整体比 49 小/大"
- 右半里还有个 49，和枢轴相等——放在左右哪边都算对，**但要和题目约定的写法一致**（本题代码是"小于等于留在右边"）

### 考题 2：稳定性 + 多关键字排序

> 学生表 `(学号, 姓名, 分数)` 如下，要求**按分数降序排，分数相同的按学号升序排**。写出结果，并说明为什么必须用稳定排序。

```python
students = [(1002, "李", 88), (1001, "张", 92), (1003, "王", 92), (1004, "赵", 88)]

res = sorted(students, key=lambda s: (-s[2], s[0]))
for s in res:
    print(s)
```

输出：

```text
(1001, '张', 92)
(1003, '王', 92)
(1002, '李', 88)
(1004, '赵', 88)
```

**另一种写法（两趟稳定排序，考试也认）**：

```python
students = [(1002, "李", 88), (1001, "张", 92), (1003, "王", 92), (1004, "赵", 88)]

step1 = sorted(students, key=lambda s: s[0])    # 第一趟：按次要关键字（学号）升序
step2 = sorted(step1, key=lambda s: -s[2])      # 第二趟：按主要关键字（分数）降序
for s in step2:
    print(s)
```

输出：

```text
(1001, '张', 92)
(1003, '王', 92)
(1002, '李', 88)
(1004, '赵', 88)
```

**为什么必须稳定**：第二趟只按分数排，两个 92 分的人谁前谁后，**完全取决于第一趟排好的学号次序**。如果第二趟用的是不稳定排序（比如快排、堆排），92 分那两个人的先后就变成随机的，第一趟白排。**所以多关键字排序的正确套路是：从次要关键字排到主要关键字，每一趟都用稳定排序。**

### 考题 3：场景选算法 + 数量级估算

> （1）n = 1000 个无序整数，内存充足，要求通用、快，选什么？
> （2）同样数据，要求排序后相同元素的相对次序不变，选什么？
> （3）数据有 1 亿条存在磁盘上，内存装不下，怎么办？

**（1）快速排序**：平均 O(n log n)、常数最小，是通用场景的首选（工程上用内省排序，快排 + 堆排 + 插入的混合）。

**（2）归并排序**：它是 O(n log n) 里唯一**稳定 + 最坏也是 n log n** 的算法，代价是 O(n) 额外空间。

**（3）外部排序（多路归并）**：先把大文件切成能放进内存的段，每段排好写回磁盘，再做多路归并。

**顺带算一下数量级**（大题爱让你填这个数）：

```python
import math

n = 1000
print("冒泡最坏比较次数 n(n-1)/2 =", n * (n - 1) // 2)
print("归并大约 n·log₂n        =", int(n * math.log2(n)))
```

输出：

```text
冒泡最坏比较次数 n(n-1)/2 = 499500
归并大约 n·log₂n        = 9965
```

**50 倍**，这就是 O(n²) 和 O(n log n) 在 n = 1000 时的真实差距。

### 手工模拟题的满分格式（三步）

**第一步：抄题，标出"这一趟要干什么"**

```text
第 1 趟冒泡：从 a[0] 到 a[n-2] 相邻比较，大的往后换
```

**第二步：逐个写出比较结果，用 `[ ]` 标出已经到位的元素**

```text
初始：49  38  65  97  76  13  27  49
(49,38) 换 → 38  49  65  97  76  13  27  49
(49,65) 不换
(65,97) 不换
(97,76) 换 → 38  49  65  76  97  13  27  49
(97,13) 换 → 38  49  65  76  13  97  27  49
(97,27) 换 → 38  49  65  76  13  27  97  49
(97,49) 换 → 38  49  65  76  13  27  49  97
结果：38  49  65  76  13  27  49  [97]
```

**第三步：一句话点出性质**

```text
本趟共比较 7 次、交换 5 次；最大值 97 已到最终位置；其余元素相对次序不变（冒泡稳定）。
```

**有这三步，就算中间某一格算错，过程分也能拿到大半。** 只写最后一行结果的，老师最多给 1 分。

### 稳定性判断题的答题模板

题目："快速排序是否稳定？请说明理由。"

> **不稳定。** 反例：序列 `(5a, 5b, 2)`，第一趟划分时把最小的 2 换到最前面，`5a` 被越过了 `5b`，排完变成 `(2, 5b, 5a)`，相等元素的相对次序发生改变。

**三句话就够**：给结论 → 给反例 → 指出"为什么"（远距离交换 / 相等时也换）。

## 十、小结：这一篇必须带走的东西

### 一屏速查（考前 5 分钟看这个）

```text
稳定：冒泡、插入、归并、计数、基数、桶      → 「冒插归，计基桶」
不稳定：选择、希尔、快速、堆                → 「选希快堆」
最坏也是 n log n：归并、堆
空间 O(1)：冒泡、选择、插入、希尔、堆
最好 O(n)：冒泡、插入（数据基本有序时）
最好也是 O(n²)：选择（它不看数据长什么样）
建堆 O(n)，排序阶段 O(n log n)
快排最坏 O(n²)：pivot 每次都取到端点（已有序 + 固定取首/尾）
归并稳定的关键：merge 里写 <=
```

### 八个算法各一句话

| 算法 | 一句话记住它 |
| --- | --- |
| 冒泡 | 相邻比较，每趟钉一个最大值到末尾 |
| 选择 | 每轮挑最小，**交换最少但不稳定** |
| 插入 | 整理扑克牌，**基本有序时最快** |
| 希尔 | 插入排序加"大步长"，**不稳定** |
| 快速 | 选枢轴划分，**平均最快、最坏 n²** |
| 归并 | 分到 1 个再合并，**稳定 + 最坏 n log n + 费 O(n) 空间** |
| 堆 | 大顶堆反复取堆顶，**原地 + 最坏 n log n** |
| 基数 | 按位分桶收集，**不比较、必须稳定** |
