# 第 6 篇：图——从"一对多"到"多对多"

上一篇的树有一条铁律：**每个节点只能有一个爹**。砍掉这条约束，就得到这一篇的主角——**图**。

图有多自由？A 可以连 B，B 可以连 C，C 还能连回 A（转一圈回来）。地铁线路图、微信好友关系、高德地图的路线、课程之间的先修关系……**现实世界里"多对多"的关系，全都得用图来存**。

这一篇的好消息是：**你已经在第 3 篇和第 5 篇练过图的两大武器了**——DFS 就是树的"前序"推广，BFS 就是"层序"推广，一个用递归/栈，一个用队列。**唯一的差别是：图里可能有环，所以你必须"记下来走过哪儿"。**

需要先会：第 3 篇的栈与队列、第 5 篇的递归和二叉树遍历。

---

## 一、图是什么

### 两个基本元素

```text
        A ————— B           顶点（vertex / 结点）：A、B、C、D
        │       │           边（edge）：A—B、A—C、B—D、C—D
        │       │
        C ————— D
```

- **顶点（vertex）**：图里的"点"，比如一座车站、一个人、一门课。
- **边（edge）**：连接两个顶点的"线"，比如两站之间的一段地铁、两个人是好友。

**就这么两个东西。** 树是"边有方向（向下）、且没有环"的特殊图；图则什么都可以。

### 有向图 vs 无向图

| | 无向图 | 有向图 |
| --- | --- | --- |
| 边的形式 | `(A, B)`，没有箭头 | `<A, B>`，有箭头（A → B） |
| 含义 | 互相的、对称的关系 | 单向的关系 |
| 例子 | 微信好友（互为好友）、两站间的地铁 | 微博关注（他关注你不代表你关注他）、单行道、课程先修 |
| 边数上限 | `n(n-1)/2` | `n(n-1)` |

**注意这里**：无向图里 `(A, B)` 和 `(B, A)` 是**同一条边**；有向图里 `<A, B>` 和 `<B, A>` 是**两条不同的边**。这一条决定了后面建邻接表时"加一条边要写几行代码"——**无向图要两头都加，有向图只加一头**。

### 带权图（网）

边上再挂一个数字，就有了"距离""花费""时间"：

```text
        A ——4—— B
        │       │
        1       5
        │       │
        C ——8—— D
```

这个数字叫**权（weight）**，带权的图叫**带权图**，也叫**网**。**高德地图算最短路线，算的就是带权图里的"权和最小"**——不是边数最少。

### 必须认脸的术语

| 术语 | 含义 |
| --- | --- |
| **度（degree）** | 无向图里，一个顶点连着几条边 |
| **入度 / 出度** | 有向图里，指向它的边数 / 从它出发的边数 |
| **路径** | 从一个顶点走到另一个顶点经过的顶点序列 |
| **回路（环）** | 起点和终点是同一个顶点的路径 |
| **简单路径** | 顶点不重复的路径 |
| **连通** | 无向图里，任意两个顶点之间都有路径 |
| **连通分量** | 无向图里的一个"连成一片"的部分（极大连通子图） |
| **强连通** | 有向图里，任意两个顶点**互相**都能到达 |
| **完全图** | 任意两个顶点之间都有一条边（边数达到上限） |
| **子图** | 从原图里挑一些顶点和边出来组成的图 |
| **生成树** | 连通图的生成树：包含**全部 n 个顶点**、只有 **n-1 条边**、且连通的子图 |

**这张表里最常考的是最后两个**：完全图的边数、生成树的边数。

### 三个必背数字

```text
① 无向完全图：n(n-1)/2 条边         （4 个顶点 → 6 条边）
② 有向完全图：n(n-1) 条边           （4 个顶点 → 12 条边）
③ 生成树：n 个顶点，n-1 条边
```

为什么无向完全图是 `n(n-1)/2`？**每个顶点都要和其余 n-1 个顶点相连，一共 n(n-1) 次，但每条边被数了两遍（A 数 B 一次、B 数 A 一次），所以除以 2。**

**顺便记住两条"度数"性质**（考题经常让你验证）：

```text
无向图：所有顶点的度之和 = 2 × 边数        （每条边给两个端点各贡献 1 个度）
有向图：所有顶点的入度之和 = 出度之和 = 边数
```

**为什么无向图要乘 2？** 和上面完全图的推导是同一个道理：**一条边连两个点，两个点的度都 +1**。**这条性质的条件反射式用法**：题目说"一个无向图有 10 条边，每个顶点的度都是 2"，你立刻知道有 10 个顶点（度之和 = 20 = 2×10，顶点数 = 20/2）。

### 树是图，图不一定是树

```text
树：连通、无环、n-1 条边        图：随便，可以有环、可以不连通
```

**树的三条"必须"正好是图的三条"随便"**。所以考试里"n 个顶点 n-1 条边的连通图" = 树，这个等价关系一定要记住（**只要是连通图，n-1 条边就必然是树；多一条边必出环**）。

## 二、两种存储方式：邻接矩阵 vs 邻接表

图和链表不一样：链表的节点自带 `next`，图的顶点**不知道自己和谁相连**，你得单独准备一张"关系表"。两种最常用的表，就是考试必考的**邻接矩阵**和**邻接表**。

本篇统一用这张 6 个顶点的无向图做例子：

```text
        A ————— B
        │       │
        │       │
        C ————— D ————— E ————— F
```

也就是这些边：`A-B`、`A-C`、`B-D`、`C-D`、`D-E`、`E-F`。**一共 6 个顶点、6 条边。**

### 邻接表：每个顶点挂一串邻居

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C", "E"],
    "E": ["D", "F"],
    "F": ["E"],
}

for u in graph:
    print(u, "->", graph[u])
```

输出：

```text
A -> ['B', 'C']
B -> ['A', 'D']
C -> ['A', 'D']
D -> ['B', 'C', 'E']
E -> ['D', 'F']
F -> ['E']
```

**这就是"邻接表"**：一个字典，键是顶点，值是"和它直接相连的顶点列表"。**它长得就像链表数组**——每个顶点挂着一条小链表。

**注意这里**：无向图里 `A-B` 这条边，**在 A 的列表里记了一次，在 B 的列表里又记了一次**。所以"无向图加一条边"要写两行：

```python
g2 = {"A": [], "B": []}
u, v = "A", "B"

g2[u].append(v)
g2[v].append(u)      # 无向图必须补这一行；有向图不写

print(g2)
```

输出：

```text
{'A': ['B'], 'B': ['A']}
```

**有向图只加一头**（`graph[u].append(v)`），因为 `<A, B>` 只表示 A 能到 B，不表示 B 能到 A。

**带权图**怎么办？把邻居换成 `(邻居, 权值)` 就行：

```python
weighted = {
    "A": [("B", 4), ("C", 1)],
    "B": [("D", 1)],
    "C": [("B", 2), ("D", 5)],
    "D": [("E", 3)],
    "E": [],
}
```

后面讲 Dijkstra 和 Prim 时就用这个格式。

### 邻接矩阵：一张 n×n 的表格

行和列都是顶点，`matrix[i][j] = 1` 表示 i 和 j 之间有边，`0` 表示没有。

```python
nodes = list(graph)                        # ['A', 'B', 'C', 'D', 'E', 'F']
idx = {u: i for i, u in enumerate(nodes)}  # 顶点 -> 下标
n = len(nodes)

matrix = [[0] * n for _ in range(n)]       # 注意：不能写成 [[0]*n]*n
for u in graph:
    for v in graph[u]:
        matrix[idx[u]][idx[v]] = 1

print("    " + " ".join(nodes))
for u in nodes:
    print(u + "   " + " ".join(str(x) for x in matrix[idx[u]]))

print("A 和 D 之间有边吗：", matrix[idx["A"]][idx["D"]] == 1)
print("A 的度：", sum(matrix[idx["A"]]))
```

输出：

```text
    A B C D E F
A   0 1 1 0 0 0
B   1 0 0 1 0 0
C   1 0 0 1 0 0
D   0 1 1 0 1 0
E   0 0 0 1 0 1
F   0 0 0 0 1 0
A 和 D 之间有边吗： False
A 的度： 2
```

**看这张表，有几件事一眼就能看出来**：

1. **它是对称的**（`matrix[i][j] == matrix[j][i]`）——因为是无向图。**有向图的邻接矩阵不对称。**
2. **某一行的 1 的个数 = 该顶点的度**（`sum(matrix[i])`）。所以 `A` 的度是 2。
3. **有向图的话**：第 i 行的和 = i 的**出度**，第 j 列的和 = j 的**入度**。**这两个经常被问反，记住"行出列入"**（行是我能去哪，列是谁能来我这）。
4. **对角线全是 0**（没有自环的话）。
5. **无向图的 1 的个数 = 2 × 边数**（每条边贡献两个 1）——这正好是"度之和 = 2e"。

**`[[0] * n] * n` 这个坑必须说一下**：它建出来的是"n 个引用指向同一个列表"，你改 `matrix[0][0]`，所有行都会跟着变。**建二维列表一定要用列表推导** `[[0] * n for _ in range(n)]`。

**带权图的矩阵**：`1` 换成权值，没有边的地方填 `0`（或一个很大的数 `INF`）。**注意：填 0 还是 INF 要想清楚**——如果图上真有"权值为 0 的边"，填 0 就会把它当成"没有边"，这时候必须用 `INF`。**考试答题时写一句"无边用 ∞ 表示"最保险。**

### 两种存法怎么选

| | 邻接矩阵 | 邻接表 |
| --- | --- | --- |
| 空间 | **O(n²)** | **O(n + e)** |
| 判断 u、v 之间有没有边 | **O(1)**（直接查表） | O(u 的度)（要遍历邻居） |
| 找出 u 的所有邻居 | O(n)（扫一整行） | **O(u 的度)** |
| 适合 | **稠密图**（边很多） | **稀疏图**（边很少） |
| 实现 | 二维列表 | 字典 / 列表的列表 |

**一句话总结**：**矩阵是"用空间换时间"，邻接表是"用时间换空间"。**

举个例子感受一下：1000 个顶点、2000 条边（很稀疏）的图，矩阵要 100 万个格子，邻接表只要 2000×2 = 4000 个条目——**差 250 倍**。所以**真实世界的图（社交网络、地图）几乎都用邻接表**；而考试里问你"判断两点是否相邻"的最快结构时，答案就是矩阵。

## 三、遍历：DFS 和 BFS

### 和树最大的区别：图有环，所以必须"记账"

树的遍历不需要 `visited`，因为树**没有环、每个节点只有一个爹**，从根往下走绝对不会回到原点。

图不一样。在 `A-B-D-C-A` 这个圈里，你从 A 走到 B、走到 D、走到 C，C 的邻居又有 A——**如果不记录"A 已经走过"，你就会 A→B→D→C→A→B→… 无限转圈**（递归版本直接 `RecursionError`）。

所以图遍历的第一句心法是：

> **每访问一个顶点，立刻把它记进 `visited`（一个集合）。**

### DFS：一条路走到黑（递归写法）

DFS（Depth-First Search，深度优先）就是**树的前序遍历的推广**：走到一个顶点，先挑一个没去过的邻居扎进去，扎到底了再退回来换下一个。

```python
def dfs(graph, start, visited=None):
    if visited is None:
        visited = set()
    visited.add(start)              # 到达就标记
    print(start, end=" ")
    for v in graph[start]:          # 挨个试邻居
        if v not in visited:
            dfs(graph, v, visited)
    return visited


print("DFS 从 A 出发：", end="")
dfs(graph, "A")
print()
```

输出：

```text
DFS 从 A 出发：A B D C E F 
```

**跟着走一遍**（这是理解 DFS 唯一的方式）：

```text
A → 标记 A，去第一个邻居 B
  B → 标记 B，去第一个没去过的邻居 D
    D → 标记 D，邻居 B 去过，换 C
      C → 标记 C，邻居 A、D 都去过 → 退回 D
    D → 邻居 E 没去过
      E → 标记 E，邻居 F
        F → 标记 F，邻居 E 去过 → 退回 E
      E → 没别的邻居了 → 退回 D
    D → 没别的了 → 退回 B → 退回 A
A → 邻居 C 去过 → 结束
```

**顺序就是"深入到底再回头"**：A B D C E F。**如果你觉得这和树的前序一模一样，那就对了——树的遍历只是图遍历的一个特例。**

**注意这里**：`visited` 是在**进入函数的第一时间**标记的，不是"等邻居都访问完再标记"。**这个顺序如果搞反，在有些图里同一个顶点会被访问两次。**

### DFS 的非递归写法：用栈

递归本质是栈（第 5 篇说过），图也一样。**但要多一步"出栈时再判断是否访问过"**，因为同一个顶点可能被不同路径压进去好几次：

```python
def dfs_iter(graph, start):
    order = []
    seen = set()
    stack = [start]
    while stack:
        u = stack.pop()             # 弹栈顶
        if u in seen:               # 可能被重复压栈，跳过
            continue
        seen.add(u)
        order.append(u)
        for v in reversed(graph[u]):    # 倒着压，保证第一个邻居最先被处理
            if v not in seen:
                stack.append(v)
    return order


print("非递归 DFS：", dfs_iter(graph, "A"))
```

输出：

```text
非递归 DFS： ['A', 'B', 'D', 'C', 'E', 'F']
```

**和递归版的结果完全一致。** `reversed` 是为了"抵消"栈的后进先出——**这和第 5 篇里"先压右孩子、后压左孩子"是同一个套路**。不加 `reversed` 也能遍历全图，只是顺序会变成 `A C D E F B`（每次都先走列表里最后那个邻居）。

### BFS：一圈一圈扩散（队列）

BFS（Breadth-First Search，广度优先）**就是树的层序遍历的推广**：先把"离起点一步"的全访问完，再访问"两步"的，以此类推。

```python
from collections import deque


def bfs(graph, start):
    order = []
    seen = {start}
    q = deque([start])
    while q:
        u = q.popleft()             # 出队（第 3 篇的队列）
        order.append(u)
        for v in graph[u]:
            if v not in seen:
                seen.add(v)         # ★ 入队时就标记，不是出队时
                q.append(v)
    return order


print("BFS 从 A 出发：", bfs(graph, "A"))
```

输出：

```text
BFS 从 A 出发： ['A', 'B', 'C', 'D', 'E', 'F']
```

**BFS 的顺序 = 离起点的"距离"从小到大**：A（0 步）、B、C（1 步）、D（2 步）、E（3 步）、F（4 步）。**这个性质是后面"无权图最短路径"的全部基础**——**BFS 第一次访问到一个顶点时，走的就是最短的边数。**

**注意这里（BFS 最容易错的地方）**：`seen.add(v)` 必须在**入队时**做，不能在出队时做。

- 入队时标记：一个顶点最多进队一次，队列规模 O(n)。
- 出队时标记：B、C 都会把 D 放进队列，**同一个顶点被反复入队**，队列会膨胀（稠密图里能炸到指数级）。

**这个问题在树的层序遍历里不存在**（树里不会有两条路通到同一个节点），所以第 5 篇的代码没标记也不会错——**一到图上就露馅了**。

### DFS vs BFS 一张表

| | DFS | BFS |
| --- | --- | --- |
| 靠什么 | 递归 / 栈 | 队列 |
| 走法 | 一条路走到黑，回头再换 | 一圈一圈扩散 |
| 树上的对应物 | 前序遍历 | 层序遍历 |
| 空间（最坏） | O(n)（递归深度 / 栈） | O(n)（队列宽度） |
| 能保证"路径最短"吗 | ❌ 不能 | ✅ 能（无权图） |
| 典型用途 | 连通性、找环、拓扑排序、回溯 | 最短步数、层次关系、拓扑排序（Kahn） |

### 时间复杂度

| 存储方式 | DFS / BFS 的时间 |
| --- | --- |
| 邻接表 | **O(n + e)**：每个顶点进一次、每条边看一眼 |
| 邻接矩阵 | **O(n²)**：为了找邻居，每个顶点都得扫一整行 |

**为什么邻接表是 O(n+e)？** 每个顶点被访问一次（n），每次访问要把它的邻居列表走一遍，所有顶点的邻居列表长度加起来正好是 2e（无向图）。**所以是 n + 2e，去掉常数就是 O(n+e)。**

**这道题每年都考**："分别用邻接矩阵和邻接表存图，DFS 的时间复杂度是多少？"**答：O(n²) 和 O(n+e)。** 别只答一个。

## 四、遍历能干什么：连通分量与"能不能到达"

### 非连通图：一个起点走不完怎么办

上面那张图是连通的，从 A 出发能走遍所有顶点。**但如果是"三个孤岛"呢？**

```python
parts = {
    "A": ["B"],
    "B": ["A", "C"],
    "C": ["B"],
    "D": ["E"],
    "E": ["D"],
    "F": [],
}
```

从 A 出发只能走 A、B、C，D、E、F 根本进不去。**解决办法很简单：外层把所有顶点过一遍，谁没访问过，就从谁开始再做一次 DFS。**

```python
def count_components(graph):
    seen = set()
    count = 0

    def dfs(u):
        seen.add(u)
        for v in graph[u]:
            if v not in seen:
                dfs(v)

    for u in graph:
        if u not in seen:
            count += 1          # 发现一个新岛，岛数 +1
            dfs(u)
    return count


print("连通分量个数：", count_components(parts))
print("连通分量个数（原来的图）：", count_components(graph))
```

输出：

```text
连通分量个数： 3
连通分量个数（原来的图）： 1
```

**这个"外层 for + 内层 DFS"的写法非常重要**，考试里凡是"非连通图"的题（连通分量、遍历全图、判断图是否连通）都要用它。**只写一次 `dfs(start)` 是这类题最常见的失分点。**

**注意这里**：内层的 `dfs` 是定义在函数里面的**嵌套函数**，它直接用外层的 `seen`，所以不用传参。**如果不想用嵌套函数，就把 `seen` 当参数一路传下去**（像第 5 篇遍历那样），两种写法都对。

### 判断两个顶点之间有没有路径

这个更好写：**从起点做一次 DFS（或 BFS），最后看终点在不在 `visited` 里**。

```python
def has_path(graph, start, end):
    seen = set()
    stack = [start]
    while stack:
        u = stack.pop()
        if u == end:
            return True
        if u in seen:
            continue
        seen.add(u)
        for v in graph[u]:
            if v not in seen:
                stack.append(v)
    return False


print("A 到 F 有路径吗：", has_path(graph, "A", "F"))
print("A 到 D 有路径吗：", has_path(parts, "A", "D"))
print("A 到 C 有路径吗：", has_path(parts, "A", "C"))
```

输出：

```text
A 到 F 有路径吗： True
A 到 D 有路径吗： False
A 到 C 有路径吗： True
```

**注意这里**：这个版本里 `if u == end` 的判断放在了 `if u in seen: continue` **之前**，所以起点和终点相同时会直接返回 `True`（`has_path(g, "A", "A")` → True）。**这种边界情况（起点 = 终点）考试不常考，但写代码时想一下不吃亏。**

## 五、最短路径：BFS 管"最少几步"，Dijkstra 管"最短距离"

### 无权图：BFS 就是最短路算法

BFS 有个天然的好处：**它是按"离起点的距离"一圈圈扩散的，所以第一次到达某个顶点时走的就是最少的边数。**

把 BFS 稍微改一下：不只记录"去过没"，还记录**"几步到的"**和**"从谁那儿来的"**：

```python
def bfs_dist(graph, start):
    dist = {start: 0}                # 到 start 的距离是 0
    parent = {start: None}           # 记录"从谁那儿来的"，用来还原路径
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:        # 第一次到达（也就是最短的那次）
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)
    return dist, parent


def path_to(parent, end):
    path = []
    cur = end
    while cur is not None:
        path.append(cur)
        cur = parent[cur]
    return path[::-1]                # 倒过来就是 "起点 → 终点"


dist, parent = bfs_dist(graph, "A")
print("A 到各点的最少边数：", dist)
print("A 到 F 的路径：", path_to(parent, "F"))
```

输出：

```text
A 到各点的最少边数： {'A': 0, 'B': 1, 'C': 1, 'D': 2, 'E': 3, 'F': 4}
A 到 F 的路径： ['A', 'B', 'D', 'E', 'F']
```

**`parent` 这个"记录从谁来的"的技巧，考试写代码题时几乎必用**——题目只要问"路径"，你就得靠它倒推。**光有 `dist` 只能回答"几步"，答不了"怎么走"。**

**注意这里**：无权图的最短路**只能用 BFS，不能用 DFS**。DFS 可能先走进一条又长又绕的路，虽然最终也能到，但**不是最短的**。这就是上面那张表里"DFS 不能保证最短"的意思。

### 带权图：Dijkstra（迪杰斯特拉）

一旦边上有了权，"最少几步"就不等于"最短距离"了——**走 1 条权值 100 的边，比走 3 条权值 1 的边亏得多**。这时候要用 Dijkstra。

**思路（贪心）**：每次从"还没确定的顶点"里挑一个**当前距离最小**的，确定它的最短路，然后用它去**更新（松弛）**它的邻居。

用第二节建好的那个带权图（`weighted`：A→B 4、A→C 1、C→B 2、C→D 5、D→E 3）来跑：

```python
INF = float("inf")


def dijkstra(graph, start):
    dist = {u: INF for u in graph}       # 一开始到哪都是"无穷远"
    dist[start] = 0
    visited = set()

    while len(visited) < len(graph):
        # ① 挑出没确定过的、dist 最小的那个
        u = None
        for v in graph:
            if v not in visited and (u is None or dist[v] < dist[u]):
                u = v
        if u is None or dist[u] == INF:  # 剩下的都到不了，收工
            break
        visited.add(u)

        # ② 用 u 去松弛邻居
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    return dist


print("从 A 出发的最短距离：", dijkstra(weighted, "A"))
```

输出：

```text
从 A 出发的最短距离： {'A': 0, 'B': 3, 'C': 1, 'D': 4, 'E': 7}
```

**手工跟着走一遍（考试的"表格法"就是干这个）**：

| 步骤 | 确定 u | A | B | C | D | E |
| --- | --- | --- | --- | --- | --- | --- |
| 初始 | — | **0** | ∞ | ∞ | ∞ | ∞ |
| 1 | A | 0 | 4 | 1 | ∞ | ∞ |
| 2 | C（1） | 0 | **3** | 1 | 6 | ∞ |
| 3 | B（3） | 0 | 3 | 1 | **4** | ∞ |
| 4 | D（4） | 0 | 3 | 1 | 4 | **7** |
| 5 | E（7） | 0 | 3 | 1 | 4 | 7 |

**关键看第 2 步**：A 直接到 B 要 4，但 A→C→B 只要 1+2=3，所以 B 被"松弛"成了 3。**"松弛"（relax）这个词就是"发现有更短的路，把它改小"**——这个词考试写简答会用到。

**为什么 Dijkstra 不能有负权边？** 因为它的贪心建立在"**已经确定的最短路不会再变短**"上。如果有负权边，一个"绕远路"的走法可能反而更短，**已经确定的距离会被推翻**，算法就错了。**有负权必须用 Bellman-Ford（O(n·e)），别用 Dijkstra。**

### 三个最短路算法，考试只考这三个的"适用场景"

| 算法 | 解决什么 | 复杂度 | 能处理负权吗 |
| --- | --- | --- | --- |
| **BFS** | 无权图的单源最短路 | O(n + e) | 不涉及权 |
| **Dijkstra** | 非负权图的**单源**最短路 | O(n²)（本实现）/ O((n+e)log n)（堆优化） | ❌ 不能 |
| **Floyd** | **任意两点之间**的最短路（多源） | O(n³) | ✅ 能（别问为什么，背结论） |

**"单源" = 只算一个起点到所有点；"多源" = 每两个点之间的距离都要。** 这三个词经常被问混。

**注意这里**：上面 Dijkstra 的复杂度是 **O(n²)**，因为"挑最小的 dist"是用一个 `for` 循环扫出来的。如果改用堆（第 5 篇的 `MinHeap`）来挑，就变成 **O((n+e) log n)**——**这正是"堆"这个数据结构存在的最大理由之一**。

## 六、最小生成树：把所有点连起来，花的钱最少

### 问题是什么

假设有 6 个城市，你要修路让它们**全部连通**，每条路的造价不同。**怎么修，造价最低？**

- 要让 n 个点连通，**至少要 n-1 条边**（少一条就断开）。
- **正好 n-1 条边 + 连通 = 一棵树**（这是第 5 篇的结论）。
- **再想省钱，就不能有环**（有环就说明某条边是白花的）。

所以答案是：**在原图里挑出一棵"包含所有顶点、权值之和最小"的树**——这就是**最小生成树（MST, Minimum Spanning Tree）**。

```text
原图：A-B(4)  A-C(2)  B-C(1)  B-D(5)  C-D(8)  C-E(10)  D-E(2)  D-F(6)  E-F(3)
      一共 9 条边

最小生成树：A-C(2)  C-B(1)  B-D(5)  D-E(2)  E-F(3)
      一共 5 条边（= n-1），总权 13

        A
        │2
        C
        │1
        B ——5—— D ——2—— E ——3—— F
```

**两个必须记住的结论**：

1. **最小生成树的边数永远是 n - 1。**
2. **最小生成树总权值唯一，但形状可能不唯一**（有权值相同的边时，可以选这条也可以选那条）。

### Prim（普里姆）："加点法"

**思路**：从任意一个点出发，把它当作"已连好的一伙"。然后**每次从"已连好的点"和"还没连的点"之间，挑一条最便宜的边**，把新点拉进来。重复 n-1 次。

```python
mgraph = {
    "A": [("B", 4), ("C", 2)],
    "B": [("A", 4), ("C", 1), ("D", 5)],
    "C": [("A", 2), ("B", 1), ("D", 8), ("E", 10)],
    "D": [("B", 5), ("C", 8), ("E", 2), ("F", 6)],
    "E": [("C", 10), ("D", 2), ("F", 3)],
    "F": [("D", 6), ("E", 3)],
}


def prim(graph, start):
    visited = {start}               # 已经连好的点
    chosen = []                     # 选中的边
    total = 0
    while len(visited) < len(graph):
        best = None                 # (权值, 从谁, 到谁)
        for u in visited:
            for v, w in graph[u]:
                if v in visited:    # 两边都在集合里，会成环，跳过
                    continue
                if best is None or w < best[0]:
                    best = (w, u, v)
        if best is None:            # 图不连通，生成不出树
            break
        w, u, v = best
        visited.add(v)              # 把新点拉进来
        chosen.append((u, v, w))
        total += w
    return chosen, total


edges, total = prim(mgraph, "A")
for u, v, w in edges:
    print(f"{u} — {v}    权 {w}")
print("总权值：", total)
```

输出：

```text
A — C    权 2
C — B    权 1
B — D    权 5
D — E    权 2
E — F    权 3
总权值： 13
```

**手工跟着走**：

```text
已连 {A}：可选 A-B(4)、A-C(2)              → 选 A-C(2)，把 C 拉进来
已连 {A,C}：可选 A-B(4)、C-B(1)、C-D(8)、C-E(10)  → 选 C-B(1)，拉进 B
已连 {A,C,B}：可选 C-D(8)、B-D(5)、C-E(10)        → 选 B-D(5)，拉进 D
已连 {A,C,B,D}：可选 C-E(10)、D-E(2)、D-F(6)      → 选 D-E(2)，拉进 E
已连 {A,C,B,D,E}：可选 D-F(6)、E-F(3)             → 选 E-F(3)，拉进 F
5 条边，总权 2+1+5+2+3 = 13
```

**注意这里**：`if v in visited: continue` 这一行是 Prim 的命门——**它保证了不会成环**。因为"已经连好的点"内部已经连通了，再加一条两端都在里面的边，必然形成一个圈，那这条边就是白花钱。

### Kruskal（克鲁斯卡尔）："加边法"

**思路完全不同**：把所有边**按权值从小到大排序**，依次尝试加入；**如果这条边的两个端点已经连通了（加了会成环），就扔掉它**；否则加进来。加到够 n-1 条为止。

```text
Kruskal 的思路（伪代码，不是可直接运行的 Python）：

把所有边排序：[C-B(1), A-C(2), D-E(2), E-F(3), A-B(4), B-D(5), D-F(6), C-D(8), C-E(10)]
选 C-B(1)  → 不成环，要
选 A-C(2)  → 不成环，要
选 D-E(2)  → 不成环，要
选 E-F(3)  → 不成环，要
选 A-B(4)  → A、B 已经通过 C 连通了，会成环 → 扔
选 B-D(5)  → 不成环，要       ← 已经有 5 条边（n-1），结束
总权 = 1 + 2 + 2 + 3 + 5 = 13
```

**结果和 Prim 一模一样（总权 13），但过程完全不同**：Prim 是"从一个点长出去"，Kruskal 是"全局挑最便宜的边"。

**"怎么判断两个点是否已经连通"**——这就需要**并查集（Union-Find）**：每个点一开始是独立的一伙，加边时把两伙合并，判断"是不是一伙"就是查根节点是否相同。**并查集几乎是专门为 Kruskal 发明的**，考试如果问"Kruskal 用什么判断环"，答案就是**并查集**。

### Prim vs Kruskal

| | Prim | Kruskal |
| --- | --- | --- |
| 策略 | **加点**：从一棵树长出去 | **加边**：全局挑最小边 |
| 判断成环 | 看顶点是否已在集合里 | **并查集** |
| 复杂度 | O(n²)（本实现）/ O(e log n)（堆优化） | **O(e log e)**（排序是瓶颈） |
| 适合 | **稠密图**（边多） | **稀疏图**（边少） |
| 一句话 | 从点出发 | 从边出发 |

**怎么记？** **Prim 的 P 想成"Point（点）"，Kruskal 的 K 想成"Kante"（德语"边"）**——或者更简单的：**Prim 每次只关心"一个点"，Kruskal 每次关心"所有边"。**

## 七、拓扑排序：谁必须先做

### 问题：修课顺序

假设你在选课：

```text
课程 1 是基础课，课程 2、3 要先修 1；课程 4 要先修 2 和 3；课程 5 要先修 4。
```

画成有向图（**顶点是"活动/课程"，边表示"必须先完成"**），这种图叫 **AOV 网（Activity On Vertex）**：

```text
   1 ──→ 2 ──→ 4 ──→ 5
   └───→ 3 ──→ 4
```

**问题**：给出一个合法的上课顺序，使得**每门课的所有先修课都排在它前面**。

答案就是**拓扑序列**：`1 2 3 4 5`（或者 `1 3 2 4 5`，**两种都合法，所以拓扑序列不唯一**）。

**"拓扑排序"不是把元素按大小排序，而是把图排成一个"不违反箭头方向"的线性顺序。** 这一点千万别被名字骗了。

### 有环就没戏

如果课程依赖出现死循环——`1 要先修 2`、`2 要先修 3`、`3 要先修 1`——**谁都开不了课**。

```text
   1 ──→ 2
   ↑     │
   └──3──┘      这是一个环，没有拓扑序列
```

**所以"能不能拓扑排序"等价于"图里有没有环"**。这也是拓扑排序最主要的用途：**检测有向图是否有环**（比如判断"包的依赖关系里有没有循环依赖"）。

### Kahn 算法（BFS 版）：入度为 0 的先处理

思路非常朴素，就三步：

1. **数出每个顶点的入度**（有几门先修课）。
2. **把所有入度为 0 的顶点放进队列**（这些课可以立刻上）。
3. **反复出队**：出队一个顶点，把它加进答案；然后**把它指向的所有邻居的入度减 1**（相当于"这门先修课上完了"）；**谁的入度减到 0，谁就入队**。

```python
def topo_sort(graph):
    indeg = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indeg[v] += 1                   # 数入度

    q = deque([u for u in graph if indeg[u] == 0])   # 入度 0 的入队
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1                   # 删掉 u→v 这条边
            if indeg[v] == 0:               # v 的先修课全上完了
                q.append(v)
    return order, len(order) == len(graph)  # 长度不够 = 有环


courses = {
    1: [2, 3],
    2: [4],
    3: [4],
    4: [5],
    5: [],
}
order, ok = topo_sort(courses)
print("课程顺序：", order, "无环：", ok)

bad = {1: [2], 2: [3], 3: [1]}
order, ok = topo_sort(bad)
print("循环依赖：", order, "无环：", ok)
```

输出：

```text
课程顺序： [1, 2, 3, 4, 5] 无环： True
循环依赖： [] 无环： False
```

**手工跟着走一遍**（考试就考这个手推）：

```text
入度：1→0，2→1，3→1，4→2，5→1
队列 [1]
出队 1 → 答案 [1]；2 的入度 1→0 入队；3 的入度 1→0 入队  队列 [2,3]
出队 2 → 答案 [1,2]；4 的入度 2→1                        队列 [3]
出队 3 → 答案 [1,2,3]；4 的入度 1→0 入队                  队列 [4]
出队 4 → 答案 [1,2,3,4]；5 的入度 1→0 入队                队列 [5]
出队 5 → 答案 [1,2,3,4,5]                                队列 []
→ 得到了全部 5 个顶点，无环
```

**关键就一句话**：**"入度变成 0" = "所有先修课都上完了"**。每次出队，相当于**把这个顶点从图里删掉**，顺便删掉它的出边——**出边的入度减一，就是这么来的**。

**检测环的方法也藏在里面**：如果图里有环，**环上的顶点入度永远减不到 0**，它们永远进不了队列。所以最后 `len(order) < n` 就说明有环。**这个"看长度对不对"的技巧，比单独写一个找环算法省事得多。**

**复杂度**：每个顶点进队一次（n），每条边被看一次（e），所以是 **O(n + e)**。

**注意这里**：Kahn 用的是**队列**（BFS 思路）。也有用**栈 / 递归**（DFS 思路）的版本——**在 DFS 的后序位置逆序输出**，两种都叫拓扑排序，考场上写 Kahn 更不容易错，因为"入度"这个概念看得见摸得着。

## 八、常见错误

### 错误 1：DFS 不标 `visited`

```python
# ❌ 错
def dfs(graph, u, visited):
    print(u)
    for v in graph[u]:
        dfs(graph, v, visited)     # 没有"访问过就跳过"的判断
```

图里只要有环（`A-B-D-C-A`），就会 A→B→D→C→A→B→… 无限递归，最后 `RecursionError`。

**改法**：第一行 `visited.add(u)`，邻居循环里 `if v not in visited`。**这两句话是图遍历的"生命线"。**

### 错误 2：BFS 在"出队时"才标记

```python
# ❌ 错
u = q.popleft()
seen.add(u)                  # 太晚了
for v in graph[u]:
    if v not in seen:
        q.append(v)
```

同一个顶点会被它的多个邻居各塞进队列一次。而且那些重复进队的副本出队时，代码里没有 `if u in seen: continue` 兜底，**它们会把邻居再展开一遍**——重复越来越多，稠密图里队列规模会直接爆炸。

**改法**：`seen.add(v)` 写在 `q.append(v)` **旁边**，入队即标记。

### 错误 3：无向图只加了一条边

```python
# ❌ 错：建出来的是"有向图"
graph[u].append(v)
```

结果：从 u 能走到 v，从 v 走不回 u——**BFS/DFS 结果全错，连通分量数也会算多**。

**改法**：无向图必须 `graph[u].append(v)` 和 `graph[v].append(u)` **成对出现**。（用矩阵存无向图同理，`m[i][j]` 和 `m[j][i]` 都要置 1。）

### 错误 4：`[[0] * n] * n` 建矩阵

```python
# ❌ 错：n 行其实是同一个列表
matrix = [[0] * n] * n
matrix[0][0] = 1              # 所有行的第 0 个元素全变成 1 了
```

**改法**：`matrix = [[0] * n for _ in range(n)]`。

**这个坑在第 1 篇讲过"列表是引用"之后就不该再踩**——`* n` 复制的是引用，不是内容。

### 错误 5：非连通图只从一个点出发

```python
# ❌ 错：parts 有 3 个连通分量，这样只能走完第一个
dfs(parts, "A")
```

**改法**：外层 `for u in graph: if u not in seen: ...`（就是第四节那个骨架）。

### 错误 6：拿 Dijkstra 跑负权图

```python
# ❌ 思路错：图里有 -5 这样的边
dijkstra(graph_with_negative_edges, "A")
```

Dijkstra 的贪心假设是"确定下来的最短距离不会再变小"，**负权边会推翻这个假设**，结果可能比正确答案大。

**改法**：负权用 **Bellman-Ford**；只关心"有没有负环"也是它。**答题时写一句"Dijkstra 要求边权非负"就是得分点。**

### 错误 7：Prim 忘了判"两个端点是否都已加入"

```python
# ❌ 错
for u in visited:
    for v, w in graph[u]:
        if best is None or w < best[0]:      # 少了 if v in visited: continue
            best = (w, u, v)
```

一旦选到一条两端都在集合里的边，就**成环**了，生成出来的不是树。

**改法**：`if v in visited: continue`。**这一行就是 Prim 的"选边合法性检查"。**

### 错误 8：拓扑排序忘了判环

```python
# ❌ 不完整：有环也返回一个"残缺序列"，调用者以为是完整的
return order
```

**改法**：返回 `order, len(order) == len(graph)`，或者显式判断 `len(order) < n` 就报"有环"。

### 错误 9：几个数字记混

| 问题 | 正确答案 | 常见错答 |
| --- | --- | --- |
| 无向完全图边数 | **n(n-1)/2** | n(n-1) |
| 有向完全图边数 | **n(n-1)** | n(n-1)/2 |
| 最小生成树边数 | **n-1** | n |
| 邻接矩阵空间 | **O(n²)** | O(n+e) |
| 邻接表空间 | **O(n+e)** | O(n²) |
| 无向图度之和 | **2e** | e |
| 有向图入度之和 | **e** | 2e |

**这张表建议直接背下来。** 这七个数字几乎覆盖了图论部分所有选择题。

### 考题 1：画矩阵、写遍历序列、数度数

> 已知无向图 G 的顶点集为 {A, B, C, D, E}，边集为 {A-B, A-C, B-D, B-E, C-D, D-E}。
> (1) 画出邻接矩阵；(2) 写出从 A 出发的 DFS 和 BFS 序列；(3) 求每个顶点的度和图的边数；(4) 该图连通吗？

**手工做**：

```text
(1) 邻接矩阵（行 = 从谁出发，列 = 到谁）
      A B C D E
   A  0 1 1 0 0
   B  1 0 0 1 1
   C  1 0 0 1 0
   D  0 1 1 0 1
   E  0 1 0 1 0

(2) DFS（一条路走到黑）：A → B → D → C → E
    BFS（一圈圈扩散）  ：A → B → C → D → E

(3) 度：A=2，B=3，C=2，D=3，E=2，度之和 12，边数 12/2 = 6
(4) 连通（所有顶点都能互相到达），连通分量 1 个
```

**代码核对**：

```python
exam = {
    "A": ["B", "C"],
    "B": ["A", "D", "E"],
    "C": ["A", "D"],
    "D": ["B", "C", "E"],

}

print("DFS：", dfs_iter(exam, "A"))
print("BFS：", bfs(exam, "A"))

nodes2 = list(exam)
idx2 = {u: i for i, u in enumerate(nodes2)}

    for v in exam[u]:

for u in nodes2:

```

### 考题 2：Dijkstra 手算 + 代码

> 下面这个无向带权图，求从 A 出发到各点的最短距离。

```text
6 个顶点 A B C D E F，9 条边（无向，带权）：

A-B 7     A-C 9     A-F 14
B-C 10    B-D 15
C-D 11    C-F 2
D-E 6
E-F 9

（这就是 Dijkstra 最经典的那个例子，考试常直接拿来用）
```

**手工用表格法**（考试就按这个格式写，能拿满步骤分）：

| 步骤 | 确定 | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 初始 | — | **0** | ∞ | ∞ | ∞ | ∞ | ∞ |
| 1 | A | 0 | **7** | **9** | ∞ | ∞ | **14** |
| 2 | B | 0 | 7 | 9 | **22** | ∞ | 14 |
| 3 | C | 0 | 7 | 9 | **20** | ∞ | **11** |
| 4 | F | 0 | 7 | 9 | 20 | **20** | 11 |
| 5 | D | 0 | 7 | 9 | 20 | 20 | 11 |
| 6 | E | 0 | 7 | 9 | 20 | 20 | 11 |

**结果：A=0，B=7，C=9，D=20，E=20，F=11。**

**代码核对**：

```python
w2 = {
    "A": [("B", 7), ("C", 9), ("F", 14)],
    "B": [("A", 7), ("C", 10), ("D", 15)],
    "C": [("A", 9), ("B", 10), ("D", 11), ("F", 2)],
    "D": [("B", 15), ("C", 11), ("E", 6)],
    "E": [("D", 6), ("F", 9)],
    "F": [("A", 14), ("C", 2), ("E", 9)],
}

print("从 A 出发：", dijkstra(w2, "A"))
```

输出：

```text
从 A 出发： {'A': 0, 'B': 7, 'C': 9, 'D': 20, 'E': 20, 'F': 11}
```

**这道题最容易丢分的地方**：**忘了更新"绕路更近"的情况**。比如上表第 3 步，`A→C→D` 是 9+11=20，比第 2 步的 `A→B→D`=22 更短，所以 D 要从 22 改成 20。**"比较新旧、取小的"这个动作，每松弛一次都不能省。**

### 考题 3：判断一个序列是不是合法拓扑序列

> 已知 AOV 网：`1→2`、`1→3`、`2→4`、`3→4`、`4→5`。判断下列序列是否是拓扑序列：
> (1) `1 2 3 4 5`  (2) `1 3 2 4 5`  (3) `2 1 3 4 5`  (4) `1 2 4 3 5`

**手工判断法**：**看每条边，起点是不是都排在终点前面**。只要有一条边反过来，就不是拓扑序列。

```text
(1) 1 2 3 4 5：所有边都从左指向右 ✅
(2) 1 3 2 4 5：1→2（1 在 2 前）✓，1→3 ✓，2→4 ✓，3→4（3 在 2 前，但 3 仍在 4 前）✓ ✅
(3) 2 1 3 4 5：1→2 要求 1 在 2 前面，但这里 2 在前 ❌
(4) 1 2 4 3 5：3→4 要求 3 在 4 前面，但这里 4 在 3 前面 ❌
```

**代码核对**：

```python
def is_valid_topo(graph, seq):
    pos = {u: i for i, u in enumerate(seq)}      # 每个顶点排在第几位
    for u in graph:
        for v in graph[u]:
            if pos[u] > pos[v]:                 # 有边反向了
                return False
    return True


for seq in [[1, 2, 3, 4, 5],
            [1, 3, 2, 4, 5],
            [2, 1, 3, 4, 5],
            [1, 2, 4, 3, 5]]:
    print(seq, "->", is_valid_topo(courses, seq))
```

输出：

```text
[1, 2, 3, 4, 5] -> True
[1, 3, 2, 4, 5] -> True
[2, 1, 3, 4, 5] -> False
[1, 2, 4, 3, 5] -> False
```

**这道题的价值在于提醒你：拓扑序列不唯一。** 题目如果只给一个序列让你判断，别拿它跟"标准答案"对比，**要一条边一条边地验**。

## 十、考试怎么考

### 四种题型，各自怎么应对

**① 选择 / 填空（最容易拿分，也最容易丢在细节上）**

必背清单，进考场前扫一遍：

```text
无向完全图边数 = n(n-1)/2          有向完全图边数 = n(n-1)
生成树 / 最小生成树边数 = n-1      连通 n 个点至少要 n-1 条边
无向图度之和 = 2e                  有向图入度和 = 出度和 = e
邻接矩阵空间 O(n²)                 邻接表空间 O(n+e)
邻接矩阵遍历 O(n²)                 邻接表遍历 O(n+e)
DFS 用栈（递归）                   BFS 用队列
Dijkstra 不能有负权                 Floyd 是 O(n³)、多源
Prim 适合稠密图                    Kruskal 适合稀疏图、靠并查集
拓扑排序 = 反复删入度为 0 的点       len(order) < n 说明有环
```

**② 简答（背三句话就够）**

- **"邻接矩阵和邻接表有什么区别？"** → 矩阵空间 O(n²)、判边 O(1)，适合稠密图；邻接表空间 O(n+e)、找邻居快，适合稀疏图。
- **"DFS 和 BFS 有什么区别？"** → DFS 用栈/递归、一条路走到黑；BFS 用队列、按层次扩散，**无权图能求最短路**。
- **"Prim 和 Kruskal 有什么区别？"** → Prim 加点、看顶点集合、适合稠密图；Kruskal 加边、按权排序 + 并查集判环、适合稀疏图。

**③ 综合题（画图 + 手推，占分最多）**

标准动作顺序：

1. **先数顶点和边**，写在草稿上（后面所有校验都靠它）。
2. 画邻接矩阵 → **检查是否对称**（无向图必须对称）。
3. 写 DFS / BFS 序列 → **写之前先把每个顶点的邻居按字母序排好**，避免自己前后不一致。
4. Dijkstra → **用表格，一行一步，别跳步**。
5. 拓扑排序 → **先算入度，再一步步删**。

**④ 代码题（本篇的代码够用了）**

图这部分的代码题基本就四个：**建图、DFS/BFS、拓扑排序、Dijkstra**。**能把"建图 + 遍历"写对，及格线就稳了。**

### 最容易掉的三个坑（考场上检查这三条）

1. **无向图加边加了两次吗？**（`graph[u].append(v)` 和 `graph[v].append(u)`）
2. **BFS 是入队时标记的吗？**（不是出队时）
3. **非连通图的题，外层有 for 遍历所有顶点吗？**

## 十一、小结

这一篇其实就讲了四件事，全都围着"**怎么存**"和"**怎么走**"：

| 你要解决的问题 | 用什么 | 复杂度 |
| --- | --- | --- |
| 图怎么存 | 邻接矩阵 / 邻接表 | O(n²) / O(n+e) |
| 走遍所有点 | DFS（栈）/ BFS（队列） | O(n+e) 或 O(n²) |
| 无权图最短路 | BFS + `dist`/`parent` | O(n+e) |
| 带权图最短路 | Dijkstra（不能负权） | O(n²) |
| 连所有点最省钱 | Prim（加点）/ Kruskal（加边） | O(n²) / O(e log e) |
| 排出先后顺序 | 拓扑排序（入度为 0 入队） | O(n+e) |

**五句话记住这一篇**：

1. **树是"一对多"，图是"多对多"**——图只多了一条"可以有环、可以不连通"的自由。
2. **图遍历 = 树遍历 + `visited`**。DFS 对应前序，BFS 对应层序，一个栈一个队列。
3. **BFS 第一次到达就是最短（无权图）**，这是它存在的全部意义。
4. **Dijkstra 是"每次挑最近的点，然后松弛"**，贪心的前提是**没有负权**。
5. **拓扑排序就是反复删"入度为 0"的点**，删不完就说明有环。

**图这一篇写下来，你会发现一件事**：之前学的**栈、队列、递归、堆**，在图里全都回来了——**DFS 用栈、BFS 用队列、拓扑排序用队列、Dijkstra 的堆优化用堆**。数据结构不是一堆孤立的知识点，而是**一套工具，换个场景再拿出来用一次**。
