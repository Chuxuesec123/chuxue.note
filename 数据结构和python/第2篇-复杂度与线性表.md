# 第 2 篇：复杂度入门 + 线性表——为什么"尾部加元素快、头部删元素慢"

这篇讲两件事：一是怎么用大 O 记号**一眼看出**一段代码快不快，二是把 Python 列表当成"顺序表"来解剖，数清楚它每种操作到底要动几下。需要先会：第 1 篇的变量、列表、`for`/`while`、函数和类——就这些，不用别的。

上一篇文章结尾我说过：语法只是工具，真正的问题是"为什么同样一个操作，有的写法快、有的写法慢"。这一篇就来把这个问题回答到底。

---

## 一、先说人话：什么叫"快"

如果你拿秒表去测两段代码，会立刻遇到三个麻烦：

1. 我这台电脑快，你那台电脑慢，测出来的秒数没法比；
2. 同一个程序，跑一百万条数据和跑十条数据，时间差得离谱；
3. 系统后台还在下载东西，测出来的数忽高忽低。

所以计算机科学不用秒表，用**"随着数据量变大，工作量涨得多快"**来衡量。这个"涨得多快"，就是时间复杂度。

生活里的类比，你可以这样想——假设你面前有一摞书，你要做不同的事：

| 你要做的事 | 工作量随书变多怎么变 | 复杂度 |
| --- | --- | --- |
| 按编号直接抽出第 37 本 | 不管有多少本，都是一步 | O(1) |
| 一本本翻，找封面是蓝色的那本 | 书越多翻得越久，正比增长 | O(n) |
| 书已经按编号排好，像查字典一样折半找 | 每翻一次少一半，涨得特别慢 | O(log n) |
| 每本书都要和其他所有书比一遍"谁更厚" | 书翻倍，比较次数变四倍 | O(n²) |

**注意这里**：O(1) 不是"绝对只用一毫秒"，而是"**不管 n 多大，工作量都不变**"。O(1) 的操作也可能很慢（比如从硬盘读一个文件），但它不随数据量增长。这一点考试很爱在选择题里绕你。

## 二、大 O 记号：只数"主项"，把零碎扔掉

大 O 的数学定义考试一般不考，你只要会一条**操作规则**：

> **数出基本操作的执行次数，只保留增长最快的那一项，并且把系数扔掉。**

为什么能这么粗暴？因为 n 很大的时候，小项和系数根本不重要：

- `3n + 5` 和 `n` 在 n 变成一千万时，差别只是"三千万" 和 "一千万"，**都是千万级**；而 `n²` 是"一亿亿级"，完全不是一个世界。
- 所以 `3n + 5` 记作 **O(n)**，`n²/2 + 3n` 记作 **O(n²)**，`2` 记作 **O(1)**。

三条口诀，背下来就能应付 90% 的题：

1. **加法取最大**：`O(n) + O(n²)` → `O(n²)`。两段代码先后执行，取慢的那个。
2. **嵌套相乘**：外层循环 n 次、内层也循环 n 次 → `n × n = O(n²)`。
3. **常数全扔**：`O(2n)` 写 `O(n)`，`O(n/2)` 写 `O(n)`，`O(3n² + 100n + 7)` 写 `O(n²)`。

**很多同学会在这里踩坑**：把 `O(2n)` 当成答案写上去。**大 O 里不写系数**，写 `O(2n)` 和写 `O(n)` 意思一样，但前者会被判不标准。

### 常见量级，从快到慢

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

背这张表的时候顺便记住它们各自长什么样：

- **O(1)**：没有循环，或者循环次数是固定的常数。
- **O(log n)**：每轮把问题**砍一半**，比如 `n = n // 2`、二分查找。
- **O(n)**：一层循环，每个元素过一遍。
- **O(n log n)**：外层 n 次，内层 log n 次，排序里的归并、快排平均情况就是这样。
- **O(n²)**：两层嵌套，都是 n 次。
- **O(2ⁿ)**：每个元素"选或不选"的暴力枚举，斐波那契的朴素递归。

### 规模一大，差距有多恐怖

同样是 n 条数据，不同复杂度的操作次数：

| n | log₂n | n | n log₂n | n² |
| --- | --- | --- | --- | --- |
| 10 | 约 3.3 | 10 | 约 33 | 100 |
| 100 | 约 6.6 | 100 | 约 664 | 10,000 |
| 1,000 | 10 | 1,000 | 10,000 | 1,000,000 |
| 10,000 | 约 13.3 | 10,000 | 约 133,000 | 100,000,000 |

你看，n 从 1000 涨到 10000（10 倍），O(n) 的工作量涨 10 倍，O(n²) 的工作量涨 **100 倍**，而 O(log n) 只从 10 涨到 13。这就是为什么算法课天天念叨"能不能把 O(n²) 优化成 O(n log n)"——不是省一点，是省一百倍。

## 三、动手：五个例子教会你"数循环"

大 O 分析在考试里九成是"看代码数循环"。下面五个例子，我建议你先把代码遮住，自己猜复杂度和循环次数，再往下看。

### 例子 1：一层循环，跟着 n 走 → O(n)

```python
def sum_list(a):
    total = 0
    for x in a:          # 循环 n 次（n 是列表长度）
        total += x       # 每次 1 次加法、1 次赋值
    return total

print(sum_list([1, 2, 3, 4, 5]))   # 15
```

循环体执行 n 次，每次做常数个操作，总次数 `1 + 2n`，扔掉常数和系数 → **O(n)**。

### 例子 2：两层嵌套，都是 n → O(n²)

```python
def count_pairs(n):
    count = 0
    for i in range(n):       # 外层 n 次
        for j in range(n):   # 内层也是 n 次
            count += 1
    return count

print(count_pairs(5))    # 25，正好 5 × 5
print(count_pairs(100))  # 10000
```

外层每转一圈，内层就把 n 次全做完，所以是 `n × n = n²`。**嵌套相乘**，这是最常见的 O(n²)。

### 例子 3：每轮砍一半 → O(log n)

```python
def halve_times(n):
    steps = 0
    while n > 1:
        n = n // 2       # 关键这一行：每轮除以 2
        steps += 1
    return steps

for k in [8, 16, 1024, 1048576]:
    print(k, "→", halve_times(k), "次")
```

输出：

```text
8 → 3 次
16 → 4 次
1024 → 10 次
1048576 → 20 次
```

看清楚这个增长：数据量从 8 涨到一百万（十几万倍），循环次数只从 3 涨到 20。因为 `n` 每轮折半，`n = 2^k` 时只需要 k 轮，而 `k = log₂n`。

所以**只要看到循环变量乘 2 或除以 2，就往 O(log n) 上想**。`i *= 2`、`i //= 2`、`left/right` 折半的二分查找，都是这一类。

### 例子 4：两段循环并列 → 还是 O(n)

```python
def two_loops(n):
    total = 0
    for i in range(n):      # 第一个循环 n 次
        total += i
    for i in range(n):      # 第二个循环也是 n 次
        total += i
    return total

print(two_loops(10))    # 90
```

`n + n = 2n`，扔掉系数 → **O(n)**。**并列的循环用加法，嵌套的循环用乘法**，这是很多人第一次做复杂度题会混的地方。

### 例子 5：内层次数和 n 无关 → 还是 O(n)

```python
def fixed_inner(a):
    total = 0
    for x in a:                # n 次
        for k in range(3):     # 固定 3 次，和 n 没关系
            total += x * k
    return total

print(fixed_inner([1, 2, 3]))   # 18
```

`n × 3 = 3n` → **O(n)**。**不要看到两层 for 就条件反射写 O(n²)**，要看内层循环的次数是不是跟着 n 变。这是选择题里最爱挖的坑之一，我在后面"常见错误"还会再说一遍。

### 一个小技巧：三角循环

```python
def count_triangle(n):
    count = 0
    for i in range(n):
        for j in range(i):      # 内层次数跟着 i 变：0, 1, 2, ..., n-1
            count += 1
    return count

print(count_triangle(5))    # 10 = 0+1+2+3+4
print(count_triangle(10))   # 45 = 0+1+...+9
```

总次数是 `0 + 1 + 2 + ... + (n-1) = n(n-1)/2`，展开是 `n²/2 - n/2`，只留最高阶 → 仍然是 **O(n²)**。

**记住这个结论**：内层循环次数从 1 涨到 n 的那种"三角形"循环，虽然只做了一半的工作，但复杂度还是 O(n²)，只是系数变成 1/2。**系数在大 O 里是要扔掉的**。

## 四、线性表：一排有顺序的格子

前面说了半天的"n 条数据"，现在该给它一个正式名字了。

**线性表**是逻辑结构上的一句话：**数据排成一条线，除了第一个和最后一个，每个元素都只有一个前驱和一个后继。**

生活类比：排队买奶茶。每个人（除了队首和队尾）前面有一个人、后面有一个人。你不能插到队伍中间的第三位去"跳号"——位置是有序的。

线性表可以有两种**存储方式**（也就是在内存里怎么放）：

| 存储方式 | 长什么样 | 随机访问 | 插入/删除 | 本课对应 |
| --- | --- | --- | --- | --- |
| **顺序表**（数组） | 一格一格紧挨着放，靠下标定位 | 快，O(1) | 慢，要挪元素，O(n) | Python 的 `list` |
| **链表** | 每个元素自带一个"下一站在哪"的箭头 | 慢，得从头走，O(n) | 快，改箭头就行，O(1) | 第 4 篇自己写 |

这一篇只讲顺序表，链表留到第 4 篇。但你现在就要把这张表的两句话记住，因为**期末考试最喜欢问的就是"顺序表和链表各有什么优缺点"**，而答案全在这两列里。

### Python 的 list 就是顺序表

```python
a = [10, 20, 30, 40, 50]

print(a[0])      # 10
print(a[4])      # 50
# print(a[5])    # 取消注释就会报 IndexError: list index out of range
```

你可以这样想 `a[i]`：Python 知道列表开头在内存的哪个地址，每个格子占几位，于是**直接算**出第 i 个格子的地址，一步跨过去。所以：

```python
big = list(range(1000000))
print(big[0])        # 一步
print(big[999999])   # 也是一步，不会因为下标大而变慢
```

**这就是"随机访问 O(1)"的意思**：不管你要第几个，花的步数都一样。这是顺序表最大的本钱，也是它唯一的本钱。

顺便一个细节，知道就行不用深究：Python 的 list 里存的其实是**对象的指针**（地址），不是对象本身。所以 `[1, "abc", [2, 3]]` 这种"什么都能装"的列表才可能存在——每个格子放的都是"地址"，大小一样。考试不会考这个，但能帮你理解为什么列表这么灵活。

## 五、把 list 的每个操作拆开数步数

先给你一张"考试版"总表，后面我们挨个验证它为什么长这样：

| 操作 | 写法 | 时间复杂度 | 一句话原因 |
| --- | --- | --- | --- |
| 按下标访问 | `a[i]` | **O(1)** | 地址直接算出来 |
| 修改 | `a[i] = x` | **O(1)** | 同上 |
| 求长度 | `len(a)` | **O(1)** | 长度单独存着，不用数 |
| 尾部追加 | `a.append(x)` | **均摊 O(1)** | 大多数时候放在末尾空位 |
| 尾部删除 | `a.pop()` | **O(1)** | 直接把最后一个划掉 |
| 指定位置插入 | `a.insert(i, x)` | **O(n)** | 后面所有元素都得后移 |
| 头部插入 | `a.insert(0, x)` | **O(n)** | 全部元素都要后移 |
| 指定位置删除 | `a.pop(i)` | **O(n)** | 后面所有元素都得前移 |
| 头部删除 | `a.pop(0)` | **O(n)** | 同上，最坏情况 |
| 按值查找 | `x in a` / `a.index(x)` | **O(n)** | 从前往后一个个比 |
| 删除指定值 | `a.remove(x)` | **O(n)** | 先找 O(n)，再挪 O(n) |
| 切片 | `a[i:j]` | **O(j-i)** | 要复制一段出来 |
| 整体复制 | `a.copy()` | **O(n)** | 每个元素都要复制 |

这张表不要背，要**理解成一幅画**：一排人坐在长凳上。

- **按下标找人**（`a[i]`）：长凳有刻度，直接走到第 i 个位置，一步。O(1)。
- **末尾加人**（`append`）：走到队尾坐下，一步。O(1)。
- **中间插队**（`insert(i, x)`）：从第 i 个人开始，后面所有人都得站起来往后挪一格。插得越靠前，挪的人越多。O(n)。
- **队首离开**（`pop(0)`）：第一个人走了，后面所有人都得往前挪一格。O(n)。
- **按特征找人**（`in` / `index`）：不知道编号，只能从头一个个看。O(n)。

### 亲手数一次 insert 的"移动次数"

考试最爱考"插入一个元素平均要移动多少次"。我们写个函数，把移动次数真的数出来：

```python
def insert_count(a, pos, x):
    """在列表 a 的下标 pos 处插入 x，返回这次插入移动了多少个元素。"""
    a.append(None)                      # 先在末尾腾出一个空格子
    moves = 0
    for i in range(len(a) - 1, pos, -1):   # 从最后一个开始，倒着往右挪
        a[i] = a[i - 1]
        moves += 1
    a[pos] = x
    return moves


a = [10, 20, 30, 40, 50]
print("插到最前面，移动", insert_count(a, 0, 5), "次 →", a)
print("插到最后面，移动", insert_count(a, 6, 99), "次 →", a)
```

输出：

```text
插到最前面，移动 5 次 → [5, 10, 20, 30, 40, 50]
插到最后面，移动 0 次 → [5, 10, 20, 30, 40, 50, 99]
```

逐块解释：

- `a.append(None)`：先占一个空位。你不可能在一条已经坐满的长凳上硬塞一个人，得先加个座位。
- `range(len(a) - 1, pos, -1)`：**倒着**遍历。为什么必须倒着？因为正着挪会把后面的元素覆盖掉。倒着走，每个元素都往"刚空出来的那格"里放，谁也不会被吃掉。这个细节手写代码题里很关键。
- 移动次数 = `len(a) - 1 - pos`，也就是"pos 后面有多少个元素"。所以插在最前面移 n 个，插在最后面移 0 个。

**注意这里**：`insert` 的时间复杂度是 O(n)，说的是**最坏情况**（插在头部）。插在尾部其实是 O(1)。但考试里问 `insert` 的复杂度，标准答案写 **O(n)**。

### 为什么 append 能是 O(1)：动态扩容

你可能会问：列表不是"紧挨着放"吗？那它怎么知道后面还有没有空位？

答案是：Python 的列表**故意多申请一点空间**。比如你只要 5 个格子，它可能给你 8 个，多出来的空着备用。所以 `append` 大多数时候只是"在下一个空位放东西"，一步搞定。

那如果备用空间也用完了呢？它会向系统要一块**更大的**内存（大约是原来的 1.125 倍），把老元素全部复制过去，再释放旧的。这一次复制是 O(n)，但它**很少发生**：n 次 append 里，扩容总成本加起来也就 O(n)，摊到每次头上是 O(1)。

这个说法叫**均摊复杂度**（摊还分析）。考试里遇到"Python 列表 append 的时间复杂度"，答 **O(1)（均摊）** 就是满分答案；只写 O(1) 一般也不会扣分，但要能解释一句"扩容时是 O(n)，不过平均下来是 O(1)"。

### 亲眼看看"头部操作"有多慢

下面这段代码用计时器对比"尾部操作"和"头部操作"。**数字会因电脑不同而不同，你只要看数量级**：

```python
import time

n = 5000

# 第一种：全在尾部操作
a = list(range(n))
t1 = time.perf_counter()
for _ in range(n):
    a.append(1)
    a.pop()
t2 = time.perf_counter()

# 第二种：全在头部操作
b = list(range(n))
t3 = time.perf_counter()
for _ in range(n):
    b.insert(0, 1)
    b.pop(0)
t4 = time.perf_counter()

print(f"尾部操作 {t2 - t1:.4f} 秒")
print(f"头部操作 {t4 - t3:.4f} 秒")
```

在我这边跑出来大概是这个量级（你的数字不一样，正常）：

```text
尾部操作 0.0004 秒
头部操作 0.0090 秒
```

同样的循环次数，头部操作慢了 **几十倍**。而且你注意：这里的 n 只有 5000。如果 n 是 50000，头部操作会再慢上百倍——因为它的工作量是 n² 级，n 涨 10 倍，工作量涨 100 倍。

**这就是第 1 篇里那句"尾部快、头部慢"的量化版。** 记住它，第 3 篇讲队列的时候你会看到：用 `pop(0)` 实现出队，就是一个典型的 O(n²) 陷阱。

## 六、考试必算：插入/删除的平均移动次数

这是顺序表部分**最稳定的一道计算题**，公式不难，但一定要会自己推。

设顺序表长度为 n。

### 插入：平均移动 n/2 次

在一个长度为 n 的顺序表里插入一个元素，一共有 **n+1 个**可以插的位置（下标 0 到 n，包括最前面和最后面）。

插在下标 i 的位置，要移动它后面的所有元素，也就是 **n - i** 个。

把每种位置的移动次数加起来再平均：

```text
总移动次数 = n + (n-1) + (n-2) + ... + 1 + 0 = n(n+1)/2
平均移动次数 = n(n+1)/2 ÷ (n+1) = n/2
```

### 删除：平均移动 (n-1)/2 次

删除第 i 个元素（下标 0 到 n-1），要把它后面的 **n-1-i** 个元素往前挪。

```text
总移动次数 = (n-1) + (n-2) + ... + 1 + 0 = n(n-1)/2
平均移动次数 = n(n-1)/2 ÷ n = (n-1)/2
```

### 让代码替你验证

```python
def avg_moves_insert(n):
    total = 0
    for i in range(n + 1):        # n+1 个插入位置
        total += n - i            # 插在 i 处要移动 n-i 个
    return total / (n + 1)


def avg_moves_delete(n):
    total = 0
    for i in range(n):            # n 个删除位置
        total += n - 1 - i        # 删掉 i 处要移动 n-1-i 个
    return total / n


for n in [10, 20, 100]:
    print(f"n={n}: 插入平均 {avg_moves_insert(n)} 次，删除平均 {avg_moves_delete(n)} 次")
```

输出：

```text
n=10: 插入平均 5.0 次，删除平均 4.5 次
n=20: 插入平均 10.0 次，删除平均 9.5 次
n=100: 插入平均 50.0 次，删除平均 49.5 次
```

正好是 n/2 和 (n-1)/2。

**注意这里有两个细节，考试就扣在这**：

1. 插入的位置数是 **n+1**，不是 n。因为"插在最后一个元素后面"也算一个位置。少了这个 +1，你算出来会是 `n(n-1)/2 ÷ n = (n-1)/2`，就错了。
2. 删除的位置数是 **n**，平均是 **(n-1)/2**，比插入少半个。很多同学两个都写 n/2，插入对、删除错。

**生活类比**：一条坐着 n 个人的长凳，你挤进去坐下，后面的人全要挪。挤在队尾，0 个人挪；挤在队首，n 个人挪；平均下来 n/2 个人挪。

## 七、手写三个经典小题

这三道题是"顺序表"这一章的手写代码常客，而且它们的思路（尤其是双指针）会一路用到后面的快排和链表里。

### 第 1 题：不用 insert，自己实现插入

题目：在列表 `a` 的下标 `i` 处插入 `x`，要求自己挪元素，不许用 `insert`。

```python
def my_insert(a, i, x):
    a.append(None)                      # 1. 末尾先加一个空位
    for k in range(len(a) - 1, i, -1):  # 2. 从后往前，把元素一个个右移
        a[k] = a[k - 1]
    a[i] = x                            # 3. 空出来的位置放 x
    return a


nums = [10, 20, 30, 40]
print(my_insert(nums, 2, 99))    # [10, 20, 99, 30, 40]
```

逐块解释：

1. `a.append(None)` 之后 `len(a)` 从 4 变成 5，最后一个位置是空的，可以安全地放东西。
2. `range(len(a) - 1, i, -1)` 生成 `4, 3`（因为 range 不含 i），也就是先把下标 4 填上原来的下标 3 的内容，再把下标 3 填上原来的下标 2 的内容。**为什么倒着来**：如果正着从 i 开始往右写，`a[i+1] = a[i]` 之后，原来的 `a[i+1]` 就被覆盖了，下一步就丢数据了。
3. 循环结束时，下标 i 那格的内容已经复制到 i+1 了，i 空出来，放 x。

复杂度：移动次数是 `n - i`，最坏 O(n)。

### 第 2 题：删除所有值为 x 的元素（O(n)，不许开新列表）

这是本章最有价值的题，因为它引出了"**双指针**"这个万能套路。

先看不合格的写法（很多人第一反应）：

```python
def remove_all_bad(a, x):
    for v in a:
        if v == x:
            a.remove(v)      # 边遍历边删
    return a

print(remove_all_bad([1, 2, 2, 2, 3], 2))   # [1, 2, 3] —— 漏删了！
```

为什么漏？`for v in a` 内部是靠一个隐藏的下标在往前走。删掉一个元素后，后面的元素整体左移，而那个隐藏下标照样 +1，于是**刚挪过来的那个元素被跳过了**。元素挨在一起时，这个 bug 特别明显。

还有另一种"看着对但很慢"的写法：每次 `remove` 都要先 O(n) 找、再 O(n) 挪，外面还套一层循环，最坏变成 O(n²)。

正确写法是双指针（也叫快慢指针）：

```python
def remove_all(a, x):
    write = 0                       # 写指针：下一个"保留"的元素该放哪
    for read in range(len(a)):      # 读指针：从头到尾检查每个元素
        if a[read] != x:
            a[write] = a[read]      # 不是 x，就抄到写指针处
            write += 1
        # 是 x 就什么都不做，读指针继续往前走
    del a[write:]                   # 把后面多出来的尾巴切掉
    return write                    # 返回保留下来的元素个数


nums = [1, 2, 2, 3, 2, 4]
print(remove_all(nums, 2), nums)    # 3 [1, 3, 4]
```

逐块解释：

- `write` 是"我要往哪儿写"，`read` 是"我正在看哪个"。两个指针都从 0 出发。
- 遇到不是 x 的，就抄到 `write` 的位置，然后 `write` 前进一格。**注意 `a[write] = a[read]` 在 `write == read` 时是自己抄自己，不花钱**，不用特殊处理。
- 遇到是 x 的，`read` 往前走，`write` 不动——相当于"这个位置先空着，等下一个合格的人来填"。
- 循环结束后，`[0, write)` 这一段就是答案，`write` 之后全是垃圾，用 `del a[write:]` 一次切掉。

复杂度：`read` 只走一遍，O(n)；`write` 最多也走一遍，O(n)；总共 **O(n)**。额外只用了两个整数变量，**空间 O(1)**。这就是题目要求的"时间 O(n)、空间 O(1)"。

**你可以这样记这个套路**：像整理书架，左手（read）一本本拿起来看，右手（write）只把要留的书放回架子上，放一本右手指向右移一格。不需要另开一个书架。

### 第 3 题：就地逆置（不许用 `a[::-1]`）

```python
def reverse_in_place(a):
    left, right = 0, len(a) - 1
    while left < right:
        a[left], a[right] = a[right], a[left]   # 交换两端
        left += 1
        right -= 1
    return a


print(reverse_in_place([1, 2, 3, 4, 5]))   # [5, 4, 3, 2, 1]
print(reverse_in_place([1, 2, 3, 4]))      # [4, 3, 2, 1]
```

- `left` 从最左、`right` 从最右往中间靠，每次交换两个，然后各走一步。
- 循环条件 `left < right`：奇数个元素时中间那个不用动；偶数个元素时两指针会正好错开，也不会重复交换。
- 复杂度：交换了 n/2 次，O(n)；额外只有两个变量，空间 O(1)。

**踩坑提醒**：写成 `while left <= right` 也能跑出正确结果，但奇数长度时会跟自己交换一次，多做了无用功；而如果写成 `while left < len(a)` 就死循环了。这类边界考试很爱考。

## 八、这一章最容易丢分的 6 个地方

**1. 看到两层循环就写 O(n²)**

```python
def f(a):
    total = 0
    for x in a:
        for k in range(10):    # 固定 10 次
            total += k
    return total
```

这是 O(10n) = **O(n)**。判断标准永远是"**内层的次数会不会随着 n 变大**"，不是"有几层 for"。

**2. 把系数留在答案里**

`O(2n)`、`O(n/2)`、`O(3n + 5)` 都不标准，标准写法只有 `O(n)`。同理 `O(n² + n)` 要写成 `O(n²)`。

**3. 以为 O(1) 就是"很快"**

O(1) 的真实含义是"**不随数据量增长**"。一个 O(1) 的操作可能也要 1 毫秒（比如访问一次磁盘），但当 n 从 10 涨到一千万时，它还是 1 毫秒，而 O(n) 的那段代码已经跑了十分钟。**大 O 描述的是趋势，不是绝对速度。**

**4. 边遍历边删元素**

```python
a = [1, 2, 2, 2, 3]
for v in a:
    if v == 2:
        a.remove(v)
print(a)    # [1, 2, 3]，还剩一个 2
```

这个坑在第 1 篇提过一次，现在你知道它还有第二个后果：**就算删对了，`remove` 本身是 O(n)，套在循环里就是 O(n²)**。正确做法是第 7 节的双指针。

**5. 用 `pop(0)` 当队列用**

```python
n = 10000
a = list(range(n))
moves = 0
for _ in range(n):
    a.pop(0)            # 每次 O(n)：剩下的元素全要往前挪一格
    moves += len(a)     # 粗略统计"一共挪了多少次"
print("总共挪动约", moves, "次")
```

输出是 `总共挪动约 49995000 次`——n 只有一万，就挪了五千万次，因为它是 n²/2 级的。第 3 篇会教你用两个下标或 `collections.deque` 解决。

**6. 二维列表的"乘法复制"陷阱**

```python
matrix = [[0] * 3] * 3      # 看起来是 3 行 3 列
print(matrix)               # [[0, 0, 0], [0, 0, 0], [0, 0, 0]]

matrix[0][0] = 1
print(matrix)               # [[1, 0, 0], [1, 0, 0], [1, 0, 0]] —— 三行全变了！
```

外面那个 `* 3` 复制的是**同一行的引用**，三行其实是同一条数据。正确写法是用推导式，让每一行都是新的：

```python
matrix = [[0] * 3 for _ in range(3)]
matrix[0][0] = 1
print(matrix)    # [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```

图那一篇建邻接矩阵时你会用到这个写法，先记住。

## 九、典型考题

### 考题 1（分析复杂度）

```python
def mystery(n):
    i = 1
    count = 0
    while i < n:
        for j in range(n):
            count += 1
        i *= 2
    return count
```

问：这段代码的时间复杂度是多少？当 n = 8 时，`count` 的值是多少？

**参考答案：**

时间复杂度 **O(n log n)**；n = 8 时 `count = 24`。

**解析：**

先看外层 `while i < n`，`i` 的取值是 1, 2, 4, 8...，每轮乘 2。当 n = 8 时，`i` 依次是 1、2、4（8 不满足 `< 8`），所以外层跑 **3 轮**。一般情况下外层是 log₂n 轮。

内层 `for j in range(n)` 每轮固定跑 n 次。

所以总次数是 `n × log₂n` → **O(n log n)**。

n = 8 时：外层 3 轮 × 内层 8 次 = 24。

**这道题的三个坑**：

1. 外层是 `while` 不是 `for`，很多人一看不是 `for i in range` 就不知道怎么数了——**数循环的本质是"数执行次数"，跟用哪个关键字没关系**。
2. `i *= 2` 决定了轮数是 log n，不是 n。如果写成 `i += 1`，那就是 O(n²)。
3. 看到"嵌套"就乘，这是对的；但**外层是 log n 轮**这件事必须自己数出来。

### 考题 2（手写代码 + 复杂度）

> 已知一个顺序表（Python 列表）`a` 和一个值 `x`，请**就地**删除所有等于 `x` 的元素，返回删除后元素的个数。要求时间复杂度 O(n)，额外空间 O(1)。不许用 `remove`，不许新建列表。

**参考答案：**

```python
def remove_all(a, x):
    write = 0
    for read in range(len(a)):
        if a[read] != x:
            a[write] = a[read]
            write += 1
    del a[write:]
    return write


nums = [1, 2, 2, 3, 2, 4]
k = remove_all(nums, 2)
print(k, nums)          # 3 [1, 3, 4]
print(nums[:k])         # [1, 3, 4]

all_x = [2, 2, 2]
print(remove_all(all_x, 2), all_x)    # 0 []

none_x = [1, 3, 5]
print(remove_all(none_x, 2), none_x)  # 3 [1, 3, 5]
```

**解析与评分点：**

1. **两个指针**：`read` 负责扫描全部 n 个元素，`write` 负责"把要留的往前搬"。这是拿满分的关键，用 `remove` 循环会判 O(n²)。
2. **`del a[write:]` 不能漏**，不然列表长度不变，后面全是重复的旧数据。如果题目要求"返回新长度"而不是"修改原表"，那么 `del` 可以省掉，但一定要返回 `write`。
3. **边界**：全是 x（返回 0，列表变空）、一个都不是 x（返回 n，列表不变）、空列表（返回 0）——这三组测试最好自己在纸上跑一遍，考试时在代码后面顺手写个 `print` 验证，能救不少分。
4. **复杂度**：循环 n 次，每次常数操作 → 时间 O(n)；只用了 `write`、`read` 两个整数 → 空间 O(1)。

**补充一句**：如果题目允许开新列表，写 `[v for v in a if v != x]` 也对，但那是空间 O(n)。**题目里的"就地"和"O(1) 空间"就是在逼你用双指针**，审题时把这两个词圈出来。

## 十、考试怎么考

**选择题**，这一章的高频点：

- 给一段代码问复杂度（单层 / 双层 / `i *= 2` / 内层固定次数）。
- `list` 各操作哪个是 O(1)、哪个是 O(n)。特别爱考 `append` 是 O(1)、`insert(0, x)` 是 O(n)。
- 顺序表和链表的优缺点对比（"随机访问快"是顺序表，"插入删除快"是链表）。
- 顺序表插入/删除的平均移动次数：n 个元素插入平均 **n/2**，删除平均 **(n-1)/2**。
- 大 O 之间的大小排序：O(1) < O(log n) < O(n) < O(n log n) < O(n²)。

**填空题**：

- "在长度为 n 的顺序表中插入一个元素，平均需要移动 \_\_\_\_ 个元素"（填 `n/2`）。
- "删除第 i 个元素需要移动 \_\_\_\_ 个元素"（填 `n-1-i`，如果下标从 0 开始）。
- "`a.insert(0, x)` 的时间复杂度是 \_\_\_\_"（填 `O(n)`）。
- 给一段代码填复杂度。

**读代码写输出**：这一章常配合"移动/覆盖"类代码出题，比如给你一段双指针删除的代码，问最后列表长什么样。**方法还是那句话：拿笔维护指针和列表内容，一轮一轮推。**

**手写代码**：最高频的三道就是本篇第 7 节的三道——自己实现插入、删除所有 x、就地逆置。另外"合并两个有序列表"也很常见，思路是双指针各指一个列表，谁小先放谁，这个套路和归并排序是同一个，第 8 篇会再讲。

**复杂度分析**：几乎必考一题 5 分左右。答题格式建议写成"**这段代码的基本操作是 XXX，执行了 f(n) 次，所以时间复杂度为 O(...)**"，把过程写出来，即使最后答案错一点，过程分也能拿。

## 十一、小结

这一篇的东西可以压缩成三句话：

1. **大 O 看趋势不看秒表**：只留最高阶、扔掉系数，加法取最大、嵌套相乘。
2. **顺序表 = 一排格子**：按下标访问 O(1)，插中间/删中间 O(n)，因为后面的人要挪。
3. **顺序表的核心操作就是"挪"**：插入平均挪 n/2 个，删除平均挪 (n-1)/2 个；想在 O(n) 时间里做原地修改，就用双指针。

如果你只记一件事，请记这个：

> **顺序表的所有性能问题，本质上都是"元素必须连续摆放"带来的搬运成本。**

理解了这句话，你就能自己推出那张复杂度表，而不是死记。第 4 篇讲链表时，你会看到另一种设计——"不连续摆放，靠箭头串起来"——它把插入删除降到了 O(1)，代价是失去了随机访问。两种结构的取舍，就是数据结构这门课最核心的思想。

## 下一篇讲什么

顺序表有个很有趣的性质：如果你**只在末尾加、只在末尾删**，所有操作都是 O(1)。这个"只在一头操作"的受限线性表，就是**栈**；如果"一头进、另一头出"，就是**队列**。

下一篇《栈与队列》会讲：栈的"后进先出"到底像什么（洗碗、撤销、函数调用），怎么用列表两行实现一个栈，然后用它解决两个期末必考题——**括号匹配**和**表达式求值**（中缀转后缀、后缀求值）。队列部分会重点讲清楚"为什么不能用 `pop(0)`"以及正确写法。那一篇是"用数据结构解决问题"的第一次实战，代码量会比这一篇大，但套路很固定。
