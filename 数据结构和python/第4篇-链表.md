# 第 4 篇：链表——从"节点"开始，把指针串成一条链

第 2 篇里我们算过一笔账：顺序表（Python 列表）在中间插入或删除一个元素，要把后面所有元素往后挪或往前挪，O(n)。第 3 篇的队列更惨，出队时用 `pop(0)` 直接变成 O(n²)。

当时我留了个问题：**能不能不挪？**

这篇就回答它。答案是：**可以不挪，代价是放弃"连续存储"**。你只需要让每个元素记住"下一个在哪"。这个思路催生的结构叫**链表**，它是后面树、图的直接地基——树就是"每个节点有多个 next"，图就是"每个节点有很多 next"。所以这篇不只是为了链表本身，是为后面铺路。

需要先会：第 1 篇的类（`class`、`self`、`__init__`）、`None`、`while` 循环。不需要别的。

---

## 一、为什么要链表：三个痛点

先回顾顺序表（数组 / Python 列表）的毛病：

**痛点 1：中间插入、删除要挪元素。** 在 100 万个元素的最前面插一个，要挪 100 万个。这是"存储必须连续"逼出来的——不挪，新元素就没地方放。

**痛点 2：扩容有代价。** Python 的列表在容量不够时会申请一块更大的内存，把老数据全部拷过去。虽然 `append` 摊还下来还是 O(1)，但那一下确实是 O(n)。

**痛点 3：要求一整块连续内存。** 你想存 100 万个元素，操作系统必须给你找到一块能装下 100 万个的连续空间。如果内存里到处是碎片，明明总量够、就是凑不出一整块，那就分配失败。

这三个问题，根子都在同一句话上：**元素必须挨在一起**。

那如果不挨着呢？

### 生活里的"链表"：藏宝图

想象一个寻宝游戏。你把 5 张纸条分别藏在不同地方：

- 第 1 张纸条放在门口，上面写："下一个线索在冰箱上。"
- 冰箱上的纸条写："下一个线索在书架上。"
- ……
- 最后一张纸条写："没了。"

现在你想按顺序看所有线索，怎么办？很简单：**从门口开始，看一张，按上面的地址找下一张，再下一张……直到看到"没了"。**

注意几个关键点：

- **纸条可以藏在任何地方**，不用挨着。冰箱、书架、花盆、鞋柜，随便。
- **每张纸条必须记住下一张在哪**，否则线索就断了。
- **只要知道"第一张在哪"（门口），就能找到全部**。这个"第一张"就是链表的 `head`。
- **最后一张写"没了"**，这就是 `None`，表示结束。

链表就是这么回事。每个元素叫一个**节点（node）**，节点里存两样东西：**自己的数据** + **下一个节点的位置**。位置在 Python 里用"引用"表示。

### 顺序表 vs 链表，一张图看懂

```text
顺序表（必须连续）：
内存地址 1000 1004 1008 1012 1016
        ┌────┬────┬────┬────┬────┐
        │ 10 │ 20 │ 30 │ 40 │ 50 │
        └────┴────┴────┴────┴────┘
        想插一个 15 到 20 前面？后面全部往右挪一格。

链表（不必连续）：
        ┌────┬────┐    ┌────┬────┐    ┌────┬────┐
        │ 10 │ ·──┼───→│ 20 │ ·──┼───→│ 30 │None│
        └────┴────┘    └────┴────┘    └────┴────┘
         值   next       值   next       值   next
         地址任意        地址任意        地址任意

        想插一个 15 到 10 和 20 之间？只要改两根"线"。
```

**这就是全部的秘密**：链表用"每节车厢拉下一节车厢"的方式，把分散的内存碎片串成了一条逻辑上的链。

## 二、从"节点"开始：`ListNode`

链表的节点就是一个小对象，里面两个属性：`val` 存数据，`next` 存"下一个节点"。Python 里一个类就够了：

```python
class ListNode:
    def __init__(self, val=0):
        self.val = val
        self.next = None       # 默认后面没人，就是链尾
```

**就这两行，是整篇的地基。** 考试里名字可能叫 `Node`、`LNode`、`ListNode`，属性可能叫 `data` 和 `next`，本质完全一样。

### 手工串一条链

有了节点，串链就是给 `next` 赋值：

```python
class ListNode:
    def __init__(self, val=0):
        self.val = val
        self.next = None


a = ListNode(1)
b = ListNode(2)
c = ListNode(3)

a.next = b          # a 后面接 b
b.next = c          # b 后面接 c

head = a            # head 永远指向第一个节点
cur = head
while cur is not None:
    print(cur.val, end=" ")
    cur = cur.next
print()
print("遍历完了，cur 现在是：", cur)
```

输出：

```text
1 2 3 
遍历完了，cur 现在是： None
```

**这段代码请务必吃透**，因为它是后面所有操作的原型：

- `a.next = b`：让 `a` 的 `next` 指向 `b`。**这不是"复制 b"，是"记住 b 在哪"**。
- `while cur is not None`：一直走到"没有了"为止。这是链表遍历的标准写法。
- `cur = cur.next`：往前走一步。**这一句是链表的"`i += 1`"**。
- 循环结束时 `cur` 变成 `None`，说明已经走出链尾了。

注意 `c.next` 从头到尾没赋值，所以它是 `None`（`__init__` 里给的默认值）。**链表的末尾必须是 `None`**，否则用 `while cur is not None` 遍历会死循环——这条后面还会单独说。

### 造链和打印的辅助函数

考试的时候一节一节 `ListNode(1)`、`ListNode(2)` 地写，手会断。实际写题时我们造两个小工具：

```python
class ListNode:
    def __init__(self, val=0):
        self.val = val
        self.next = None


def build(vals):
    """用列表造一条链，返回头节点。vals 为空时返回 None"""
    dummy = ListNode(0)      # 临时"哑节点"，省去"链表为空"的特判
    tail = dummy
    for v in vals:
        tail.next = ListNode(v)
        tail = tail.next
    return dummy.next        # 真正的头是哑节点的下一个


def to_list(head):
    """把链表转回列表，方便打印和验证"""
    out = []
    cur = head
    while cur is not None:
        out.append(cur.val)
        cur = cur.next
    return out


print(to_list(build([1, 2, 3])))
print(to_list(build([])))
```

输出：

```text
[1, 2, 3]
[]
```

**`dummy`（哑节点 / 哨兵）这个技巧考试非常爱用**，后面还会出现好几次。它的好处是：有了它，"链表为空"和"链表不为空"就不用分开处理了，头节点也变成了"某个节点的下一个"，删改头节点时不用特判。

`build([2,5,7])` 造出来是这样的：

```text
dummy → [0|·] → [2|·] → [5|·] → [7|None]
                ↑
          返回的是这个（dummy.next）
```

### 关键理解：`next` 是"引用"，不是"副本"

这一点是 Python 写链表最容易迷糊的地方。

```python
class ListNode:
    def __init__(self, val=0):
        self.val = val
        self.next = None


x = ListNode(1)
y = x              # 这不是复制！y 和 x 指向同一个节点
y.val = 100
print(x.val)       # 100
print(x is y)      # True
```

输出：

```text
100
True
```

`y = x` 只是给同一个节点多贴了一个标签。所以：

- 想让 `a` 后面接上 `b`，写 `a.next = b`。**改的是 `a` 这个节点的内部属性。**
- 想"复制"一条链，`new = old` 是不行的，那只是两个名字指同一条链。真要复制，得一个个 `ListNode` 新建。

**这个"标签"的心智模型一旦建立，链表就再也不会绕晕了。** 你可以把变量想成遥控器，节点是电视：`cur = cur.next` 是把遥控器对准下一台电视，不是把电视搬过来。

## 三、五个基本操作

先把工具箱准备好，**后面所有代码都接着这一段往下写**（省得每个例子都重抄一遍）：

```python
class ListNode:
    def __init__(self, val=0):
        self.val = val
        self.next = None


def build(vals):
    dummy = ListNode(0)
    tail = dummy
    for v in vals:
        tail.next = ListNode(v)
        tail = tail.next
    return dummy.next


def to_list(head):
    out = []
    cur = head
    while cur is not None:
        out.append(cur.val)
        cur = cur.next
    return out
```

### 操作 1、2、3：求长度、按值查找、取第 k 个

这三个都是"走一遍"，套路完全一样：

```python
def length(head):
    n = 0
    cur = head
    while cur is not None:
        n += 1
        cur = cur.next
    return n


def find(head, target):
    """返回第一个值为 target 的节点，找不到返回 None"""
    cur = head
    while cur is not None:
        if cur.val == target:
            return cur
        cur = cur.next
    return None


def get(head, k):
    """取第 k 个节点（从 1 开始数），越界返回 None"""
    cur = head
    for _ in range(k - 1):
        if cur is None:
            return None
        cur = cur.next
    return cur


h = build([10, 20, 30, 40])
print("长度", length(h))
print("找 30：", find(h, 30).val)
print("找 99：", find(h, 99))
print("第 2 个：", get(h, 2).val)
print("第 9 个：", get(h, 9))
```

输出：

```text
长度 4
找 30： 30
找 99： None
第 2 个： 20
第 9 个： None
```

三点说明：

- **`length` 必须走完整个链**，所以是 O(n)。链表不像列表有现成的 `len()`，长度得自己数（或者额外维护一个 `size` 变量）。
- **`find` 找到就 `return cur`，返回的是节点本身**，不是下标。因为在链表里"节点"比"下标"有用——拿到节点就能接着改它后面的结构。
- **`get(h, k)` 就是"链表的 `a[k]`"**，但它只能从头一个个跳，所以是 O(k)。这就是链表最大的代价：**没有随机访问**。

### 操作 4：头插、尾插、在某节点后插入

```python
def push_front(head, val):
    """头插：新节点变成新的头，返回它"""
    node = ListNode(val)
    node.next = head
    return node


def push_back(head, val):
    """尾插：走到最后一个，接上去，返回头（头没变）"""
    node = ListNode(val)
    if head is None:          # 空链表：新节点就是头
        return node
    cur = head
    while cur.next is not None:   # 注意是 cur.next，不是 cur
        cur = cur.next
    cur.next = node
    return head


def insert_after(p, val):
    """在节点 p 后面插入，返回新节点"""
    node = ListNode(val)
    node.next = p.next        # 第一步：新节点先接住 p 后面的链
    p.next = node             # 第二步：再让 p 指向新节点
    return node


h = build([2, 3])
h = push_front(h, 1)
print("头插后：", to_list(h))

h = push_back(h, 4)
print("尾插后：", to_list(h))

p = find(h, 2)
insert_after(p, 99)
print("在 2 后面插 99：", to_list(h))
```

输出：

```text
头插后： [1, 2, 3]
尾插后： [1, 2, 3, 4]
在 2 后面插 99： [1, 2, 99, 3, 4]
```

这几行里藏着三个必须记住的细节：

**细节 1：`insert_after` 的两步顺序不能反。**

```text
正确：                         错误：
p → [2|·] → [3|None]           p → [2|·] → [3|None]
node → [99|·]                  node → [99|·]

node.next = p.next   先接后    p.next = node     ← 先把 p 指向 node
p.next = node        再断前                     ← 这时 [3] 已经没人指向它了
                                                （除非你提前存过，否则链断了）
```

**先接新的，再断旧的**。这是链表插入的唯一口诀。

**细节 2：`push_front` 返回新头，`push_back` 返回原头。**

因为头插之后头变了，你不返回新头，外面的人就找不到这条链了。**每次操作完都问一句"头变了吗？"** —— 变了就返回新头，没变返回原来的。

**细节 3：`push_back` 里的 `while cur.next is not None`。**

一定要判断 `cur.next`，不是 `cur`。因为我们要停在**最后一个节点**上（它的 `next` 是 `None`），好把新节点接在它后面。如果写成 `while cur is not None`，循环结束时 `cur` 已经是 `None`，你没法 `cur.next = node`。

**这个"`cur` 还是 `cur.next`"的选择，是链表代码里最高频的错误来源，没有之一。** 判断标准很简单：**你想站在哪个节点上动手，循环就得停在哪。**

### 操作 5：删除——单向链表最麻烦的一步

删除节点 `X`，本质是**让 X 的前一个节点直接指向 X 的后一个节点**，把 X 跳过去：

```text
删除前：  prev → [2|·] → [3|·] → [4|None]
                         ↑ X
删除后：  prev → [2|·] ────────→ [4|None]

           prev.next = prev.next.next
```

问题来了：**要改 `prev.next`，就必须先找到 `prev`**。而单向链表只能往前走，所以你遍历时必须**同时记住前一个节点**：

```python
def remove(head, target):
    """删除第一个值为 target 的节点，返回新的头"""
    dummy = ListNode(0)
    dummy.next = head
    prev = dummy
    while prev.next is not None:
        if prev.next.val == target:
            prev.next = prev.next.next    # 跳过它
            break
        prev = prev.next
    return dummy.next


h = build([1, 2, 3, 2])
print("删 2 后：", to_list(remove(h, 2)))

h = build([1, 2, 3])
print("删头节点 1：", to_list(remove(h, 1)))

h = build([1])
print("删唯一的节点：", to_list(remove(h, 1)))

h = build([1, 2])
print("要删的 9 不存在：", to_list(remove(h, 9)))
```

输出：

```text
删 2 后： [1, 3, 2]
删头节点 1： [2, 3]
删唯一的节点： []
要删的 9 不存在： [1, 2]
```

这段代码的精妙之处全在 `dummy` 上，值得逐句拆：

- **`prev` 从 `dummy` 出发，判断的永远是 `prev.next`。** 这样做的好处是：**要删的节点总是在 `prev` 的后面**，包括头节点——头节点的前面是 `dummy`。这样"删头节点"就和"删中间节点"变成了同一件事，不用写 `if head.val == target: head = head.next` 这种特判。
- **`while prev.next is not None`**：只要后面还有节点就继续。注意是 `prev.next`，我们要停在"待删节点的前一个"上。
- **`prev.next = prev.next.next`**：一句话跳过目标节点。左边的 `prev.next` 被重新赋值，中间那个节点就没人指向了。
- **`break`**：只删第一个。如果要删所有值为 `target` 的节点，把 `break` 去掉就行（那时候 `prev` 不能往前走，得重新检查新的 `prev.next`）。

**为什么单向链表删除必须知道前驱？** 因为"绕过 X"这个动作，只有 `X` 的前一个节点能做到。`X` 自己知道后面是谁，但不知道前面是谁——**单向链表是"单行道"，回不了头**。这也是后面要讲**双向链表**的动机。

### 顺序表 vs 链表：复杂度总表

| 操作 | 顺序表（列表） | 链表 |
| --- | --- | --- |
| 按下标取 `a[i]` | **O(1)** | O(n)（必须从头数） |
| 按值查找 | O(n) | O(n) |
| 头部插入 | O(n)（后面全挪） | **O(1)**（改两个指针） |
| 尾部插入 | O(1) 摊还 | O(n)（要先走到尾巴）；有尾指针则 O(1) |
| 中间插入（已定位到位置） | O(n)（挪元素） | **O(1)**（改指针） |
| 删除（已定位到前驱） | O(n)（挪元素） | **O(1)**（改指针） |
| 内存布局 | 一整块连续内存 | 分散，每个节点多存一个 `next` |
| 额外开销 | 扩容时要整体拷贝 | 每个节点一个引用（约 8 字节） |

**这张表要能默写。** 考试最爱问的一道判断题是：

> "链表的插入和删除是 O(1)，所以链表比顺序表快。" —— **错。**

因为它漏了"**定位**"这一步。链表确实是"改指针只要 O(1)"，但**找到要改的地方**是 O(n)。所以：

- 在**已知节点**后面插入 → O(1)，链表赢。
- "在链表第 500 个位置插入" → 找位置 O(n) + 改指针 O(1) = **O(n)**，和顺序表打平（但链表不用挪元素，实际常数小一些）。
- "取第 500 个元素" → 链表 O(n)，顺序表 O(1)，**顺序表完胜**。

一句话总结两者的取舍：

> **顺序表用"连续"换来了随机访问；链表用"随机访问"换来了灵活的插入删除。**

## 四、必考题：反转链表

这是链表最经典的题，没有之一。**面试考、期末考、考研 408 都考**，而且它是"指针操作"的试金石——能把反转写对，说明你真的懂了 `next`。

题目：把 `1 → 2 → 3 → 4 → None` 变成 `4 → 3 → 2 → 1 → None`。

### 迭代版：三个指针，四行核心

思路：从头走到尾，**每到一个节点就把它掉头，指向它的前一个**。为了掉头，你得同时知道"前一个是谁"和"下一个是谁"，所以要三个变量：`prev`、`cur`、`nxt`。

```python
def reverse(head):
    prev = None              # 反转后，原来的头会变成尾巴，所以 prev 从 None 开始
    cur = head
    while cur is not None:
        nxt = cur.next       # ① 先记住下一个，否则等会儿就找不到了
        cur.next = prev      # ② 掉头：指向前面
        prev = cur           # ③ prev 往前走一步
        cur = nxt            # ④ cur 往前走一步
    return prev              # 循环结束时 cur 是 None，prev 才是新头


h = build([1, 2, 3, 4])
print("反转前：", to_list(h))
print("反转后：", to_list(reverse(h)))
```

输出：

```text
反转前： [1, 2, 3, 4]
反转后： [4, 3, 2, 1]
```

### 拿 `1 → 2 → 3` 一步步走

| 阶段 | `cur` | `nxt = cur.next` | 执行 `cur.next = prev` 后 | `prev` | `cur` |
| --- | --- | --- | --- | --- | --- |
| 初始 | 1 | — | — | `None` | 1 |
| 第 1 轮 | 1 | 2 | `1 → None` | 1 | 2 |
| 第 2 轮 | 2 | 3 | `2 → 1` | 2 | 3 |
| 第 3 轮 | 3 | `None` | `3 → 2` | 3 | `None` |
| 结束 | — | — | — | **3（新头）** | `None` |

每一轮结束时的链：

```text
初始：      1 → 2 → 3 → None      prev=None

第 1 轮后：  1 → None              prev=1
            2 → 3 → None           cur=2

第 2 轮后：  1 → None  2 → 1       prev=2
            3 → None               cur=3

第 3 轮后：  3 → 2 → 1 → None      prev=3, cur=None
```

**四个赋值为什么缺一不可：**

1. `nxt = cur.next`：**必须最先做**。因为第 ② 步一执行，`cur.next` 就被改掉了，原来的"下一个"信息就永久丢失。这是反转链表唯一的难点，也是 90% 的人第一次写会错的地方。
2. `cur.next = prev`：掉头。
3. `prev = cur`：前指针前进。
4. `cur = nxt`：当前指针前进。**注意用的是 ① 存下的 `nxt`，不是 `cur.next`**——此刻的 `cur.next` 已经指向 `prev` 了，用它就会原地踏步甚至死循环。

**为什么最后返回 `prev` 而不是 `cur`？** 因为循环结束时 `cur` 是 `None`（它已经走出链尾了），而 `prev` 停在最后一个被处理的节点上，也就是**反转后的新头**。

### 递归版：把"整条链"交给下一层

递归版的思路非常优雅，代码只有四行：

```python
def reverse_rec(head):
    if head is None or head.next is None:
        return head                        # 空链，或只剩一个节点：它就是头

    new_head = reverse_rec(head.next)      # 先让后面那截自己反转好
    head.next.next = head                  # 让后一个节点指回自己
    head.next = None                       # 自己变成新的尾巴
    return new_head                        # 一路把新头传回去


h = build([1, 2, 3, 4])
print("递归反转：", to_list(reverse_rec(h)))
```

输出：

```text
递归反转： [4, 3, 2, 1]
```

以 `1 → 2 → 3` 说明：

```text
reverse_rec(1)
  └─ reverse_rec(2)
       └─ reverse_rec(3) → 3.next 是 None，直接返回 3

       回到 head=2：new_head=3
         2.next.next = 2   → 3.next = 2
         2.next = None     → 2 成为尾巴
         现在的链：3 → 2 → None，返回 3

回到 head=1：new_head=3
         1.next.next = 1   → 2.next = 1
         1.next = None     → 1 成为尾巴
         现在的链：3 → 2 → 1 → None，返回 3
```

**关键那一步是 `head.next.next = head`**：`head.next` 是"我后面那个节点"，`head.next.next` 是"后面那个节点的 next"，把它改成我，就完成了掉头。刚看会有点晕，**在纸上画三个方块，一步步跟着改线，两分钟就通了**。

递归的细节第 5 篇专门讲，这里你只要理解"**先让后面一整截反转好，再处理我这一根线**"就够了。

**复杂度**：两种写法都是时间 O(n)，每个节点只碰一次。空间上迭代是 O(1)，递归是 O(n)——每层递归都要占一个栈帧（第 3 篇说过，函数调用就是栈）。

## 五、快慢指针：链表题的第二把钥匙

链表没有下标，所以很多"位置"类问题不能靠索引，只能靠**两个指针以不同速度走**。这套技巧叫快慢指针，是链表第二大考点。

### 用法一：找中点

让 `slow` 每次走一步，`fast` 每次走两步。`fast` 走到头时，`slow` 正好在中间。

```python
def middle(head):
    slow = head
    fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
    return slow


for vals in [[1, 2, 3, 4, 5], [1, 2, 3, 4], [7]]:
    print(vals, "→ 中点是", middle(build(vals)).val)
```

输出：

```text
[1, 2, 3, 4, 5] → 中点是 3
[1, 2, 3, 4] → 中点是 3
[7] → 中点是 7
```

**注意循环条件 `fast is not None and fast.next is not None`**，两个都要写：

- `fast is not None`：防止 `fast.next` 报 `AttributeError`（走到链尾之后 `fast` 是 `None`）。
- `fast.next is not None`：因为循环体里要执行 `fast.next.next`，如果 `fast.next` 是 `None`，`None.next` 会炸。

**顺带一个细节**：偶数个节点时（`[1,2,3,4]`），这段代码返回的是**后一个中点**（3）。如果题目要前一个中点（2），循环条件改成 `while fast.next is not None and fast.next.next is not None`。**考试如果没说清，就按自己写的代码说明"返回后一个中点"**，别不吭声。

### 用法二：判断有没有环

如果链表里有个环（某个节点的 `next` 指回了前面的节点），正常的 `while cur is not None` 遍历会**永远走不完**——你就死循环了。怎么办？

还是快慢指针：**如果有环，快指针一定会在环里追上慢指针**；如果没环，快指针会先撞到 `None`。

```python
def has_cycle(head):
    slow = head
    fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:        # 追上了，说明有环
            return True
    return False                # fast 走到头了，说明没环


# 造一条有环的链：1 → 2 → 3 → 4
#                    ↑___________|
h = build([1, 2, 3, 4])
tail = h
while tail.next is not None:
    tail = tail.next
tail.next = h.next          # 让尾巴指回 2，形成环

print("有环吗？", has_cycle(h))
print("普通链：", has_cycle(build([1, 2, 3])))
print("空链：", has_cycle(None))

s = ListNode(1)
s.next = s                  # 自己指自己，也是环
print("单节点自环：", has_cycle(s))
```

输出：

```text
有环吗？ True
普通链： False
空链： False
单节点自环： True
```

**为什么一定会相遇？** 进了环之后，`fast` 每轮比 `slow` 多走一步。你可以把环想成操场跑道：一个跑得快、一个跑得慢，快的那个迟早会从后面"套圈"追上慢的。相对速度是 1 步/轮，所以最多再走"环长"轮就会相遇——不会错过去，因为每轮只差一步，不存在"跳过"的可能。

**这个"每轮只差一步，所以不会跳过"是判环题的标准解释**，简答题可以直接写。

### 快慢指针还能干什么

同一套模板还能解：找环的入口、判断回文链表（先找中点再反转后半段）、找倒数第 k 个（让 `fast` 先走 k 步，然后两个一起走）——最后这个就是本篇的考题 1。

## 六、三种链表和"头结点"，考试要认脸

### 单链表、双链表、循环链表

| 类型 | 每个节点存什么 | 特点 | 删除时的麻烦 |
| --- | --- | --- | --- |
| 单链表 | `val` + `next` | 只能往前走 | 必须找前驱 |
| 双链表 | `val` + `prev` + `next` | 能往前也能往后 | 不用找前驱，但要改 4 根线 |
| 循环链表 | `val` + `next`（尾巴指回头） | 没有"尽头"，绕圈 | 遍历要判断"回到起点" |

**双链表**就是把"单行道"修成了"双向道"，每个节点多一个 `prev` 指向前一个：

```python
class DListNode:
    def __init__(self, val=0):
        self.val = val
        self.prev = None
        self.next = None


def insert_after_d(p, val):
    """在双链表节点 p 之后插入新节点（考试爱考这四步的顺序）"""
    node = DListNode(val)
    node.next = p.next           # ① 新节点接住后面的链
    node.prev = p                # ② 新节点的前驱是 p
    if p.next is not None:       # ③ 原来 p 后面的节点要认这个新前驱
        p.next.prev = node
    p.next = node                # ④ 最后才让 p 指向新节点
    return node


a = DListNode(1)
b = DListNode(3)
a.next = b
b.prev = a
insert_after_d(a, 2)

cur, forward = a, []
while cur is not None:
    forward.append(cur.val)
    cur = cur.next

cur, backward = b, []
while cur is not None:
    backward.append(cur.val)
    cur = cur.prev

print("正向：", forward)
print("反向：", backward)
```

输出：

```text
正向： [1, 2, 3]
反向： [3, 2, 1]
```

**双链表插入要改 4 根线（新节点的两个 + 前后节点的各一个），顺序里最关键是"③ 必须在 ④ 之前"**：如果先执行 `p.next = node`，你就再也找不到"原来 p 后面那个节点"了，`p.next.prev = node` 就会改错对象（改成新节点自己）。**这是双链表题唯一的坑**。

### 头结点（dummy / 哨兵）到底有啥用

考试里有个概念叫**头结点**：在第一个真实数据节点前面，额外加一个不存数据（或只存表长）的节点。它的好处有三条，可以直接背：

1. **让空表和非空表的操作统一**：不管链表空不空，头结点的 `next` 都存在，不用特判 `head is None`。
2. **让"在第一个位置插入/删除"和其他位置统一**：因为我们永远在"某个节点的后面"操作，第一个位置也有"前一个节点"（就是头结点）。
3. **方便共享**：多个链表可以共用一个头结点（实际工程里的用法）。

**注意区分"头结点"和"头指针"**：头指针是"指向第一个节点的指针"（在 Python 里就是 `head` 变量），头结点是"一个真实存在的节点"。考试常问"头指针和头结点的区别"，标准答案是：**头指针必须存在（不然找不到链），头结点可有可无**。

代码里我们一直用的 `dummy = ListNode(0)` 就是临时造一个头结点，用完就丢，不让它出现在结果里（`return dummy.next`）。

## 七、链表代码的 7 个常见错误

**1. 把 `head` 自己走掉了，链就丢了**

```python
head = build([1, 2, 3])
cur = head
while cur is not None:
    cur = cur.next
print(to_list(head))      # [1, 2, 3]，head 没动，链还在

head2 = build([1, 2, 3])
while head2 is not None:
    head2 = head2.next
print(head2)              # None，而且原来的三个节点再也没人指向了
```

输出：

```text
[1, 2, 3]
None
```

**永远用 `cur` 去走，把 `head` 留着当"门牌号"。** 只有一种情况该动 `head`：你确实想让头变（比如头插、或者反转之后换了新头）。

**2. 遍历时把 `cur.next` 改掉了，还继续用它前进**

（下面只是伪代码，示意错误的顺序，别直接跑）

```python
# 错的写法
while cur is not None:
    cur.next = prev      # 先把 next 改了
    cur = cur.next       # 再用它前进 → 此刻它指向 prev，直接原地打转
```

**要改 `next` 的地方，一定先把原 `next` 存到临时变量里**（反转链表就是这么做的）。

**3. `while cur` 和 `while cur.next` 混用**

- 要**读取所有节点**（求长度、找值、打印）→ 用 `while cur is not None`。
- 要**停在最后一个节点上动手**（尾插、删除尾节点）→ 用 `while cur.next is not None`。

用错了要么少处理一个节点，要么 `None.next` 报错。**写之前先问：我要站在哪儿改线？**

**4. 忘了返回新的头**

头插、删除头节点、反转之后，头变了。**函数必须返回新的头**，调用方要接住（下面假设 `push_front` 已定义）：

```python
h = push_front(h, 0)      # 对：接住返回值
push_front(h, 0)          # 错：新头丢了，还是原来的链
```

**5. 以为 `new = old` 是复制**

那只是贴了个新标签。想复制链表必须逐个 `ListNode(v)` 新建。这个坑在"复制带随机指针的链表"这类题里会要命。

**6. 删除后忘了处理尾巴 / 拼接后残留旧尾巴**

把两条链拼起来（比如考题 2 合并有序链表）时，最后一定要把尾巴接好，或者显式 `tail.next = None`，否则可能把旧链剩下的部分也带进来。

**7. 删除节点时没保存前驱**

`cur` 走到目标节点时，你已经不知道它前面是谁了。要么用 `prev` 跟着走，要么用 `dummy + prev.next` 的写法。

## 八、两道考题

### 考题 1：删除链表的倒数第 n 个节点

> 给定链表头和整数 n，删除倒数第 n 个节点，返回头节点。例如 `1→2→3→4→5`，n = 2，结果是 `1→2→3→5`。

**思路**：核心难点是"倒数第 n 个"没法直接定位。用快慢指针一次遍历搞定：**`fast` 先走 n 步，然后两个一起走；`fast` 走到最后一个节点时，`slow` 正好停在待删节点的前一个**。

```python
def remove_nth_from_end(head, n):
    dummy = ListNode(0)
    dummy.next = head
    fast = dummy
    slow = dummy

    for _ in range(n):          # fast 先走 n 步
        fast = fast.next

    while fast.next is not None:    # 一起走，直到 fast 到最后一个
        fast = fast.next
        slow = slow.next

    slow.next = slow.next.next  # 跳过待删节点
    return dummy.next


for n in [2, 1, 5]:
    print(f"删倒数第 {n} 个：", to_list(remove_nth_from_end(build([1, 2, 3, 4, 5]), n)))

print("单节点删倒数第 1 个：", to_list(remove_nth_from_end(build([7]), 1)))
```

输出：

```text
删倒数第 2 个： [1, 2, 3, 5]
删倒数第 1 个： [1, 2, 3, 4]
删倒数第 5 个： [2, 3, 4, 5]
单节点删倒数第 1 个： []
```

**为什么 `fast` 和 `slow` 都从 `dummy` 出发，而不是从 `head`？**

因为要删的可能是**头节点**。如果从 `head` 出发，`slow` 只能停在待删节点上，改不了它前面那根线。从 `dummy` 出发，`slow` 永远停在"待删节点的前一个"，头节点也有前驱（`dummy`），于是**所有情况统一处理，不需要特判**。最后返回 `dummy.next`。

**手推一下 `1→2→3→4→5`、n=2：**

| 阶段 | fast | slow |
| --- | --- | --- |
| 初始 | dummy | dummy |
| fast 先走 2 步 | 2 | dummy |
| 一起走 1 轮 | 3 | 1 |
| 一起走 2 轮 | 4 | 2 |
| 一起走 3 轮 | 5（最后一个，`fast.next` 是 None，停） | 3 |

`slow` 停在 3，删它的下一个（4），得到 `1→2→3→5`。**对。**

**复杂度**：时间 O(n)（一趟遍历），空间 O(1)。

### 考题 2：合并两个有序链表

> 两个升序链表，合并成一个升序链表。例：`1→3→5` 和 `2→4→6` 合并成 `1→2→3→4→5→6`。

**思路**：像扑克牌里"把两摞排好的牌合成一摞"——每次比较两摞最上面那张，取小的。用一个 `tail` 记录新链的尾巴，不断往后接。

```python
def merge(a, b):
    dummy = ListNode(0)
    tail = dummy

    while a is not None and b is not None:
        if a.val <= b.val:      # 取小的（相等时取 a，保证稳定）
            tail.next = a
            a = a.next
        else:
            tail.next = b
            b = b.next
        tail = tail.next        # tail 跟着往前走

    tail.next = a if a is not None else b   # 谁还有剩就整段接上
    return dummy.next


print(to_list(merge(build([1, 3, 5]), build([2, 4, 6]))))
print(to_list(merge(build([]), build([1, 2]))))
print(to_list(merge(build([1, 2]), build([]))))
```

输出：

```text
[1, 2, 3, 4, 5, 6]
[1, 2]
[1, 2]
```

三个要点：

1. **`tail.next = a` 之后要 `tail = tail.next`**。忘了这一句，新链永远只挂在 `dummy` 后面，后面的元素全被覆盖——这是本题最高频的错误。
2. **循环结束后剩下的那一段直接整段接上**，不用再一个个搬。因为两段本身都是有序的，剩下的那截必然全都更大（或更小）。
3. **`a.val <= b.val` 里的 `=` 是为了"稳定"**：相等时优先取前一条链的元素，合并后相同元素的相对顺序不变。考试不一定考，但写上显得专业。

**复杂度**：时间 O(m+n)（两条链各走一遍），空间 O(1)（只改指针，没建新节点）。

## 九、考试怎么考

**选择题 / 判断题**（这几句几乎年年出现，请把对错和理由都记住）：

| 说法 | 对错 | 理由 |
| --- | --- | --- |
| 链表可以随机访问第 k 个元素 | **错** | 必须从头走 k 步，O(k) |
| 链表插入删除一定是 O(1) | **错** | 改指针是 O(1)，但**定位**是 O(n) |
| 顺序表插入删除一定是 O(n) | **基本对** | 尾部插入是 O(1)，中间/头部才是 O(n) |
| 单链表删除节点不需要知道前驱 | **错** | 必须知道，否则改不了前一个的 `next` |
| 双链表删除节点需要知道前驱 | **错** | 有 `prev`，自己就能找到前驱，O(1) |
| 链表比顺序表省内存 | **错** | 每个节点多存指针（还可能有内存碎片） |
| 带头结点的单链表，判空条件是 `head == None` | **错** | 是 `head.next == None`（头结点本身一直存在） |
| 单链表找前驱的时间复杂度是 O(1) | **错** | O(n)；双链表才是 O(1) |

**填空题**：

- 链表节点通常包含 \_\_\_\_ 和 \_\_\_\_ 两部分（数据域 / 指针域）。
- 单链表中，尾节点的 `next` 为 \_\_\_\_（`None` / `NULL`）。
- 在单链表中，若 `p` 指向某节点，则 `p.next` 表示 \_\_\_\_（p 的后继节点）。
- 循环链表判空（带头结点）：\_\_\_\_（`head.next == head`）。
- 在双链表中，在 `p` 之后插入 `s`，需要修改 \_\_\_\_ 根指针（4 根）。

**读代码写输出**：给你一段建链、遍历、插入、删除的代码，问最后链是什么样。**做法：在纸上画格子，一格一格改线，别在脑子里模拟。**

**手写代码**：高频四件套——遍历、插入、删除、反转。**反转链表**出现率最高，几乎必考；其次是"合并两个有序链表"和"删除倒数第 n 个"。

**简答题**：

- "顺序表和链表的区别与适用场景"——从**存储方式、访问方式、插入删除、空间开销**四个角度答。
- "头结点的作用"——本篇第六节的三条。
- "为什么单链表删除需要找前驱"——因为只能单向走，只有前一个节点能绕过它。

**一个答题技巧**：只要能画图，就先画图。链表题的所有错误（顺序反了、丢指针、少返回头）在图上都能一眼看出来，在脑子里却很难发现。

## 十、小结

这一篇的三句话：

1. **链表 = 节点 + 指针**。节点存"值 + 下一个在哪"，用一根根 `next` 把分散的内存串成一条逻辑上的链。头指针是唯一的入口，`None` 是终点。
2. **链表用"随机访问"换"灵活增删"**。改指针 O(1)，但定位 O(n)。所以"链表增删快"这句话必须补上前提：**你已经站在那个位置上了**。
3. **写链表的三个口诀**：先接新的再断旧的；要改 `next` 就先把原 `next` 存起来；操作完检查"头变了吗"。

如果只记一个画面：

> **链表是一列火车**，每节车厢（节点）里坐着乘客（值），还挂着一根钩子，钩住下一节车厢。想插一节车厢？把钩子换个位置就行。**想找第 5 节车厢？只能从车头一节节数过去。**

还有一点方法论：你会发现这一篇里，**"用 `dummy` 省特判"** 和 **"用两个指针代替下标"** 这两个技巧反复出现。它们不是链表专属的，而是"用额外的一点空间，换掉一堆 `if` 分支"的通用思路。后面学树、图、动态规划，你会一次次见到它们。

## 下一篇讲什么

链表已经把"一个节点指向另一个节点"玩明白了。但链表有个先天限制：**一个节点最多只能有一个 `next`**。

如果允许**一个节点有两个 `next`** 呢？那它就变成了分叉——一个父节点挂两个孩子。这就是**树**。

下一篇《树与二叉树》会讲：树的基本术语（根、叶子、深度、高度）、二叉树的五种形态、三种遍历（前序、中序、后序）——你会发现**它们全是递归**，两三行就写完；然后是二叉搜索树（为什么查得快）、堆（第 8 篇排序的前置）、以及层序遍历怎么用第 3 篇的队列。这一篇会是整个系列里"递归"正式登场的地方，也是期末卷子上分值最高的一章。
